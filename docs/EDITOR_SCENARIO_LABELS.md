# 시나리오 선택 번호·제목·공유 자료

2026-10-11 `20261011-public3`은 인증된 시나리오 본문·제목 선택 표·분기 진행표를 연결해 **화수 · 작전명**으로 정렬한다. F 정규 전장 50본문과 완결편 83본문에 숫자 연결표를 적용한다. 제목은 사용자의 TSR에서 읽으며, 제목을 읽지 못한 경우에도 확인된 순서를 유지하고 `제목 확인 불가`로 표시한다. 연결되지 않은 자료는 화수를 추정하지 않고 목록 뒤에 둔다.

## 현재 화수·제목·정렬 계약

- F는 실제 분기별 화수를 표시한다. 우회 여부로 한 화 차이가 생기는 구간은 `제33·34화`처럼 두 번호를 함께 표시한다. 같은 화의 리얼계·슈퍼계 및 분기 전장은 진행표의 순서로 묶는다.
- 완결편은 **완결편 시작을 1화로 센 순서**를 `완결편 5화`처럼 표시한다. F에서 이어온 경로에 따라 달라지는 게임의 통산 화수와 구분하며, 선택기의 설명·툴팁·접근성 이름에 이 기준을 명시한다.
- 같은 작전의 연속 전장은 `(1/3)`처럼 구분한다. 비전술 도입 선택185와 엔딩184·188은 정규 전장 연결표에서 제외한다. 기존 편집 가능한 미연결 자료는 유지한다.
- 정품 원본의 제목은 `editor-scenario-stock-name-map.mjs`의 제한된 일본어 문자표로 읽는다. 승인본의 한글 문자표를 원본에 적용하지 않는다. 문자표는 연결된 제목에서 실제 쓰인 문자 코드만 포함하며, 완결편의 원본 글리프 `F588`은 제목 그림으로 확인한 `絆`로 판독한다.
- 이름·정렬은 읽기 전용 표시 정보다. 선택 option의 값은 원래 `physicalIndex`이고, 본문 별칭·identity·출처 마스크·JSON/변경 목록·쓰기 권한을 바꾸지 않는다. 인증된 정규 전장은 등장 목록이나 목적 조건이 없어도 맵 타일 편집을 위해 선택할 수 있다.
- `editor-scenario-chapter-data.mjs`에는 숫자 좌표와 순서만 있다. `editor-scenario-chapters.mjs`는 현재 정품 원본 및 승인 a/b/c 프로필의 본문 세 scope 값과 정확한 별칭 집합을 검사해 연결한다. 다시 열 때 과거 `chapter` 정보는 버리고 현재 입력에서 연결한다.
- 완결편 제목 셀169·179·180에 남아 있는 승인본의 리터럴 `Ｆ588`은 같은 제목 그림125의 원제 `絆`와 원본 글리프를 대조해 UI에서 `인연`으로 표시한다. TSR 문자열이나 내보내기 바이트는 수정하지 않는다.

현재 승인 EXEC의 제목 그림 선택 표는 F `060B4C64`의 73 byte(SHA-256 `917627f88a611b3eda10090566ed6c7191d159e282b5bfe46b9e0a80a9f18787`), 완결편 `060BB2A4`의 200 byte(`c62cf63daa84c2a0a51976fcc26cd708cd12c0935e68534389ec916e697e9c2d`)다. 소비자 두 경로·원래 BF 제목 전이·진행표 및 실제 제목 그림 목록을 대조했다. 정품 원본도 전체 이미지 해시를 확인한 뒤 해당 표·소비자·제목 명령과 최신 승인본의 동일성을 검사했다. 이는 전체 분기를 실제 게임에서 플레이했다는 증거가 아니다.

최종 숫자 연결표 SHA-256은 `08c0ec4506a8be200fd0b68f9a3aa02195410a8f88c5c965b7cda716334d5cd4`다. 사적 근거는 저장소 밖 `scenario-episode-order-contract-20261011-1/`과 `editor-episode-metadata-review-20261011-1/`에 보관한다. 아래의 두 개별 게임 실행 연결과 이전 화면 검수는 각각의 당시 범위를 설명하며, 현재 전체 정렬의 네이티브 실행 증거로 확대하지 않는다.

정품 원본 F·완결편을 기존 폴더/CUE 정규화와 현재 production inspector로 열어, 각각 50·83개 연결의 일본어 제목 판독·화수순 정렬·입력 배열과 원래 선택 식별자 보존을 확인했다. 두 원본의 전체 해시·원본 provenance가 유지되고 승인 패치로 오인되지 않았다. 새 이미지·내보내기·게임 실행은 하지 않았다. 실제 원본 통합 기록은 저장소 밖 `scenario-episode-order-contract-20261011-1/stock-public3-inspector.json`에 있다.

모바일에서는 시나리오 제목 선택기를 한 줄 전체 폭으로 배치한다. 실제 남은 높이로 편집값 페이지를 나누며, 안내가 나타나도 맵 타일·기체/이벤트 도구를 다시 선택할 수 있다.

현재 승인 F a·완결편 c를 실제 폴더 선택과 전체 해시 확인 경로로 열어 F 52개·완결편 98개 표시 항목의 원래 선택 ID·맵 연결·133개 화수/제목/정렬을 대조했다. `1440×1000`, `390×844`, `320×568`의 30상태에서 맵 클릭·좌표 수정·처음 값·도구 왕복을 검수했으며 JavaScript 오류·문서 넘침·선택 문구와 입력 잘림은 없었다. 정품 원본의 실제 133개 일본어 제목은 같은 CSS의 폭 측정으로 별도 확인했다. 이는 Mac Edge 화면 크기 검수이고 실제 삼성 브라우저 실행을 주장하지 않는다. 기록은 저장소 밖 `scenario-chapter-final-browser-review-20261011-1/`에 보관한다.

## 서로 다른 세 번호

| 좌표 | 확인된 역할 | 표시할 수 없는 추론 |
|---|---|---|
| SCEDATA 논리 선택 번호 | 디렉터리의 압축 본문 선택. 여러 번호가 같은 본문을 공유할 수 있다 | 선택 번호 102를 102화로 표시 |
| SCEDATA 물리 본문 번호 | 디렉터리의 unique 시작 주소를 물리 순서로 정렬한 번호. 쓰기 위치와 출처 검사에 사용 | 물리 본문 5를 5화로 표시 |
| TSR root22 제목 선택 번호 | 게임이 표시할 이름표 항목. 런타임의 별도 상태 byte로 선택 | 본문 번호나 현재 SCEDATA 선택 번호와 항상 같다고 가정 |

F의 논리 선택 번호는 74개, 현재 F완결편은 200개다. 이는 게임의 플레이 화수 수를 뜻하지 않는다. 작전 목적 조합의 지원 개수 또한 해석·쓰기 계약을 만족한 **물리 본문 개수**이지 플레이 화수 개수가 아니다. 공유 별칭, 분기, 도입부와 사용 여부를 실제 진행 경로로 연결하기 전에는 지원 범위를 ‘몇 화’라고 표현하지 않는다.

## 실행 파일에서 확인한 제목 상태

현재 승인 F/완결편 실행 파일의 원문을 읽기 전용으로 확인했다. 주소는 SH-2 실행 주소이며 TSR 해제 offset이나 디스크 offset이 아니다.

| 동작 | F | F완결편 | 관찰 |
|---|---|---|---|
| BF 명령 dispatcher | `0601FCF8` | `0602149C` | 현재 명령의 subopcode로 별도 handler 선택 |
| BF.00 | `0601FD20` | `060214C4` | 기존 GameState+6 byte를 +7에 복사한 뒤, 명령의 지정값으로 +6을 변경 |
| BF.03 | `0601FD9C` | `06021540` | 명령의 지정값으로 +7만 변경 |
| 제목표를 읽는 표시 경로 | `0606B5BC..0606B5D8` | `06071F90..06071FAC` | TSR root22를 선택하고 GameState+7 byte를 이름 셀 번호로 사용 |

GameState는 F `060B2090`, 완결편 `060B8570`이 가리키는 포인터로 찾는다. BF.00에서 새 선택 번호와 제목 선택 번호는 서로 다른 값이 될 수 있다. BF.03은 현재 본문을 바꾸지 않고 표시 제목을 바꿀 수 있다. 이는 일반 규칙이며 특정 본문의 고정 작전명을 보장하지 않는다.

완결편의 실제 게임 저장 후 새 부팅·이어하기에서 읽은 상태는 GameState+5=34, +6=102, +7=67이었다. 이 관측은 **+6과 +7이 서로 다르다는 증거**다. `102→67`을 모든 시점의 제목 연결로 등록하거나, 두 번호의 차이 35를 다른 본문에 적용하지 않는다. +5도 이 판독만으로 확정 화수로 표시하지 않는다.

다음 조사는 원래의 공통 스크립트와 본문의 CFG에서 BF.00/BF.03 명령 경계, 호출·복귀 순서 및 상태를 설정하는 경로를 함께 확인하는 것이다. 명령과 같은 byte가 발견된 사실만으로 해당 경로가 실행됐다고 판단하지 않는다.

## 완결편의 실제 완료 화면과 제목 연결

완결편 물리 본문 9·선택 번호 106은 원래 root0의 BF.00(해제 offset 6905, 지정값 107)을 지나 완료했다. 실제 게임 상태가 `[+5,+6,+7]=[38,106,105]`에서 `[39,107,106]`으로 바뀌고, 다음 원본 본문 10이 RAM에 로드됐다. 그 완료 저장 화면에 `제38화「자비 가문의 망령」`이 표시됐다. 이 증거와 동일 입력의 TSR root22 제목 셀 106을 연결한다.

제품의 연결 조건은 최신 승인 완결편 계열의 정규화된 본문 9 scope 세 값(해제 길이 12645, mask SHA-256 `f5addcb2ef2442522d82c7e5d9da9647cfa4de9fcb3372a0a8c9521b3b65dfe4`, 변경 불가 구간 SHA-256 `e24ee5ccadfae119d609fb6b4c834befec3ec963004a94dd7c41ac0b0c583541`)과 유일한 선택 번호 106이다. 제목 셀은 같은 사용자 BIN의 정상 판독 결과여야 한다. 빈 이름, 긴 이름, 제어문자와 줄 구분자는 연결하지 않는다. 정품 원본은 별도 scope이므로 이 연결을 상속하지 않는다.

선택기에는 작전명만 표시하고 전체 자료 번호는 설명·툴팁에 유지한다. 위 실행에서 관측한 38화를 다른 분기의 고정 화수로 등록하지 않는다. 이름 문자열은 저장소에 포함하지 않고 사용자 BIN에서 읽는다. `verifiedTitle`은 읽기 전용 표시 정보이며 프리셋 identity·본문 마스크·출처 검사·쓰기 권한을 바꾸지 않는다.

## F의 완료 저장 화면과 제목 연결

`20261011-18`에는 F 물리 본문47·유일 선택67의 이름 연결을 추가했다.
같은 승인 F-a 기반의 기존 사적 OB03 검증 경로에서 정상 승리 처리를
거쳐 게임 저장34와 MCA 없는 새 부팅 Load34를 확인한 자료를 재검토했다.
입력 상태 `[+5,+6,+7]=[34,67,29]`에서 원래 EC01/common ECFF 완료 뒤
`[35,73,67]`이 되고 원래 다음 본문51이 로드됐다. 원본문47의 명령 경계
offset4947에는 BF.00 지정73이 있으며, 완료 저장 화면의 작전명은 같은
사용자 TSR root22 셀67의 판독값과 맞았다.

이 관측은 사적 OB03에서 승리 trigger를 바꾼 경로다. 원래 완료 action과
EXEC·TSR는 유지됐지만 원래 전투 목적 전체를 플레이한 증거로 확대하지
않는다. 당시 observer는 BF.00과 제목 renderer를 직접 watch하지 않았으므로
해당 store의 직접 trace라고 하지 않는다. 원문 명령·실제 GS·완료 화면을
함께 사용한 이름 연결이며 고정 화수34나 분기 이름은 추가하지 않았다.

연결 scope는 해제 길이13,084, mask SHA-256
`96c7b1692dd75e633b11ffb085bc2a78f5fba6e869e8a7f4a25161e11766090a`,
변경 불가 구간 SHA-256
`5c6d0a062f9708e8dbc5a2aebc2c2027ef1eb4cdf2a132daaa4109023024e93d`다.
현재 승인 a/b/c의 세 scope가 같다는 정적 검사와 a 기반 실제 실행 근거를
구분하며 b/c 각각의 게임 실행을 주장하지 않는다. 정품 원본·공유 별칭·다른
본문·원복 전 wrapper 길이는 이 연결을 상속하지 않는다. 실제 정규화된
출처 scope를 받은 경우에만 기존 편집값을 보존하면서 읽기 전용 이름을 붙인다.
계약 보고서 SHA-256은
`43c3978c4b9686c0a446d808eb09f502398a3a68cfdc8da76e7924b348007512`다.

## 구현과 core 연결 계약

`assets/editor-scenario-labels.mjs`는 읽기 전용이다.

- `readScenarioTitleTable(decoded, root[22], gameId, decodeEditorName, nameMap)`은 기존 TSR 문자 디코더를 재사용한다. 해제된 TSR과 이름표 문자열은 사용자 세션 안에서만 읽는다. 이름 문자열이나 추출 TSR을 저장소에 넣지 않는다.
- F는 SCEDATA 논리 선택 범위와 대응 여부를 조사하기 위한 처음 74개 **제목 셀**을 읽는다. 이 제한은 root22 전체 길이의 선언이나 74개 시나리오의 명칭 연결이 아니다. F의 이식된 첫 제목 포인터 값은 제목표 길이가 아니다.
- 완결편의 이름표 셀은 192개다. 192..199번 SCEDATA 선택 번호는 `no-title-cell`로 남기며 이름표 뒤의 문자 데이터를 포인터로 읽지 않는다.
- 반환값의 `titleIndex`는 제목표 좌표다. `physicalIndex`, `scenarioSlot`, `episode`, `route`를 추론해 붙이지 않는다. `bindVerifiedScenarioTitles()`는 아래의 개별 게임 실행 계약으로 이름을 연결한다. 현재 전체 진행표 연결은 별도의 `bindScenarioChapters()`가 본문 scope·별칭·제목 셀을 결합해 처리한다.
- `scenarioSelectorEffect()`는 **별도 VM 디코더가 명령 경계를 이미 확인한** BF.00/BF.03의 상태 변화를 표현한다. raw 검색 결과를 인증하는 함수가 아니며 출처 검사나 바이너리 쓰기 권한을 부여하지 않는다. 이전 selector가 없으면 제목 상태는 `null`이다.
- `scenarioSelectionLabel/Description/SharedCaption`은 현재 시나리오 row의 인증된 `scenarioSlots`와 위 계약으로 만든 `verifiedTitle`을 사용한다. `scene.title`, `scene.episode` 등 미확정 명칭을 자동 사용하지 않는다.

core는 기존 문자 디코더로 읽은 제목표를 위 연결 함수에 전달한다. 이 정보는 프리셋 identity, recordIndex, decoded masks 또는 BIN 쓰기 범위를 바꾸지 않는다. 다른 제목 연결을 추가할 때에도 동일 세션의 제목 셀과 확인된 경로 근거를 결합한 별도 계약이 필요하다.

## 이전 자료 번호 중심 화면 개선 기록

승리·패배의 각 조건에서 `기체 종류`를 고르면 숫자 기준값 대신 실제 입력 BIN의 기체 이름 목록을 한 줄 폭으로 표시한다. 비교는 `있음`·`없음`만 선택하며, 동명이면 번호를 덧붙여 구별한다. 실제 모델의 기체 행·게임 구분·기체 표 범위로 목록과 조건을 제한한다. F는 #1..#367, 완결편은 #1..#447이고 #0은 대상 기체로 표시하지 않는다.
