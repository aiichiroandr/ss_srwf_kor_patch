# SRWFP v3 (Nightly 검수안, 아직 공개하지 않음)

v1/v2 파서·승인 인덱스·기본 선택은 변경하지 않는다. v3는 Nightly 행을
선택한 경우만 별도 워커에서 처리한다. 원본 이미지, 저장 파일, 영상 파일을
사이트에 업로드하거나 정적 사이트에 싣지 않는다.

## 입력과 봉투

`SRWFKP3\0` 8바이트, 큰 엔디언 JSON 헤더 길이 4바이트, UTF-8 JSON,
제한된 VCDIFF 스트림 순이다. 카탈로그에는 패치 길이 및 SHA-256,
완결편 정규 원본 크기 및 SHA-256, F 본편 21M Track 1 크기 및 SHA-256,
최종 BIN 크기 및 SHA-256을 별도로 고정한다. 원본 2종은 재구성하기
전에 각각 해시를 전수 확인한다. 완결편 기준은 정품 원본만 사용한다. 기존 F 연동 BIN은 여섯 영상 각 SHA-256이 모두 일치할 경우 보조 입력으로만 읽으며, 롬 편집값이나 실행 코드를 대체 입력으로 삼지 않는다.

- 전체 패치 최대 80 MiB, JSON 헤더 최대 128 KiB, 결과 최대 333,000섹터.
- VCDIFF는 표준 기본 명령표, 2 MiB 이하 타깃 창, 현재 창 안의 역참조에
  한정한다. 외부·과거 타깃 창, 사용자 명령표, 이차 압축은 받지 않는다.
- 참조 기록은 2,352바이트 RAW 섹터 안에서 원본과 결과 위치 및 개수를
  선언한다. 기록 간 출력 겹침, 범위 초과, 원본이 아닌 객체를 거부한다.
- 참조 대상으로 지정된 영역은 VCDIFF 단계에서 전부 0이어야 한다.
  따라서 실제 원본 영상과 CD-DA를 VCDIFF 본문에서 재생성하는 일반
  ADD/COPY 데이터로 넣으면 최종 적용이 중단된다.
- 결과 전체 크기와 SHA-256이 일치하기 전에 다운로드를 보여 주거나
  저장 스트림을 정상 종료하지 않는다. 잘못된 입력이나 중단은 실패로
  끝나며 기존 원본 파일을 수정하지 않는다.

## 검수 빌드

원본 F 본편과 완결편은 각각 인증한다. F 원본에서 그대로 읽는 여섯 영상의
논리 데이터는 66,698,400바이트이며, 복원 위치의 디스크 헤더는 패치에
포함된 데이터와 조합한다. 완결편에서 그대로 가져오는 CD-DA 및 이동한
동일 논리 섹터 26,488,672바이트도 별도 참조한다. 두 원본이 없으면
검수본과 동일한 BIN을 만들 수 없다. 패치 25,335,221바이트는 Node와 로컬 Edge에서 적용해 동일한 결과를 확인했다. 모바일 화면 크기는 PC에서 검사했고 물리 기기는 미검증이다. 서브 에이전트가 확인한 게임 세이브와
에디터 호환 여부를 결과 형식 검증과 혼동하지 않는다.

이 분기는 향후 버전마다 별도 승인·출시 게이트를 거친다. 오프라인
테스트, 잘못된 원본과 취소, 배포 기준 v1/v2 고정 검증, 모바일 실기,
실행 결과 BIN/CUE, 카트리지 일반/중단 저장, F 전승, 4차 변환,
구버전 롬 편집 이관은 각각 판정한다.
