# ALICE 이름·초상 등록 — 2026-10-26

이 문서는 최초 이름·초상 단계의 기록이다. 이후 실제 서브파일럿 연결·정신기·SP·
변형 및 게임 저장/재실행 검증은 [ALICE 서브파일럿](ALICE_SUBPILOT_20261026.md)에 있다.
아래의 미연결 설명은 최초 단계에만 해당한다.

사용자가 승인한 어두운 여성 실루엣과 절제된 회로 표현을 그대로 사용한다.
40×40 초상 안에는 문자를 그리지 않고, 파일럿의 전체 이름과 짧은 이름
칸에 `ALICE`를 등록한다. 원작의 공식 인간 외모라고 주장하는 그림이 아니다.

## 지원 범위와 사용

- 현재 지원 기반은 완결편 승인 v0.3c
  (`0fb10cbf4332f94c865c0e8d0a0c7234f8f6083bdbbb5a06198cebff871d195d`)이다.
  F, 다른 폰트, 검수 중인 v0.4의 호환성을 추정하여 열지 않는다.
- 로컬 에디터에서 지원 BIN을 열고 파일럿 목록의 **ALICE 추가**를 누른다.
  **ALICE 등록 취소**, 편집 내용 JSON 내보내기/가져오기, BIN 저장 및 재열기를 지원한다.
- 기존 인물 대신 빈 파일럿 #399를 사용하며 새 FACE 번호는 #342다.
  사용 중인 슬롯, 다른 초상 아카이브, 손상된 등록 정보는 거부한다.
- 이 기능은 **이름·초상 등록**이다. Ex-S의 인간 주파일럿 + ALICE 서브파일럿
  배치, 정신기·SP, 새 음성, 다인승 로직은 연결하지 않았다. 능력치 편집도
  허용하지 않는다. 임의 기존 파일럿을 ALICE로 이름만 바꾸지 않는다.
- 등록 취소는 빈 파일럿 및 원래 이름 참조를 복원한다. 이미 저장한 초상
  아카이브의 손실 없는 재압축과 추가 초상은 유지하고 네이티브 주소표도
  함께 유지한다. 취소가 최초 BIN의 바이트 전체 복원을 뜻하지 않는다.

## 네이티브 형식과 무결성

새 그림은 40×40, 4bpp, RGB555 16색 팔레트의 11개 가시 색상이다.
한 FACE 레코드의 네 변형 칸에는 동일한 중립 실루엣을 넣는다. 기존
인공지능 FACE의 유효한 subheader를 사용자 이미지에서 가져와 조립한다.
이름은 기존 문자 집합의 `ＡＬＩＣＥ` 바이트열을 사용한다.

기존 342개 FACE 레코드는 해제한 전체 raw 바이트가 모두 같은지 검사하며
압축 스트림만 더 작게 다시 저장한다. 새 그림까지 고정 파일 길이
351,651바이트 안에 넣는다. TSR root2의 FACE 주소표 미러도 343셀로
만들어 4바이트 경계에 이설한다. FACE 파일의 헤더만 갱신하면 게임은
오래된 미러로 잘못 읽으므로 둘을 반드시 함께 저장하고 검사한다.

기준 FACE SHA-256:
`273c2f6e023636a466cbdb9cab7ed02c79bc5ce59bab6f2fb721a7f32c389ff4`

새 FACE SHA-256:
`560f6fdfee3142df23eee44ae88c0c228b6396a85a5a3005ec8a3b8ee09443fb`

`SRWALC01` 꼬리는 원래 전체/짧은 이름 상대참조와 root2 상대참조를
보존한다. 재열기는 이를 원복한 뒤 기존 provenance 검사를 실행하고,
재작성 결과와 저장된 모든 등록 바이트가 정확히 같은지 확인한다.
FACE와 미러 등록 표식이 한쪽만 존재해도 거부한다. FACE의 고정 해시,
CD 체크섬, 마지막 섹터의 0 패딩을 검사한 뒤에만 해당 파일의 제한된
영역을 포함하는 대체 불변 해시를 허용한다. 임의 초상 편집 권한을
출처 마스크로 허용하는 기능이 아니다.

정렬된 기본 이미지에서는 TSR 2,780바이트를 추가한다. 다른 이름 편집으로
꼬리 위치가 달라지면 최대 3바이트를 더 넣어 미러 정렬을 유지한다.
게임 RAM 및 디스크 한도 검사를 그대로 통과해야 저장한다. 원본 게임
픽셀·ROM·CUE·세이브는 저장소에 포함하지 않는다.

## 로컬 검증 근거

비공개 근거는 `build/alice-registration-20261026/`에 보관한다.

- `report.json`: 실제 v0.3c BIN에서 UI 등록 → 프리플라이트 → 출력 →
  영수증 없는 재열기, 초상 픽셀 일치, 기존 파일럿 이름/그림 번호 보존,
  무수정 재출력 바이트 일치, 취소, JSON 재적용 확인.
- `combined-report.json`: 기존 Ex-S #430 / G크루저 #431와 무장을 포함한
  로컬 수정본에 ALICE를 합쳐 저장·재열기. 기존 기체 필드와 무장 유지.
  해당 조합의 TSR 잔여량은 516바이트다.
- `browser-report.json`: 실제 수정 BIN으로 백그라운드 브라우저에서
  1440/390/320px 화면 표시, 40×40 RGBA 픽셀 일치, 취소/재등록,
  가로 넘침 없음 및 JavaScript 오류 없음 확인.
- `native/alice-native-status.png`, `native/pilot-list.png`:
  수정 BIN을 Mac 네이티브에서 정상 부팅·로드한 뒤 파일럿 목록과
  능력창의 ALICE 이름 및 실루엣을 실제 게임 렌더러로 확인.
  표시 시험을 위해 **복사 세이브의 첫 파일럿 슬롯을 일시 RAM에서만
  #399로 교체**했다. 이는 Ex-S 서브파일럿 연결이나 정상 시나리오
  합류의 증명이 아니다. 원본 세이브와 제품 BIN의 승무원 구성은
  이 시험으로 변경하지 않았다.

직접 VM 상태를 덮어 대사를 시작하려던 별도 실험은 정상 UI 진입이
아니어서 실패했다. 그 캡처는 성공 근거로 쓰지 않는다. 최종 표시는
기존 파일럿 능력창의 정상 UI 경로를 사용했다.

단위 회귀는 빈 슬롯/다른 게임/등록 변조 거부, 두 이름 필드, 픽셀
규격, 다른 길이의 TSR 뒤 미러 정렬, 등록 취소, 선택적 JSON 적용을
포함한다. 전체 Node 실행에서는 관련 없는 preview-resource 시험이
종료되지 않아 해당 자식 프로세스를 중단했다. 그 결과를 전체 통과로
보고하지 않는다. 추가한 오류 코드의 한국어 안내 누락은 수정 후
frontend-contract 집중 회귀로 다시 확인했다.
