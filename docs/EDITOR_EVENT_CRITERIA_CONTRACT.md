# 기존 사건의 턴 조건 조합

2026-10-10. 새 사건이나 증원을 생성하지 않고, 확인한 기존 사건의 턴 판정만 조합한다.
현재 지원 대상은 최신 승인 F완결편 계열의 물리 본문 9, 선택 번호 106에 있는 적군 시작 사건 하나다.
화면의 `자료 #106`은 게임의 106화를 뜻하지 않는다. F와 다른 본문의 기존 턴 숫자 편집 범위는 유지한다.

## 화면과 저장 계약

- 턴 조건은 1~99의 같음·아님·이하·이상이며 최대 3개다. 모두 충족 또는 하나라도 충족으로 묶는다.
- 조합의 결과가 짧은 범위로 정리되면 선택기에 `7~9턴`, `3·6턴`, `4턴부터`처럼 표시한다.
  만족하는 턴이 없으면 `발동 없음`으로 표시하며 원래 조합 식은 툴팁·접근성 설명에 남긴다.
  이는 정상 턴 1~127의 턴 판정 미리보기이며 사건 전체의 다른 조건이나 반복 실행을 보장하지 않는다.
- 조건 추가는 빈 기준값으로 시작한다. 입력을 마치기 전에는 저장 데이터에 넣지 않고 다른 자료로 이동하지 않는다.
- 마지막 유효 조건은 삭제할 수 없다. 삭제한 뒤의 조건은 앞으로 모으며, 처음 값은 현재 BIN을 열었을 때의 전체 조건이다.
- JSON의 `events`에는 같은 위치의 구조 식별값과 바뀐 `eventJoin`, `eventRule1`~`3`의 `from/to`를 저장한다.
  그룹 변경은 적용·충돌·건너뛰기를 하나의 작업으로 판정한다. F 입력, 다른 사건, 없는 식별값이나 다른 구조로 옮기지 않는다.
- BIN 출력은 그룹의 네 필드를 함께 전달한다. 기존 `turn` 변경과 함께 적용할 때는 원래 본문을 복원한 뒤 턴 숫자를 바꾸고 그룹을 재생성한다.
  사용자 그룹이 있으면 기존 턴 숫자 편집만으로 그 그룹을 지우지 않는다.
- 변경 목록에서 조건을 누르면 해당 입력칸으로 이동한다. JSON 저장 버튼과 변경 개수도 그룹 변경을 반영한다.

맵과 입력칸은 실제 높이를 측정해 함께 배치한다. 맵 설명·좌표 줄·여백과 최소 64px 그림이 남을 때 함께 표시하고,
들어가지 않을 때만 맵/편집값을 나눈다. 320×568에서는 조건 두 줄과 맵을 함께 보여 주고 세 줄은 나눈다.
데스크톱 1440×1000, 모바일 390×844와 320×568에서 조건 추가·빈 입력·조합·오류·복원·포커스를 검사한다.
화면 측정은 바이너리 쓰기나 게임 실행 검증을 대신하지 않는다.

## 생성과 출처 검사

`assets/editor-scenario-event-criteria.mjs`의 SRWFTE02는 원래 F3 건너뛰기 명령 5바이트만 후크로 바꾼다.
원래 D000 플래그 250 설정, E9 대기, E9 뒤의 재개 위치 2802, 루프, root 8의 플래그 소비 경로와 14개 root는 유지한다.
턴 조회와 비교만 추가하며 다른 페이즈로 옮기거나 1회 실행 플래그·새 개체를 만들지 않는다.

메타데이터는 80바이트다. 원래 본문 길이·후크 위치·root 5 위치·추가 코드 길이·조합 방식·조건 3개·원래 5바이트와
**완전한 내부 본문의 SHA-256**을 담는다. 예약 바이트는 0이어야 한다. 선언한 root는 직렬화된 헤더와 같아야 하며 후크 안을 가리킬 수 없다.
전체 코드와 메타데이터를 다시 생성해 바이트 단위로 대조한다. 기본 조건과 같으면 추가 꼬리를 제거한다.

정규화 순서는 TE02 바깥 → 기존 증원 형식 → 기존 OB01/OB02/OB03 또는 DL 안쪽이다. 복원한 본문은 이전과 같은
불변 시나리오 프로필·마스크·해시 검사에 다시 통과해야 한다. 내부 SHA만으로 입력을 승인하지 않는다.
기존 출처 프로필·승인 해시·편집 마스크를 넓히지 않았다. root 8을 옮기는 OB02는 사건 조합 권한을 얻지 않으며,
OB를 TE 바깥에 임의로 덧붙인 순서도 거부한다.

## 확인한 근거와 한계

순수 조건 검사에서는 256개 raw 턴 값, 모두/하나라도 조합, 원래 조회값과 상대 분기를 대조했다.
합성 입력의 기존 출처 프로필을 고정한 검사에서는 JSON/BIN 왕복·기록 없는 재열기·재편집·복원·배치 및 목적 조건과의 동시 변경을 확인했다.
추가 코드·메타데이터의 모든 단일 바이트 변조, 다른 게임/사건, 접근자, 비동기 압축 전후 요청 변조도 검사했다.

실제 게임 조사는 [콜백 실행·재개 기록](EDITOR_PHASE_CALLBACK_RESEARCH.md)에 별도로 기록한다.
비공개 동일 조건 표본 `4턴 이상 + 4턴 이하`에서는 원래 거짓 분기 대기, 2턴 실제 게임 저장,
MCA 없는 새 부팅 이어하기, 4턴 원래 플래그·하만 사건·EC01/EA·공통 종료와 진행값 변화를 원본과 대조했다.
이 표본을 모든 조합·모든 사건·모든 저장 데이터의 호환 보증으로 확대하지 않는다.

제품 경로 출력은 원래 12,645바이트에서 12,764바이트로 늘며 기존 압축 슬롯에 들어간다.
새 검사 세션은 `bounded-editor-profile`로 재열고 네 필드를 복원한다. 전체 BIN에서 변경된 것은 SCEDATA의 4개 섹터뿐이며
독립 구현으로 EDC/ECC와 나머지 섹터의 동일성을 확인한다. 실제 제품 파일의 추가 실행 검증은 위 실행 기록에 구분한다.

실제 브라우저 검수에서는 승인 입력을 폴더로 선택한 뒤 세 크기에서 25개 화면 상태를 확인했다. 추가·입력·잘못된 값·복원 중
선택과 포커스가 유지되고, 표시된 입력·선택기는 패널 안에 있으며 문서 가로·세로 스크롤이 없었다.
JSON 저장 → 복원 → JSON 불러오기 → 변경 목록의 두 번째 조건 선택 → BIN/CUE 만들기의 실제 버튼 흐름을 사용했다.
worker 출력 전체 SHA-256은 독립 core 출력과 같은 `55c539b1f6ad0e03c3ed64ee378ca61a5f85ab54a092b1b80b9911754e1bc8df`다.
새 브라우저 컨텍스트의 localStorage는 비어 있고, 해당 BIN을 폴더로 다시 골라 `bounded-editor-profile` 판정·조건 두 개·변경 수 0을 확인했다.
재편집 후 복원하면 원래 열린 BIN의 두 조건으로 돌아간다. 320px의 변경 목록에는 각 조건을 한 줄씩 표시하고,
저장 요약 `v0.3 c 한글 패치 · 변경 2건`도 270px 안의 한 줄 21px로 측정됐다.

같은 제품 `4턴 이상 + 4턴 이하`의 별도 MCA 없는 실제 부팅·정상 Load37 경로에서는 턴 1~3의 거짓 분기 대기,
실제 적군 4턴의 플래그 250 설정·원래 기체/인물 연결·대사·EC01/EA·공통 ECFF·부모 스택 소거·진행값 변화를 확인했다.
비공개 동일 조건 표본에서 완료한 전투 중 게임 저장/새 부팅 이어하기를 제품 native 경로에서 다시 수행했다고 주장하지 않는다.
자세한 관측점·원본 대조·경로 차이는 [콜백 실행·재개 기록](EDITOR_PHASE_CALLBACK_RESEARCH.md)의 제품 TE02 절에 있다.
