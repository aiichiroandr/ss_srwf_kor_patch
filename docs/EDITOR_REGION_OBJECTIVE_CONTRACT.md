# F 위치 작전 목적의 RG01 계약

2026-10-11. 이 확장은 선택한 진영의 **현재 위치**를 한 칸 또는 양 끝을
포함하는 사각형 안에서 검사한다. 특정 파일럿의 도착, 과거 통과 기록,
격추 이력 또는 신규 이벤트를 만드는 기능이 아니다. 기존 승리·패배
사건과 가드를 보존하는 F 목적 조건에 별도 형식 `SRWFRG01`을 사용한다.

## 조회와 지원 범위

승인 F의 C0.0F는 전체 8바이트 명령이다. selector -5/-4/-3은 각각
진영 마스크 1/2/4를 고른다. 실제 원본 배치와 화면의 대응을 확인한
앞 두 항목은 아군·적군이며, 세 번째는 특정 관계를 단정하지 않는
‘기타 진영’이다. 존재·부재는 C0.0F 뒤의 F0/F1 predicate 분기로 판단한다.
현재 기체 위치의 비교이며 ‘한 번이라도 도착함’으로 유지되는 조건은 아니다.

F native 경로는 actor 목록을 읽고 VM 결과 +20/+37 및 자기 stack만 쓴다.
같은 이름의 완결편 명령에는 좌표 동기화·actor 상태 bit40·공유 목록 변경이
있으므로 F 계약을 그대로 적용하지 않는다. 완결편 RG01 입력은 인코더,
JSON 적용 계획, 출력 및 정상화 단계에서 거부한다.

현재 F의 기존 목적 hook과 맵 연결을 인증할 수 있는 물리 본문은
`0,11,14,18,23,25,27,30,33,34,39,41,44,47`이다. 이 번호는 화수가 아니다.
본문 0/27/30/47은 root relocation이고 나머지는 in-place다.
현재 게임 표의 기체 수 368과 본문의 원래 선택 번호, 맵 번호·별칭·크기,
타일 값 허용 마스크를 제외한 맵 불변 바이트를 함께 인증한다.
직접 입력과 맵 선택의 좌표는 이 인증된 맵 크기 안의 0 기반 정수다.

## 저장과 재열기

기존 OB01/OB02/OB03/PV01의 16bit 의미를 변경하지 않는다. RG01에는
조건 6칸의 별도 uint32 값과 160바이트 trailer를 둔다. 이 값의 tag와
좌표 모양이 맞아도 맵 사용 권한을 뜻하지 않는다. 실제 본문별 context와
목적 hook이 필요하며 JSON의 조건·조합·우선순위·추가 턴 제한은 한꺼번에
적용하거나 거부한다. 출처 없는 이름·비슷한 번호로 조건을 이전하지 않는다.

source 전체 SHA는 정확한 원복을 위한 영수증이다. 그것만으로 새 불변
바이트를 허용하지 않는다. 출력 재열기는 원문 복원, metadata와 생성 코드의
정확한 재생성, 기존 승인 프로필의 불변 범위를 계속 검사한다. 자기 일관성이
있는 source hash를 다시 계산한 위조도 불변 바이트가 다르면 거부한다.
합법적인 타일·배치·턴·일반 수치 편집은 같은 context를 유지한다.

생성 조건 코드는 최대 99바이트, 가드·pending은 최대 38바이트,
목적 텍스트는 최대 84바이트, 전체 증가량은 최대 381바이트다.
F RAM 0x8000과 원래 압축 슬롯을 넘으면 실패한다. 게임 목적 문구는
승리·패배 각각 NFKC 18자 이내여야 하며 좌표나 조건을 잘라 저장하지 않는다.

## 검증 범위와 남은 실제 실행

승인 코드 CPU 재실행 196사례, 별도 조건 제어 512사례 및 실제 F 본문
14개의 압축·저장·재검사·원복을 확인했다. 원 디렉터리와 다른 51개 본문은
각 검사에서 그대로다. 실제 F v0.5-a의 본문11/맵10 표본은 생산용
`PRODUCTION_TRUST`의 전체 이미지 출력과 영수증 없는 새 inspector를 통과했다.
SCEDATA의 MODE1 5개 섹터만 바뀌며 나머지 245,961개 섹터 및 기존
프로필·불변 범위가 동일하고 EDC/ECC가 맞다.

합성 기준 프로필은 RG01 이전 inspector로 고정했으며, 새 구현으로
프로필 허용 범위를 넓혀 검사를 통과시키지 않았다. 정상 JSON→BIN→재열기,
다른 합법 편집과의 조합, 기존 조건 형식 전환, 원복, 비동기 입력 변조,
metadata/code/header/context 위조 거부를 별도로 검사한다.

이 근거는 RG01 새 조건의 실제 에뮬레이터 승리·패배·게임 저장·새 부팅
실행 완료를 주장하지 않는다. 기존 OB03의 실제 게임 실행 근거와 구분한다.
전체 목적·이벤트·증원 요청 범위와 원격 배포 제한을 줄이는 계약도 아니다.

사적 backend 동결 보고서 SHA-256은
`d9295d30de1e9e8ba93076585585aaa246b233207ea90b62231fd35ec8e624fa`,
source query 보고서는
`41ad9e6f41af08feb8917f8a94a9510eb50f4b9a1ab6997aa8af0a39f21fe4aa`다.
게임 파일·추출 본문·native capture는 저장소 밖에 보존한다.

## 로컬 통합 검증 — 20261011-17

최신 로컬 코드에서 F 14개 본문을 한 JSON 거래로 편집하고 전체 이미지
출력을 새 생산용 inspector로 열었다. 영수증 없이 `bounded-editor-profile`로
검사됐으며 다른 38개 본문과 디렉터리, 인증된 맵 context 44개가 같았다.
전체 출력 SHA-256은
`dcb2ecb91c6a78524b209586b325db6e0b413a5a29b7498a712cdaee4e0d4406`다.
맵10 타일 편집과 위치 조건 재편집도 조합해 다시 검사했다. 전체 조건과
타일을 원래 값으로 돌리면 해제 본문 52개·루트와 맵 데이터가 같지만,
재압축된 전체 BIN은 원본 해시와 다르다. 매 출력의 raw 섹터 245,966개를
비교했으며 허용 파일 밖의 바이트는 같고 변경 섹터의 EDC/ECC가 맞다.

별도 실제 브라우저에서 본문11의 적군 `(4,5)` 없음 조건을 지정하고
BIN/CUE 만들기 버튼을 눌렀다. 결과는 578,512,032 bytes이며 SHA-256은
`0452f0e12258085f6ae0108cddb6b74c69bb297249b02b34081a7186ca917b85`다.
새 페이지의 저장 기록을 비우고 이 BIN과 생성 CUE를 File 객체로 다시
선택해 열었다. INSPECT 요청의 영수증 목록은 빈 배열이고 패치 해시 검증
재사용 값도 없었다. 새 검사는 `bounded-editor-profile`로 통과했으며
조건과 전체 해시가 같았다. 재편집 후 ‘처음 값’은 열린 개인 BIN의 값으로
돌아왔다. 검증 중 BIN/CUE를 파일시스템에 쓰거나 업로드하지 않았다.

데스크톱 1440×1000, 모바일 390×844·320×568에서 총 28개 입력·오류·맵
선택·변경 목록·복원·JSON·키보드 상태를 실측했다. 이 상태들에서 문서
넘침·입력칸 잘림·선택 문구 잘림·JS 오류는 없었다. 완결편 숫자 조건
19개 본문과 기존 OB03·PV01·PH01 출력도 회귀 검사했으며, 기존 세 제품
표본의 전체 해시를 그대로 재생성했다. 이는 신규 RG01의 실게임 실행
검증을 추가하는 근거는 아니다.

## 디렉터리 검사 보강과 실게임용 위치 조건 표본

2026-10-11. 이전 사적 검사 일부가 아카이브 API에 없는 `.directory`를
비교하여 양쪽 `undefined`가 같다는 결과를 디렉터리 보존 근거로 사용한
결함을 발견했다. 기존 동결 자료는 보존하고, 실제 `directoryLength` 범위의
바이트와 `.slots` 전체를 직접 비교하는 추가 검사를 작성했다. 이전 F 출력
3개·완결편 출력 8개는 각각 기존 전체 이미지 해시 그대로 재생성됐으며,
실제 F 592바이트·74슬롯 및 완결편 1,600바이트·200슬롯이 원본과 같았다.
이 추가 결과가 이전 잘못된 디렉터리 비교 항목의 근거를 대체한다.
추가 보고서 SHA-256은
`e792677aaef9149734f37b1270dc7092bc6f25c1512c3a84465777e863e931e7`이다.

별도로 F 본문47·선택67·맵31에서 아군의 `(8,5)..(10,7)` 영역 현재
있음·없음 조건을 각각 지정한 사적 BIN 두 개를 만들었다. 입력은 승인
F v0.5-a이며 출력 길이는 각각 578,512,032바이트다. 압축 본문은 원래
7,857바이트 슬롯 안의 7,704/7,703바이트이고, raw 245,966개 섹터 중
지정한 SCEDATA 5개 섹터만 달라진다. 실제 디렉터리와 다른 51개 본문은
그대로이며, 원 root8/13을 정상화하면 원본문 전체가 복원된다. 해당
SCEDATA의 원본·출력 MODE1 EDC/ECC와 새 생산용 출처 검사도 통과했다.
이 두 표본도 위 디렉터리 추가 검사에 포함했다.

있음 출력 SHA-256은
`92ec9663bee84164bfbbf47a6861b38fa125f695793949f731d0c53eeada545a`,
없음 출력은
`dc52feff404da875be060e470dded0110f7a14eb01346f1903879d501f89751d`다.
물질화 보고서 SHA-256은
`46e3503af07491bc6bee283705aea25d4bcb161cff437dee29da30e952dfda37`이다.
이는 실행할 디스크의 변경 범위·압축·출처 근거다. 새 조건의 실제 게임
판정·클리어·게임 저장·새 부팅 실행은 아직 완료 근거로 계산하지 않는다.

## F RG01 실제 게임 판정·저장·새 부팅 — 2026-10-11

본문47·선택67·맵31의 아군 사각 영역 `(8,5)..(10,7)` 제품 출력 두 개를
자기 이미지에서 실행했다. 원 집계는5이며 actor0·1·2·3·8이 포함된다.
있음 조건은 원 승리·보상·정상 후속 대사·완료 저장으로 이어지고, MCA 없는
새 부팅의 정상 데이터34 로드에서 전투 후 본문51 전체10,494바이트·
14개 루트·완료 진행이 일치했다. 없음 조건은 불충족·대기 후 자기 이미지의
전투 중 저장00을 만들었으며, MCA 없는 새 부팅의 Continue 뒤 정상 턴
종료에서 24회 재검사해 집계5·불충족·E9 대기·공통 반환0을 유지했다.

각 조회 경계의 개체 표6,560바이트·인수·상위 ABI 레지스터와 반환 경로를
대조했다. 정상 턴 진행이나 저장을 거친 전체 표까지 바이트 동일하다고
주장하지 않는다. 최초 입력 저장33의 생성 이미지 출처는 알려지지 않은
한계로 남기고, 실제 제품에서 새로 만든 저장00/01과 구분했다.

독립 재검사 결과는 전체 파일1,086핀·58단계·28조회 PASS다. 보고서
SHA-256은 `1543940f028974a506045ceefdfe7252443a70718dd94b1807ce624e5871c9e1`이며
원 실행 파일·trace·저장·캡처는 저장소 밖에 둔다. 코드 cache 갱신 전
원 검사기와 전체 입력을 확인하고, pinned live18 텍스트72개를 정확하게
보존한 읽기 전용 검사기에서도 같은 결과를 재확인했다. source snapshot
manifest SHA-256은
`e12321654614a80f6448c81f6482cfac4e5f39fb8f2b59f74fcb650981e31470`다.
이는 두 조건의 각 한 경로이며 다른 본문·진영·사각 영역·패배 사건의
전수 실행 증거가 아니다. 완결편 지역 조회의 부작용 복원·특정 인물의
도착 이력과 신규 사건 생성은 별도 미완성 범위로 유지한다.

## 완결편 위치 조건의 사적 구현 진행 — 2026-10-11

완결편 최신 c의 물리 본문5·선택102에서 공통 위치 조회가 바꾸는 임시
개체1,184바이트와 목록257바이트를 호출 전에 복사하고 반환 전에 복원하는
별도 helper를 구현했다. 실제 자기 이미지의 세 번 조회에서 집계1과
즉시 F0 분기·원 승리 진입을 관측했으며, 각 조회 경계의 전체 개체 표
6,560바이트·인수·상위 ABI와 목록 복원이 일치했다. 원 브라이트 승리
대사와 일반 확인 입력 뒤 시북의 후속 대사까지 진행했다. 이는 현재
위치 조건의 원 이벤트 진행 근거이며 해당 출력의 화 완료·게임 저장·
새 부팅은 아직 확인하지 않았다. 입력 저장의 생성 이미지도 미상이다.

별도 브라우저용 순수 컴파일러는 위치·턴·인원 조건을 승패별 최대3개씩
조합한다. 공유 helper의 동일한 검사들을 짧은 직접 조건 분기로 바꾸어
392→336바이트로 줄였고, IP 코드는 원래256바이트 범위를 유지한다.
여섯 위치 조건을 포함한18개 사적 조합은 모두 원래8,067바이트 압축
슬롯 안의7,969~8,044바이트로 들어간다. 엄격한 원 코드 CPU 검사에서
204개 조회·12개 일반 명령 차등 비교·44개 거부 검사가 통과했다.
별도 VM 분기 모델512개 위치 조합·640개 혼합 조합은 실제 게임 실행
증거와 구분한다.

사적 NR02 형식은64바이트 metadata로 조건과 원 head14를 보존하고,
원본문을 복구한 뒤 helper·분기·목적·metadata 전체를 다시 생성해 비교한다.
BOOT 코드256바이트와 EXEC 분기 셀4바이트도 이 본문과 함께 일치해야
정상화할 수 있다. 원 BOOT·EXEC 전체와103개 원 해제 본문·200슬롯을
복원했으며, 정상화한 메모리 이미지가 기존 불변 출처 프로파일로 다시
열리는 것을 확인했다. 사적 native 이미지 자체는 영수증을 붙여도 현행
검사기가 거부한다. 프로파일·마스크·승인 해시를 넓히지 않았다.
이 구현의 동결 보고서 SHA-256은
`f3dd734c56de168a7e34d6aad5bd8788e0120e56664f4122f38d0b49167d7051`이다.

새 컴파일러의 실제 실행·불충족·저장·새 부팅, 실제 맵 범위, 다른 합법적
개인 편집과의 조합, 목적 문구와 UI·JSON·BIN 연결은 남아 있다. 완결편
위치 선택은 제품 화면에 아직 허용하지 않는다. 원 승리 대사가 남은
캡처를 대사 없는 맵으로 잘못 분류한 사적 관찰은 별도 정정했으며,

### 완결편 후속 진행과 개인 편집 조합 확인

같은 자기 시험 이미지에서 시북·아무로의 원 대사를 정상 확인한 뒤,
원 EC01·EA와 공통 ECFF 반환1, 부모의 원 결과1 분기 뒤 명령을 실제로
관측했다. 보너스 경험치 화면까지 이어졌으며, 이 콜백 완료를 전체 화
완료나 저장·새 부팅 완료로 확대하지 않는다. 새336바이트 helper의 실제
실행 근거도 아니며 앞서 사용한 사적 helper의 진행 증거로 유지한다.

별도 조합 시안은 현행 원본 검사기가 연결한 맵56의 실제30×42 범위를
사용한다. 본문5의 기존20개 마스크 범위·불변 해시를 그대로 사용해
30바이트의 합법적 배치 좌표·보상 변경을 보존한다.12개 개인 수정본이
8,004~8,010바이트로 압축되어 원래8,067바이트 슬롯에 들어가고 정확하게
원복됐다. 불변 바이트13,432개 각각의 단일 비트 변조와 범위 위반33개는
거부했다. 맵 밖 좌표를6비트라는 이유만으로 허용하지 않는다.

실제 에디터로 HP·배치·보상·맵 타일을 함께 바꾼 입력에 새 조건을 적용하고,
정확한 BOOT·EXEC·본문 정상화 뒤 영수증 없는 새 현행 검사기로 열었다.
개인 편집과103개 해제 본문·기존 불변 범위가 유지됐다. 정상화가 이미지
승인을 대신하지 않도록 다른 본문0의 변조를 별도로 넣었으며, 영수증
유무 모두 기존 출처 검사에서 거부됐다. 이 조합 시안의 동결 보고서
SHA-256은 `fb78449be45f69783cf10dca777122a6447e78b9d4f7f76b80863d4fce86e50c`다.

새 조건 코드의 실제 게임 실행·불충족·게임 저장·새 부팅 및 제품
UI·변경 목록·복원·JSON·BIN 연결은 계속 미완료다. 이 절은 완결편
위치 선택을 제품에 활성화하거나 다른 맵의 지원을 승인하지 않는다.

### 실제 맵 범위와 기존 기체·파일럿 조건의 보존

후속 사적 C3는 맵56의30×42 범위로18개 압축 표본을 다시 검증했다.
등록된 조회 구간의 잘못된 NRG1 표식은 오류로 끝내며, 다른 원본 문맥의

새 코드의 실제 게임 실행을 대신하지 않는다. 동결 C3 전달본 SHA-256은
`7184c9e380e44d247ad8b5270d9903f737aee293c9ef8bb8b217a0ac45d3bc5d`다.

별도 C4는 영역 조건과 기존 기체 종류·파일럿·진영별 개체 수·턴 조건을

기체 집계의 정수 결과와 파일럿 조회의 참거짓 결과를 구별하여 즉시
분기한다. 실제 최신 완결편의448개 기체·400개 파일럿 표에서379개
지원 머리 레코드를 확인했으며, 공유 레코드1·399와 특수 슬롯302~319는
파일럿 조건에서 거부한다. 이는 파일럿379명 전체의 게임 실행 검증이라는

유지된다.

독립 분기 모델153,664개와 기존 컴파일러24개 바이트 비교, C4의32개

기존8,067바이트 슬롯에 들어갔다. 현행 에디터의 HP·배치·보상·타일을
함께 바꾼 실제 입력을 정상화하고 영수증 없는 새 검사기로 다시 열었으며,
개인 편집과 기존 불변 범위를 보존했다. NR02와 NR03은 서로 구별하고,
다른 본문의 변조와 사적 출력 자체는 영수증을 붙여도 계속 거부한다.
동결 C4 전달본 SHA-256은
`f42dc6e06582349e35fe44238288907a510d002cebab74061d45ef312f7cdf89`다.

C3의 영역 있음 표본 한 개를 저장소 밖의 독립 사본으로 실제 생성했다.
전체221,803개 raw sector와 바뀐7개 구간의 EDC/ECC, 나머지102개 압축·
해제 본문, 원본 파일 보존을 다시 확인했다. 출력 전체 SHA-256은
`ea17f48e9d31df0a94694af4d94ba0c1fc86063ab82f59d123aba526e6b8e652`다.
이는 사적 런타임 시험 자료이며 승인 릴리스·현행 UI 지원을 추가하지
않는다. 새 helper의 실제 판정·불충족·게임 저장·새 부팅과 제품

이전 helper 시험에서는 경험치 지급을 확인한 뒤 원 식민지 대사까지
정상 진행했다. 해당 원 이벤트가 바꾸는 개체 표도 관측했으며, 전체 표가
진행 내내 동일하다고 주장하지 않는다. 이 결과도 새336바이트 helper의
실제 실행이나 해당 화의 완료·게임 저장·새 부팅 증거로 확대하지 않는다.

### 현행 편집 파이프라인의 사적 NR03 연결

현행 코드67개를 동일 바이트로 복사한 별도 시험에서, 완결편c의
본문5·선택102·맵56에만 NR03을 연결했다. 영역·기체 종류·파일럿을
승리의 모두 조건으로, 진영별 수·턴을 패배의 하나라도 조건으로 넣은
6개 규칙과 우선순위가 변경 목록·원자적 JSON 불러오기·출력·기록 없는
새 검사·재편집·복원까지 유지됐다. 같은 입력의 HP·파일럿 능력치·정신기·
특수능력·배치/보상·맵 타일 편집도 보존했다. 실제 전체 파이프라인은
최종 시험 소스로 다시 실행했으며 정상 종료했다.

입력 문맥과 요청은 첫 await 전에 복사한다. 작업 중 식별 목록·수치·
getter를 바꾸는 시험과 잘못된16개 입력을 거부했고 getter는 실행하지
않았다. 목적 문구는 각각의 줄이18자를 넘을 때만 ‘승리 조건 조합’ 또는
‘패배 조건 조합’으로 요약한다. 짧은 반대쪽 문구는 유지하며 전체 규칙은
JSON과 변경 목록에 남는다.

시험 출력은14,008바이트 본문·8,029바이트 압축으로 기존8,067바이트
슬롯에 들어갔다. 실제 입력 대비 다른 바이트100,230개와 새 런타임
구간7개 섹터의 범위16,464바이트는 별도로 산정했다. BOOT·EXEC·SCEDATA
정상화 뒤에도 기존 전체 출처 검사를 반드시 수행하며 다른 본문 변조나
일치 영수증을 붙인 원시 사적 출력은 거부한다. 승인 프로필은 바꾸지
않았다. 최종 검증 묶음375개 핀의 SHA-256은
`f70adf7828dd73828d075778ee4abefe1baab31edbf7c8a4536b72a8b93fa17b`이다.

이 시험은 제품 UI의 활성화, 새 조건6개의 실제 게임 판정, 게임 저장·
새 부팅 복원이나 다른 글꼴·본문 지원의 완료 근거가 아니다.

### C3 자체 상태에서 저장 불러오기와 다음 전장 대화

C3 영역 있음 디스크(`ea17f48e9d31df0a94694af4d94ba0c1fc86063ab82f59d123aba526e6b8e652`)
의 자체 타이틀 상태에서 정상 패드 입력으로 본체 RAM의 데이터01을
선택했다. 실제 인터미션은33화 완료·총360턴·자금1,000,000을 표시했다.

진입하고, 정상 A 한 번으로 크와트로의 사이드3·스위트워터 응답을 확인했다.
각 단계는 정상 종료했으며 새 미디어 ID나 다른 이미지의 MCA를 강제로
사용하지 않았다. 처음33화 저장을 만든 이미지의 출처는 계속 미확인이다.

마지막 대화 관측은 요청205프레임·실제 종료206프레임·3.82초·4 hit다.
1프레임 종료 여유를 따로 기록했고 시간·hit 한도에는 닿지 않았다.
실제200프레임 PNG를 읽었으며 전체13944바이트 본문·336바이트 helper·

실제 승패 판정·게임 저장·새 부팅·해당 화 완료나 NR03 여섯 조건의 실행은
아직 완료하지 않았다. 마지막 실제 대화 검증 묶음 SHA-256은

### 도입 대화 뒤의 원본 분기 확인

현재 C3의 원본문에서 도입 대화 다음 D0.02는 플래그263을 검사한다.
승인 실행 코드의 해당 handler와 호출 함수들을 CPU로 실행한12사례에서
VM+37의 bit7만 참·거짓에 맞게 바뀌고 VM+20은 유지됐다. 조건 결과를
VM+20의 인원 집계로 해석하지 않는다. 다음 C4.15는 GameState+0x4D5와
+0x4D6의 일부 bit에서0~7을 계산해 원래8개 분기 중 하나를 고른다.
나머지 bit가 다른16사례에서도 같은 계산과 stack·상위 레지스터 보존을
확인했으며 해당 함수는 선택창을 여는 외부 함수를 호출하지 않았다.

현재 자기 MCA에서는 플래그263이 켜져 있고 계산값은3이었다. 이는
그 상태의 값과 원 코드 계산을 확인한 근거이며, 대화 종료 후 실제 분기나
화면을 관측한 증거는 아니다. 대화용 실행 범위를 넘어서는 추가 입력은
그 시점의 실제 화면과 실행 상태를 다시 확인해야 한다. 잘못 가정한
VM+20 boolean과 상대 분기 인수의 literal byte를 기대한 실패 기록도
별도로 보존했다. 조건부 CPU 보고서 SHA-256은
`81a65f352956f62d78ee449414bd6afa0ebddb808b3fec4864011a2ab00142d2`다.

### C3 도입 대화의32회 개별 실행

현재 C3 자체 MCA에서 매번 실제 화면을 읽고 A 한 번씩32회 실행했다.
모든 실행은 실제 종료코드0이고 시간·hit 한도에 닿지 않았다. 관측한
102 hit와 종료 상태에서 본문13944바이트·helper336·14루트·IP256·EXEC
연결·6560바이트 풀·257바이트 목록을 보존했고, 즉전 BKR와 해제 BCR도
유지했다. 자연스러운 SMPC 시각 변화는 별도로 기록했다.

마지막 실제200프레임 화면은 대사창 없는 우주·지구·함선 장면이다.
부모 반환2178과 원 대화 문맥은 유지되지만 읽을 수 있는 인물 대사가

### C3 장면 전환 뒤의 무입력 관측

위32번째 자체 상태에서 추가 버튼 없이205프레임을 관측했다. 실제 종료는
206프레임·4.02초·종료코드0이며 시간·hit 한도에 닿지 않았다. 실제1·120·
200프레임 캡처는 모두 브렉스의 ‘크와트로 대위, 부탁한다’ 대사였다.
마지막 캡처는 부모 에이전트도 직접 읽었다. 장면 전환 중 대사창이 없었던
앞 관측과, 전환을 마친 이 관측을 구분한다.

부모 반환2178과 인수80바이트는 유지됐고 본문13944바이트·helper336·
14루트·IP256·EXEC 셀·개체 풀6560바이트·목록257바이트는 입력 전과 같다.
VM80의50·51번 바이트와 자연스러운 SMPC 시각 변화는 별도 기록했다.

판정 또는 승리·저장 완료를 뜻하지 않는다. 새로 얻은 자체 MCA에서
마지막 도입 대사를 진행할 다음 단일 입력을 준비할 근거로만 사용한다.

### 완결편 마지막 원 대사의 다음 재개 주소

C3 자체 상태에서 브렉스의 원래 대사 뒤 정상 A를 한 번 입력한 별도
관측은 실제 반환 0, 4.42초, 593개 기록으로 정상 종료했다. 마지막 캡처에는
크와트로의 원래 응답이 표시됐고, 명령의 재개 주소가 2178에서 2183으로
바뀐 것을 실제 기록에서 확인했다. 원 본문·새 helper 바이트·14root·
IP·디스패치, 전체 6,560바이트 풀과 257바이트 목록은 그대로였다.

새 위치 helper와 C415 호출은 여전히 0회다. 이번에 읽힌 D002/플래그
검사 196회는 공통 대사의 플래그 10 대기 경로이며, 시나리오의 플래그
263 분기를 실행한 증거로 사용하지 않는다. 세 캡처를 작업자가 읽었고
루트 검수도 마지막 응답 캡처를 직접 확인했다. 자체 상태에서 후속 입력
없이 멈췄다.

동결 delivery SHA-256은
`61d7bc897b7a4931f53e78a8440dd32d398bb9aa913f69d5e3d07bbc313e23c6`이며,
독립 재검사는 자체 6개·코드 12개·실행 27개 핀을 통과했다. 이는 원래
대사 진행과 다음 관측의 출발점에 관한 증거이고, 위치 판정·승패·게임
저장·새 부팅이나 완결편 제품 활성화의 완료 근거는 아니다.
