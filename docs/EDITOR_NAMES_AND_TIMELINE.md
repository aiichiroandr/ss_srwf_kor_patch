# 무기 이름·세이브 이름·전투 타임라인 (2026-10-23)

2026-10-25 안전성 보강: 이름 포인터의 셀/대상 범위와 TSR 전체 RAM 크기를 검사하고, 기체 표 이설·무기명·글리프를 합친 결과를 압축 전에 다시 해체해 원래 작성 버퍼와 비교한다. 실제 v0.3a 복합 출력은 출처 재열기와 자체 맥 네이티브 원작 포인터 소비 함수 대조를 통과했다. 방법·범위는 [로컬 에디터](LOCAL_EDITOR.md)의 이설·출력 안전성 절을 따른다. 긴 세이브 애칭을 위한 새 ROM 문자열 이설은 도입하지 않았다.

## 구현 범위

- 타임라인은 ROM 에디터 **무기 탭**에만 있다. 기체 무장 슬롯에는 추가하지 않는다.
- 무기명은 무기 탭과 기체 무장 상세에서 같은 레코드의 이름을 수정한다. 같은 무기 ID를 쓰는 모든 기체에 공통 적용된다. 숫자 수치 요청과 문자열 요청은 분리한다.
- 세이브 에디터 ‘이름·자금·개조 → 이름·애칭’에서 선택한 저장 슬롯의 주인공·애인 풀네임과 애칭 네 칸을 각각 고친다. 완결편은 ‘기체 이름’에서 주인공 기체의 한 형태 또는 세 형태 이름도 편집한다. F와 완결편의 문자표를 구별한다. 입력 개선 패치의 ‘천지인 화면’을 구현한 것은 아니다. 필드별 바이트 경계와 정적 근거는 [세이브 에디터](SAVE_EDITOR.md)를 따른다.
- 빈 이름, 앞뒤 공백, 바이트 초과는 적용하지 않는다. 기존에 없는 현대 한글은 확인된 미사용 글꼴 칸에 자동 추가한다. 추가 글자만 갈무리11 기반 보조 글꼴을 사용한다. 한도·지원 범위는 [글리프 자동 추가 구현](EDITOR_GLYPH_ADDITIONS_20261023.md)을 따른다.

## 이름 저장과 출처 검증

주인공은 일반 저장 payload `[0x3c,0x4a)`, 애인은 `[0x50,0x5e)`이다. 각 14바이트 안에 FF 종료 문자까지 들어가야 한다. EB~F5 접두 문자는 2바이트다. 두 번째 바이트 FF는 문자열 종료가 아니다. 남은 공간은 FF로 채우고 기존 합산 체크섬을 다시 쓴다. 얼굴 선택, 능력, 저장 슬롯 배치, 다른 게임/저장 데이터는 건드리지 않는다.

2026-10-23 재조사: 완결편 신규 사용자 이름은 **현행 일반 글꼴**로 인코딩한다. 옛 파일럿 이름 판독표를 역으로 쓰면 ‘경’ 등이 빈 atlas 셀에 연결되는 문제가 확인됐다. 저장 이름 판독은 얼굴 선택에 대응하는 8명 기본 인물의 stock/승인 legacy 정확 일치를 먼저 한글 기본명으로 표시하고, 그 밖에는 현행 코드 우선/해독 불가 시 legacy 판독을 사용한다. 단순히 현행·legacy 중 읽히는 쪽으로 기본명을 추측하지 않는다. 기존 legacy 판독 API와 무기명 코덱은 유지한다. 실제 a/b/c atlas 대조·기본명 16종 exact match, 네이티브 바이트의 합성 메모리 144경우, 실제 56슬롯 BCR 메모리 복사본의 ‘경미나/아무로’ 출력·재열기를 확인했다. 자세한 주소와 한계는 [추가 조사](EDITOR_STORY_FONT_RESEARCH_20261023.md)에 있다.

무기명은 root14의 해당 이름 포인터만 바꾼다. 기존 문자열은 다른 ID와 공유될 수 있어 덮어쓰지 않는다. TSR 끝의 정규 확장 `SRWNAM01`에 ID, 길이, 원래 포인터 차이, 새 문자열을 ID순으로 기록한다. 끝의 16바이트는 식별자·기존 TSR 길이·개수다. 한 이름은 종료 포함 32바이트, 최대 1,408개이며, 추가 영역의 출력 한도는 `editor-storage-safety.mjs`를 따른다. 완결편은 메뉴 작업 영역 0x0028d800보다 아래여야 하며, F는 별도 배치에 대한 기존 한도 0x002b1800을 유지한다. 압축 TSR의 기존 디스크 할당 검사도 계속 적용한다. 게임 내 모든 이름 표시 창의 최대 글자 폭을 검증했다는 뜻은 아니다.

재열기는 확장 전체의 길이·정렬 순서·중복·문자표·포인터·종료 문자를 검사하고, 확장을 제거하고 원래 이름 포인터를 복원한 뒤 **기존 immutable TSR/disc 해시 검사**를 한다. 이름 편집을 이유로 새 writable hash mask를 허용하지 않는다. 복원되는 원래 포인터가 조작되면 기존 해시가 거부한다. 정상 정규 확장만 UI 이름으로 반영한다. 일반 수치 수정·무장 추가·기체 구성 때도 이름 확장은 마지막에 다시 쓰며, 재열기 후 이름은 유지한다. 원래 이름으로 되돌리면 해당 확장은 제거된다. 압축 방식/ISO 길이/남은 압축 데이터 정리 때문에 복원한 전체 BIN의 해시가 최초 승인 BIN과 같을 필요는 없다.

## 보기 전용 타임라인

`srwf-recomp/tools/weapon-preview.cpp`의 실제 스크립트 디스패처(F 0x0604416c, 완결편 0x06049940)를 탭한다. 두 디스패처의 명령 포인터 literal은 F 0x060c0900, 완결편 0x060c6d70이다. 픽셀 변화에서 opcode 시점을 추정하지 않는다. VDP1의 실제 draw command 제출도 읽기 전용으로 수집한다. ROM 실행 명령이나 무기 연출을 수정하는 편집 기능은 없다.

화면 영역은 320×224 기준 대사 `[58,172,251,44]`, 초상화 `[7,172,48,44]`, HUD `[0,0,320,30]`이며 실제 출력 크기로 비례 변환한다. 워커의 네이티브 프레임과 같은 frame의 영상에 결합한다. 영역 창의 출현/소멸도 픽셀 변화다. **화면 변화 구간을 특정 대사·감정·명중·폭발로 단정하지 않는다.** 대사와 얼굴 구간을 누르면 이미 메모리에 기록한 JPEG의 해당 영역만 잘라 보여준다. 가장 가까운 표본과 선택 프레임의 차이는 툴팁에 표시한다. HP 0 트랙은 상태값의 전이이며 파괴 이펙트 트랙으로 표시하지 않는다.

상태 근거는 기존 읽기 전용 hook 그대로다. F `0x060C0640`, 완결편 `0x060C6AB0`부터 두 전투 측이 32바이트 간격이며 얼굴 ID `+0x08`, HP `+0x0E`, EN `+0x12`를 읽는다. VDP1 자료는 draw의 실제 제출 명령이며 CTRL 하위 4비트 0·1·2인 스프라이트만 모션 요약에 사용한다. 슬롯이 사라졌다가 재사용되면 이전 모션에 연결하지 않는다. 원본 디스패치 표도 확인했으나 미해석 opcode에 의미를 추정해 붙이지 않는다.

문자열 hook는 F `0x06016688`, 완결편 `0x06016B1C`의 원본 text queue이다. 완결편 D_ANIME `0x1A` 처리 `0x06046A78`은 `0x06046C92`에서 해당 queue를 호출한다. mode 0의 r5 문자열만 관측하고 동일 원본 함수를 그대로 호출한다. 원본 copier처럼 EB~F5를 2바이트로 소비하며 두 번째 FF도 글자의 일부로 보존한다. 경계 FF만 종료다. F6~FE는 SCEDATA 입력 문법으로 재해석하지 않고 원래 queue 바이트 그대로 `⟦F6⟧`처럼 표시한다. 따라서 이미 원본에서 치환한 이름·수치를 다시 변환하지 않는다. 현재 문자표에 없는 코드는 16진 토큰으로 남긴다. 주소·호출자·요청 프레임을 이벤트 상세에서 확인할 수 있다. 요청마다 증가하는 sequence를 사용하고 재생마다 초기화하므로 프레임 메시지가 반복되어도 대사를 중복 추가하지 않는다. 요청은 한 재생 256개·한 문자열 512바이트까지다. 읽기는 두 work RAM 범위로 제한하며 실행 RAM을 수정하지 않는다.

실제 battle message 호출자 F `0x0601752C`, 완결편 `0x060179C0`의 문자열은 파일럿 약칭·F6·본문이다. 이 호출자에 한해서 F6 앞의 이름은 파일럿 문자표, 본문은 현행 문자표를 우선한다. 현행표에 없는 기존 문장부호는 파일럿 표에서 보충하며 사용자가 추가한 글리프가 우선한다. 다른 호출자는 F6만으로 파일럿 이름이라고 추정하지 않는다. 현재 네이티브 전송은 매 출력 프레임의 신규 요청만 보내고 batch를 즉시 비우므로 256개 누적 본문을 매번 재전송하지 않는다.

한 화면에서 기술 기록 펼치기/접기, 가로 1·2·4배 확대, 기록 프레임 검토, 이전·다음 관측 이벤트 선택, 실시간 커서 복귀가 가능하다. 표본은 타임라인 내부에서 닫을 수 있으며 실제 전투 미리보기의 높이를 변경하지 않는다. 검토 슬라이더와 이벤트 선택은 게임 재생을 임의 시점으로 되감지 않는다.

상한은 이벤트 12,000개, 한 draw 512개 슬롯, 화면 JPEG 표본 96개다. 원자료와 고빈도 스프라이트 모션은 마지막 256칸을 남겨 이후 HP·EN·얼굴 상태를 기록할 공간을 보존한다. 프레임 원본 전체나 동영상을 디스크에 쌓지 않고 현재 브라우저 메모리에만 둔다. 다시 재생하면 새 기록으로 교체하며 무기 선택 시 이전 무기의 기록은 비운다. 미리보기는 여전히 기본 OFF이며 무기 탭에만 타임라인을 연결한다.

## 타임라인 부하와 데스크톱 배치 보완 (2026-10-25)

재생 중 약 180ms마다 트랙 전체를 새 DOM으로 만들었고, 그 변경을 상위
레이아웃 감시자가 받아 모든 필드의 크기와 페이지 구성을 다시 계산했다.
플레이어는 화면 표본을 동기 JPEG/base64로 만들었으며, 표본 검토창을 닫아도
디코딩했다. 캔버스의 동일한 크기를 매 프레임 다시 지정하는 작업도 있었다.

트랙·이벤트 DOM을 재사용하며, 타임라인 내부 기록 갱신은 페이지 재배치에서
제외한다. 실제 창 크기·플레이어 ON/OFF·편집 필드 변경은 계속 재배치한다.
표본은 한 번에 하나씩 비동기 JPEG Blob으로 만들고, 표본 검토창을 열 때만
디코딩한다. 캔버스 크기는 달라졌을 때만 바꾼다. 중간 프레임의 대사·얼굴·HP
상태가 단일 대기 슬롯에서 덮어써지지 않도록 순서대로 전달하고 종료 전에 비운다.

900px 이상 데스크톱은 실제 편집 공간의 폭으로 배치를 정한다. 넓은 창은 수치를
상단 띠로 모아 큰 플레이어와 타임라인을 나란히 놓는다. 중간 창은 왼쪽에
수치·지형·사용 기체, 오른쪽에 플레이어와 타임라인을 둔다. OFF에서는 플레이어
공간을 회수해 편집 항목과 타임라인을 펼친다. 모바일의 측정 기반 페이지 구성은 유지한다.

변경 전후 실제 모듈에 같은 3초 합성 수집 부하(724프레임, 이벤트 2,967개)를
주었을 때 메뉴 DOM 변경은 34회→0회, 새 DOM 노드는 1,134개→235개였다.
이 조건에서 양쪽 모두 32ms 초과 RAF 간격은 없었으므로 이 수치를 실제 게임의
FPS 개선률로 해석하지 않는다. 위 합성 측정에서는 게임·ROM·네이티브 런타임을 실행하거나 빌드하지 않았다.
화면 폭 900/1024/1280/1440/1920px에서 ON/OFF 배치를 확인했고, 430px에서
모바일 배치 복귀를 확인했다. 실제 재생 성능의 최종 확인은 별도다.

### 실제 ROM 후속 확인 (2026-10-25)

완결편 v0.3a의 기존 공개 패치 해시를 페이지에서 검증한 뒤, 건담 #1·아무로
#10·빔라이플 #2·배경 #56·시드 251025의 실제 웹포트 재생을 비교했다.
이전 타임라인·레이아웃·CSS와 현재 UI를 **같은 현행 플레이어·네이티브
런타임**으로 실행했으며, 양쪽 모두 백그라운드 브라우저 녹화를 켰다.
완전한 이전 버전 전체나 동기 JPEG 제거 전 플레이어와의 비교는 아니다.

1920×1080의 단일 비교에서 원본 프레임 452~757의 같은 306개 화면 갱신을
관측했다. 메뉴 DOM 변경은 76→0회, 새 타임라인 DOM은 3,181→551개,
캔버스 갱신 간격 p95는 74.18→35.29ms, 50ms 초과 갱신은 36→1회였다.
녹화 파일은 25fps이므로 60Hz 계측값 자체를 그대로 보여 주는 영상은 아니다.
모든 무기와 기기의 성능 보장으로 확대하지 않는다.

실제 페이지의 외곽 1440px 제한과 상·하단 조작부 높이도 배치에 반영했다.
넓은 창에서는 바깥 여백을 줄이고, 가용 높이가 짧은 데스크톱에서는
편집 항목·플레이어·타임라인을 세 열로 놓는다. 좁아진 목록에서는 이름을
수치와 분리해 한 글자씩 세로로 밀리는 현상을 방지한다. 도감 설정은 상단
드롭다운, 저장 조작부는 데스크톱의 한 행으로 정리했다.

1920×1080과 1280×800 각각 실제 재생 → OFF → ON → 종료를 녹화했다.
OFF에서 같은 프레임이 유지되고 ON에서 같은 iframe으로 재개됐으며,
세 상태 모두 입력칸이 패널 안에 보이고 전체 폼이 넘치지 않았다.
네이티브 로그는 `0 program starts`였으며 콜드부트나 네이티브 재빌드는
실행하지 않았다. UI 회귀 검사는 119건 통과·1건 생략이었다.
로컬 근거는 `build/timeline-qa/real-rom-final/report.json`,
영상은 같은 폴더의 `after-wide.mp4`, `after-medium.mp4`이다.

### 실시간 트랙 그리기 보완 (2026-10-25)

수집 종료 프레임에 맞춰 전체 너비를 매번 재계산하던 방식을 고쳤다. 실시간은 프레임당 픽셀 배율을 고정하고 기록이 길어지면 가로 영역을 확장한다. 커서는 실제 수신 프레임으로 이동하며 끝을 따라간다. 수동 가로 스크롤·기록 선택은 추적을 해제하고, `실시간`으로 복귀한다. `기록 전체`는 선택 당시 범위를 맞추며 이후 패킷이 과거 막대를 다시 축소하지 않는다.

한 번 관측한 변화는 마름모, 관측된 지속 구간은 막대로 구분한다. 얼굴 ID·배경은 다음 상태 변경 또는 마지막 관측 프레임까지 유지한다. 공격/방어 얼굴·피해·HP 트랙은 위아래로 분리한다. 대사·음성의 미확인 지속 시간이나 HP 0 이후 폭발 시간을 만들어 넣지 않는다. 이 변경은 보기 전용이며 ROM이나 원자료를 고치지 않는다.

위와 같은 실제 ROM·무기·시드의 백그라운드 웹포트 한 번에서 고정 배율 상태의 기존 막대 위치 3,081회 비교 중 이동 0회, 실제 커서 전진 49회를 관측했다. 원본 프레임 452~757의 306개 화면 갱신에서 50ms 초과 갱신 간격은 0회였다. 모든 무기의 성능을 보증하는 수치는 아니다. DOM/상태/배율 회귀 17건은 실제 백그라운드 브라우저 항목까지 통과했다. 근거와 짧은 영상은 `build/timeline-drawing-qa/actual/`에 둔다. 녹화는 25fps이며 콜드부트·네이티브 재빌드는 실행하지 않았다.

## 없는 글자 자동 추가 구현 (2026-10-23)

아래는 최초 설계 기록이다. 현재 대사·무기명·주인공/애인 이름 입력, 추가 글리프 배정, 변경 목록·JSON·BIN 저장/재열기를 연결했다. 최신 동작과 검증 범위는 [구현 문서](EDITOR_GLYPH_ADDITIONS_20261023.md)와 [로컬 에디터](LOCAL_EDITOR.md)의 시나리오 대사 항목을 따른다.

사용자가 입력한 글자만 추가하는 방향은 타당하다. 다만 ‘비어 보이는 비트맵’만으로 사용하지 않는 문자 코드를 결정하면 안 된다. F의 일반 글꼴, 완결편 현행 글꼴, 구세이브 legacy 이름 판독표를 구별해야 한다. 글꼴 변형 a/b/c의 렌더링과 기존 가나/제어 코드도 보존해야 한다.

권장 순서는 다음과 같다.

1. 검증한 ROM의 게임·폰트 계열과 실제 글리프 뱅크, 참조 코드를 고정한다. 기존 참조에 안 쓰이고 게임의 lookup 경로가 받아들이는 예약 풀을 주소·길이·해시로 확정한다. 현재 문자표에서 빠진 코드의 개수는 안전한 빈 칸 수가 아니다.
2. 입력 문자열을 NFC로 정규화하고 **기존 글리프에 없는 글자만** 중복 제거한다. 예약 풀 잔여량 안에서만 할당하고 입력 순서에 따라 기존 코드 배정이 바뀌지 않게 한다.
3. 선택한 a/b/c 글꼴 원본에서 같은 크기/비트 깊이의 비트맵을 만든다. 이름용과 본문용의 lookup/캐시가 다르면 필요한 뱅크와 테이블을 함께 고친다. 브라우저에 우연히 설치된 폰트로 래스터화하면 환경마다 출력이 달라지므로 재현 가능한 same-origin 글꼴 소스가 필요하다.
4. 개인 수정 BIN과 ‘Unicode↔할당 코드·글꼴 계열·예약 풀 버전’ manifest를 함께 출력한다. 재열기·프리셋·웹포트에서도 같은 mapping을 복구한다. 기존 glyph/코드의 교체나 출처 검사 범위 전체 해제는 허용하지 않는다.
5. **BCR에는 게임 글꼴이 없다.** 세이브만 바꾸어 없는 글자를 추가할 수 없다. 먼저 해당 글리프가 포함된 개인 수정 ROM을 만들고, 그 ROM을 검증한 세이브 에디터에서만 대응 코드를 쓴다. 다른 ROM으로 열면 깨질 수 있으므로 세이브와 연결한 글꼴 manifest를 확인한다.

이 작업은 현재의 문자표 기반 이름 편집과 분리해 진행한다. 천지인 입력 개선은 사용자 요청으로 범위에서 제외한다.


## 확인 결과

- 이름 codec/세이브/무기명 쓰기·출처 재열기·프리셋·인라인 편집·타임라인 모델·기존 미리보기 등 관련 Node 검사 91건 통과.
- 실제 완결편 v0.3a를 메모리에서 무기명 수정 BIN으로 만들고, 새 세션에서 전체 해시·bounded provenance를 다시 통과해 수정 이름을 확인했다. 원본 파일을 덮어쓰거나 전체 BIN을 저장소에 남기지 않았다.
- 다운로드 폴더의 실제 56슬롯 완결편 BCR을 메모리 복사본에서 주인공·애인 이름 수정 후 재열어 체크섬/이름을 확인했다. 실제 파일은 교체하지 않았다.
- 실제 완결편 웹포트의 공격 한 번에서 프레임 기반 이벤트가 수집되고 종료되는 것을 확인했다. 기체 슬롯의 이름은 공통 레코드와 연동되며 타임라인은 무기 탭에만 있다.
- 대사 queue 후속 구현은 실제 F v0.5c·완결편 v0.3a 웹포트 공격 한 번씩을 추가 확인했다. 각 2개 문자열을 신규 batch 2회로 받았으며 sequence 중복 0·오류 0·종료 code 0이었다. 완결편은 legacy 이름과 현행 본문을 구별한 뒤 실제 타임라인 UI에서 ‘아무로’·‘인공지능’과 한글 본문을 확인했다. 현재 glyph map 변경·EBFF 글자 경계·호출자 구별·재생 초기화 회귀검사를 추가했다. 실제 에뮬레이터 진행·세이브 로드는 실행하지 않았다.
- 실행 파일·소스 아카이브는 게임별 현행 한 벌씩만 보존한다. 총 약 88 MiB이며 이전 미리보기 빌드 사본은 제거했다.
