# 좌표 기체 습득의 callback·저장 계약 확인

2026-10-23. 기존 지역 조회와 보유 기체 생성 명령을 묶은 독립34바이트
프로그램은 생성 전에는 pending, 성공 후에는 done 경로에서 E9로 반환한다.
이 문서는 그 프로그램을 설치할 실제 callback의 계약을 좁혀 확인한 기록이며
새 writer 권한이나 게임 실행 완료의 근거가 아니다.

## E9와 기존 저장 증거

승인 F v0.5-c 이미지 SHA-256은
`75555116f784115e7104c593fd990491ae182b9493d9f159201e17b3e3d88202`다.
이 이미지에서 읽은 EXEC `0`의 SHA-256
`308fe51501cd70091fe1a9983101d6cd98b9fdc7d8857e4bac9e2bff3e9974f1`와
TSR root0의 SHA-256
`b7175cfbe8e0dfef455cf8bf9eebd8798cf21fbffe9a0af08b78c340f3244c06`은
[기존 callback 조사](EDITOR_PHASE_CALLBACK_RESEARCH.md)의 승인 입력과 같다.
따라서 이미 확인한 native 재개 계약을 재사용하며 콜드부트를 반복하지 않았다.

F E9 `0601E37C`는 helper `0601F444`에 r4=0을 넘긴다. 디스패처가
E9 opcode를 소비한 상태이므로 helper는 E9 바로 뒤 주소를 전역
RESUME[0]에 쓰고 VM 반환 깊이를1 줄여 부모로 복귀한다. 따라서 독립
프로그램의 E9 뒤 JMP가 재개점이 되는 것은 맞다. FFF1/FFF2/FFF3는 이
전역 재개점을 game state +0x524/+0x528/+0x52C에 각각 저장한다.

[기존 F 실행 기록](EDITOR_SCENARIO_F_RUNTIME_PROGRESS.md)의 root5 once
실험에서는 pending과 done이 서로 다른 PC로 +0x528에 저장됐고 실제 게임
저장·새 부팅·이어하기 후에도 완료 PC와 미생성이 유지됐다. 이는 같은 후보와
확인한 root5 경로의 증거다. 임의의 callback이나 재편집한 다른 BIN에 같은
보존을 자동 부여하는 근거가 아니다. root4는 맵 준비와 새 아군 턴, root5는
적군 시작에서 재개되므로 이동완료 직후의 전용 사건으로 부르지 않는다.

## root8은 일반 재개 호출 전에 다시 선택되는 경로가 있다

좌표는 아래에서 모두 압축 해제 TSR root0 세그먼트 상대 오프셋이다.
현재 승인 F의 원래 공통 wrapper는 다음 순서다.

| 위치 | 원래 명령 | 확인한 효과 |
|---|---|---|
| 4CEB | 1D00 | 원래 선행 명령. 이 문서는 게임 효과를 새로 명명하지 않는다. |
| 4CED | E8 FF08 | 현재 SCEDATA의 root8 **시작**을 RESUME[0]으로 선택한다. |
| 4CF0 | E8 FFF3 | 선택한 시작을 GS+0x52C에 다시 저장한다. |
| 4CF3 | E8 FFFE | 이 +0x52C를 호출한다. |
| 4CF6 | ECFF | 원래 결과 전달을 유지한다. |
| 4CF8 | 04 | 부모로 복귀한다. |

E8의 FF08 경로는 F `0601E2F8..0601E346`의 일반 root 선택 경로이며,
FFF3의 저장과 FFFE의 호출은 각각 `0601E1A2..1AE`,
`0601E258..276`이다. 기존 +0x52C 값이 게임 저장에 남는다는 사실과,
다음 objective 호출에서 이 값이 다시 root 시작으로 덮인다는 사실은 구별해야
한다. **root8을 pending/done 두 사본으로 만드는 것만으로는 완료 PC를
다음 호출까지 유지하는 once 구현이 되지 않는다.** 기존 목적 검사를 단순
대기 루프로 교체하는 것도 원래 승패 판정을 차단하므로 허용하지 않는다.

원시 상대 참조의 부정 전용 목록에는 이 wrapper를 가리키는 직접0A 후보가
root0+652/6B7/6E6/70B/727/755/77D/79D/7C3/7E8/938/955/972/995에 있다.
이 목록은 각 분기가 이동확정·공격완료·취소 중 어느 사용자 행동에서 실행되는지
증명하지 않으며 쓰기 위치를 부여하지 않는다. 모든 호출자 의미와 도달 경계를
새로 닫은 것으로 표시하지 않는다.

## 이번 확인으로 남은 최소 계약

독립34바이트 프로그램의 pending/done 재개 동작과 실제 host의 수명은 별도다.
이동 뒤 지급을 연결하려면 원래 이동·행동 후 호출 경계를 먼저 인증하고,
root8 재선택에도 유지되는 명시적 완료 상태 또는 다른 독립 저장 수단을 확인해야
한다. 비어 보이는 story flag나 root7을 추측해 사용하지 않는다. 원래 목적·사건의
분기와 결과 전달, 게임 저장 및 기존 세이브에서 불러온 상태도 보존해야 한다.

이번 작업에서는 생산 compiler·metadata·출처 허용 범위를 바꾸지 않았고,
전체 BIN 생성·실행·추가 저장 검사를 하지 않았다. 주소·해시·좁힌 논리만
문서에 남기며 게임 파일과 추출 코드는 저장소에 포함하지 않는다.
