# 무기 연출 미리보기 (로컬)

검증한 F v0.5 또는 F 완결편 v0.3 a/b/c ROM으로 롬에딧을 연 뒤, 무기 탭의
‘미리보기 OFF’를 ON으로 바꾸면 무기 상세 화면 안에서 자동 재생한다.
기본은 OFF이며 별도 창·대화상자·추가 진입 단계는 없다. 사용 기체와
파일럿도 그 자리에서 바꾼다. 무기 선택이 바뀌면 해당 연출로 다시 실행한다.
조건부·미연결 무기도 에디터의 전체 목록에서 선택한다. OFF·탭 변경은
미리보기를 숨기고 실행·소리를 일시정지한다. 같은 선택으로 다시 ON이면
기존 실행을 이어가며 ROM을 다시 읽거나 전투를 초기화하지 않는다.
재생이 끝난 경우에는 결과 화면을 다시 보여 준다. 같은 선택의 재생 버튼·자동 반복은 완성한 전투 기록을 재사용한다.
무기를 바꿀 때 배경을 새로 고르고, 기체·파일럿만 바꾸면 같은 배경 선택값으로 새 전투를 준비한다. 편집 세션 종료·ROM 변경은
워커를 폐기한다. 소리는 처음에 꺼져 있다.

개인 편집본도 기존 검증기가 위 최신 패치 계열로 식별한 경우에만
허용한다. 미리보기는 불러온
ROM과 현재 편집값을 기준으로 한다. 변경값이 있으면 기존 출력 검증·쓰기 경로로
브라우저 메모리 안에 시연용 편집본을 준비한다. 디스크 파일을 만들지는 않는다.
같은 세션·같은 변경 요청은 다시 만들지 않으며, 편집값이 바뀌면 새로 준비한다.
미리보기를 켠 채 수치를 입력하는 동안에는 현재 전투를 재시작하지 않는다.
재생 버튼·선택 변경에 따른 새 재생·정상 반복 재생 직전에 부모 에디터의
편집 버전을 확인하고, 달라졌을 때만 기존 출력 검증 경로에서 최신 편집본을
다시 받는다. 변경이 없으면 ROM 재압축·해시 검사를 반복하지 않는다.
같은 iframe 안에서 소스와 선택 목록만 갱신하며 사용자가 고른 기체·파일럿,
소리·반복 설정과 숨김 상태를 유지한다. OFF/ON은 기존 전투를 숨기고 이어가며,
입력한 새 수치는 다음 재생 또는 반복 경계에서 새로 준비해 반영한다. 변경이 없는 자동 반복은 소스 확인·원작 자원 로딩을 반복하지 않는다. 준비 중 다시 편집하면 낡은 결과를
실행하지 않고 제한된 횟수 안에서 최신 버전을 다시 확인한다. 정지·더 최근 재생·세션 종료는
이전 준비 결과를 폐기한다. 이 전달은 브라우저 메모리에서만 이루어지며
JSON/BIN의 편집 형식이나 음악·피해 계산 조건을 바꾸지 않는다.
기체 추가·무기 복제 후에는 선택 메시지에 현재 목록과 편집 버전을 함께 전달해,
켜 둔 iframe의 목록을 자동으로 갱신한다. 미리보기를 껐다 켤 필요 없이 새 기체·무기를
선택하며, 재생 직전 최신 편집본을 확인한다. 초기 ROM 연결 중 추가한 기체도 더 최신인
목록을 유지하고, 빠른 연속 선택은 이전 준비를 취소한다.
한 번의 화면 갱신에서 발생한 선택 메시지는 마지막 선택·편집 버전으로 합쳐 보낸다.
기체·무기 추가/취소로 목록만 바뀐 다른 미리보기에는 선택을 바꾸지 않고 목록을 전달한다.
현재 기체가 바뀌거나 무장을 삭제하면 그 기체에 남아 있는 무장만 선택하며, 등록된 무장이
없으면 이전 화면·재생을 지우고 무장 선택을 기다린다. 취소된 복제 무기는 같은 번호가
빈 레코드로 남더라도 복제 원본 번호를 비교해 재생을 중단한다. 무기 검색 조건과 직접 고른 파일럿,
반복·소리 설정은 목록 갱신만으로 초기화하지 않는다. 에디터에서 검색 밖의 다른 무기를
명시적으로 선택했을 때는 검색을 해제해 그 무기를 보여 준다. 내용이 같은 드롭다운은
다시 만들지 않으며, OFF 상태에서 고른 새 무장은 다음 ON에서 최신 편집본으로 재생한다.
추가 직후의 미사용 기체도 같은 기체 ID로 선택한다. 선택 기체가 전달되지 않았을 때
다른 기체로 대신 재생하지 않는다.

## 실행 경로

### 전투맵 MAP 미리보기 (2026-10-26)

MAP 공격과 수리·보급을 구분한다. MAP 무기를 고르고 재생하면 내부에서
시연용 전투맵 상태를 자동 생성한다. 사용자 세이브를 받거나 번들하지 않는다.
맵 그림과 연출은 불러온 ROM에서 읽고, 새로 만든 빈 상태에 선택 기체·파일럿과
표적 세 기만 배치한다. 미리보기 RAM에서 무장을 한 개로 제한하고
잔탄·EN·기력·습득 조건을 해제한다. 원본 ROM과 사용자 저장은 쓰지 않는다.

F와 완결편 모두 원작의 범위 표시·조준·맵 위 발사를 실행한다. 선택한 무기의
사거리 안에 시연 표적을 배치하며, 이동형 공격의 착지 칸은 비워 둔다.
이데온의 게이지 조건도 시연 복사본에서만 충족한다. 파일럿 ID가 원래 편성에
이미 있으면 복사본에서 교환해 다른 기체를 잘못 선택하지 않도록 한다.
시연 상태의 맵 오브젝트 74칸을 구성하며, 그 뒤의 맵 상태는 배치로 읽지 않는다.
게임의 실제 범위 표시와 발사 반환점을 관찰해 입력과 종료를 제어하며,
개별 표적의 피해·격추 대사 처리 전에 기록을 끝낸다. 전체 맵을
보여 주며 전투 HUD 전용 크롭을 적용하지 않는다. 완성한 화면·오디오 기록을
반복 재생하고, OFF/ON은 같은 iframe을 재사용한다. 배포용 실행 모듈을 바꾸지
않고 기존 런타임의 제한된 RAM 쓰기·진단 출력을 사용한다.

이전 사용자 저장 기반 검증에서는 실제 F v0.5a·완결편 v0.3c ROM의 MAP 유형을 분류해 각 유형의
대표 무기를 실행했다. F 30종·완결편 45종, 총 75개 게임/유형 조합의 발사와
반환을 네이티브·백그라운드 웹에서 확인했다. 공격력 0인 완결편 전탄 발사도
포함한다. MAP 표 전체 114행의 실행 계획도 점검해 공격용 113행의 시연
복사본 생성을 확인했다. 공격 연출이 없는 내부 파워업 항목(type 0)은
오류로 안내한다.
이는 모든 무기·기체·파일럿·중단 저장·개인 수정본의 조합을 검증했다는 뜻이
아니며, 미리보기 결과로 실제 게임 진행 안전성을 판단하지 않는다.

사용자 저장 요구를 제거한 후에도 같은 75개 유형을 실제 ROM과 백그라운드
웹포트에서 다시 실행해 발사 반환까지 확인했다. 자동 상태의 기본 버튼 설정과
표적의 적군·행동 플래그를 생성하며, 아군 제외형 1·2도 이를 반영해 재확인했다.
완결편 에디터의 1440/1100/390 폭에서 저장 선택 없이 재생·반복·ON/OFF,
동일 iframe 유지, 가로 넘침 없음과 MAP 타임라인 숨김을 확인했다.
이는 저장을 포함한 배포가 아니다. 숫자 필드로 매번 새 상태를 생성하며
게임 그림·맵·무기 연출은 사용자가 불러온 ROM에서만 읽는다.

F 빅뱅 웨이브(type 5)·전방위 미사일(type 21)은 원본과 한글패치의 그래픽
명령을 대조해 확인한 작은 명령 치환을 미리보기 RAM에서만 되돌린다.
대사와 그래픽의 명령표 차이로 인한 잘못된 분기·종료 문제를 피하며, 확인한
원본/패치 바이트와 다른 구조는 거부한다. 사용자의 ROM은 수정하지 않는다.
부모 에디터에서도 F·완결편 각각 1440·1100·390px에서 ON/OFF, 동일 iframe
재사용, MAP에 불필요한 전투 타임라인 숨김과 가로 넘침 없음을 확인했다.

MAP 동승자 조사에서는 원본 MAP 대사 선택표(각 BMESS 레코드의 첫 6바이트 표)를
기준으로 F 44개·완결편 70개 레코드를 대조했다. 비공격 내부 항목 하나를 제외한
공격은 113개다. 일반 전투의 둘째 표와는 일부 파일럿의 발사 대사가 달라,
에디터의 MAP 대사 후보·가져오기 예문도 첫 표를 표시한다.

일반 MAP 공격은 원작의 맵 위 연출·음성을 기준으로 하며 별도 대사 팝업을
추가하지 않는다. 이데온 일부 분기의 대형 컷인은 원본 명령으로 재생한다.
시연용 연결은 코스모/이데온에 카샤·기제, 다바에 리리스, 쇼우에 참을
포함한다. 쇼우는 원래 MAP 소유 무기가 없어 추가 장착한 경우의 조건이다.
원본의 무작위 분기를 유지하므로 동승자 음성·특수 컷인이 매번 나오지는 않는다.

완결편은 백그라운드 웹포트에서 소드·건·버스터런처·쇼우 추가 MAP의 동승 조건을
각각 연결 유무로 비교했다. 사적 검사에서만 무작위 자식 포인터를 같은 길이로
고정하고 조건 명령은 유지했다. 기제·카샤의 대형 컷인과 해당 음성 호출,
리리스·참의 음성 호출 및 실제 PCM 기록을 확인했다. 이 분기 고정은 제품·출력
ROM에 적용하지 않는다. 모든 무기의 모든 음성을 청취 검수한 결과는 아니다.
F 원본과 한글패치의 MAP 스크립트 영역에는 대사 준비·소비 명령 호출이 없고,
완결편에는 그 호출이 있다. F의 MAP 음성 미호출을 미리보기 오류로 간주해
새 호출을 넣지는 않는다.

기존 saturn-recomp의 게임 코드·Canvas2D·WebAudio 호스트를 재사용한다.
PixiJS로 애니메이션을 다시 구현하지 않았다. 원래 데모 스크립트가
일회용 전투 상태를 초기화한 뒤, 원래 자원 로더가 읽기 전에 공격자의
무기·기체·파일럿을 지정한다. 상대는 원래 시연 상대를 사용하며, 피해는 아래 조건의
비교용 추정값이다. 배경은 아래 규칙으로 고른다. 실전의 모든 전투 보정이나
플레이 가능성을 검증하는 기능이 아니다.

웹 미리보기 빌드의 장치 폴링 진단은 매번 호스트의 호출 스택을 만들지 않고
게임의 PR 레지스터를 4,096개 고정 크기 기록에 보관한다. 오류 보고에도
이 값이 게스트 반환 주소임을 명시한다. 가상 시간·장치 갱신·인터럽트와
원래 네이티브 빌드의 진단 방식은 바꾸지 않는다. WORKERFS 디스크 읽기는
256 KiB 단위로 재사용하며 상한 8 MiB를 넘으면 오래된 블록을 버린다.
파일의 원래 끝·오프셋·바이트를 보존하고, ROM 전체를 RAM에 복제하거나
브라우저 저장소에 남기지 않는다. 디스크 캐시는 워커 종료 때, 반복 재생용
전투 기록은 선택 변경·세션 종료 때 폐기한다. 표시 중인 재생 상태가 같으면 상태 문구를 다시 쓰지 않고,
화면 크기 변경과 ResizeObserver에서만 크롭 치수를 재계산한다. 타임라인의
재생 커서는 레이아웃 값을 먼저 읽고 이동해 매 프레임의 강제 레이아웃을 줄인다.

### 재생마다 배경 선택

현재 런타임 버전과 실행 파일·대응 소스 해시는
`weapon-preview/runtime/f-current.json`과 `current.json`에 기록한다.

무기 선택이 바뀔 때 브라우저가 새 난수를 준비한다. 같은 무기의 재계산은 난수와 이전 배경 제외값을 함께 재사용한다. 실행 어댑터는 현재 ROM의
무기 +11 지형 값과 BTSR 배경 정보표를 읽어 후보를 고른다. 지상·수중·우주
적응 값이 0인 무기는 해당 환경을 제외한다. 공중 배경은 기체의 기본 비행
능력과 관계없이 허용한다. 기체 능력치나 장착 파츠를 바꾸지는 않는다.
허용된 환경을 먼저 고른 뒤 그 환경 안에서 배경을 골라 지상 배경 수가
많다는 이유로 지상만 주로 나오지 않도록 한다. 후보가 둘 이상이면 직전
배경은 제외한다. OFF/ON은 현재 실행을 숨기고 재개하므로 배경을 유지한다.

BTSR는 실행 파일의 `0600449C` 함수가 읽는 **표 시작 기준 상대 포인터**다.
일반 TSR의 셀 기준 상대 포인터와 구분한다. 다음 세그먼트 전까지만
2바이트 배경 정보를 읽는다. 두 작품의 유효 정보는 190개이며 BBACK의
192개 슬롯 중 정보표 밖 두 칸은 후보에 넣지 않는다.
초기·현재 전투 상태의 양쪽 배경 번호를 함께 적용하고, 원래 BBACK 로더가
요청하기 직전에 다시 맞춘다. 원본 ROM·세이브에 쓰지 않는다.

배경 선택 함수의 327,680개 난수·무기 적응·직전 배경 조합에서 환경 제외,
직전 배경 반복 방지, 후보 하나일 때의 유지와 난수 0 처리를 확인했다.
두 게임의 어댑터 회귀 검사는 배경 번호 경계·양쪽 일치·비행 불가 기체의
공중 허용과 기존 공격 종료·반격 생략 동작을 함께 확인했다.
완결편 v0.3a 웹 실행에서는 빔사벨 #1 / 건담 #1 / 아무로 #10으로
수중 #76, 공중 #0, 우주 #46, 지상 #130 배경과 각각 첫 공격 뒤 정상
종료를 확인했다. 바다 적응 0인 빔라이플 #2는 수중 대신 지상 #91을
선택하고 745프레임에 정상 종료했다. F v0.5a에서도 수중 #76과 공중 #0의
빔사벨이 각각 1100프레임에 정상 종료했다. F의 바다 적응 0인 빔라이플도
지상 #159를 선택하고 806프레임에 정상
종료했다. 실제 플레이어의 새 재생은
배경 #189에서 #5로 바뀌었고, 그 사이 OFF/ON에서는 READY 로그가
추가되지 않았다. 전체 배경·무기 조합의 완주 검사는 아니다.

F는 원래 최초 스크립트 선택 함수 `06004BDC`가 TSR 압축 해제 후 호출될 때
인수만 `(0,0)`에서 `(3,23)`으로 바꾼다. 원래의 별도 시연 스크립트
`0022EABD`를 선택하며 헤더 CRC와 포인터 경계를 검사한다. 설치기와
전투 자원 초기화는 원래 코드를 실행한다. 주인공 생성·첫 시나리오 진행은
거치지 않는다. 일반 전투용 `(0,5)`는 플레이 상태에 의존하므로 쓰지 않는다.

F 시연 스크립트의 `47` 명령은 전투 초기화 `0603F480`, `4D`는 시연 표
준비 `06043EAC`, `4F`는 얼굴·대사 준비 `06043F64`로 이어진다.
마지막 함수 진입 전에 공격자를 지정한다. 선택한 D_ANIME 스크립트 진입까지
준비 화면을 숨기고 빠르게 진행한 뒤 그 다음 프레임부터 표시한다.
디스크 배치는 F의 4트랙과 완결편의 3트랙을 각각 사용한다.

F v0.5 a/b/c의 EXEC은 동일했다. TSR의 폰트 그림 차이는 실행 코드 및
시연 진입점과 구분하여 한 F 런타임을 공유한다. F 런타임
`c2e5118ff537f382c541`을 사용한 당시 브라우저 검사에서는 실제 v0.5a 이미지로
빔사벨 #1과 빔라이플 #2 / 기체 #1 / 파일럿 #10을 선택했다. 각각 연출
282와 60이 67프레임에 적용되고, 1686·1390프레임에 종료 표식에 도달했다.
이어 선택한 발칸 #3도 연출 1280이 67프레임에 적용되고 1466프레임에
종료 표식에 도달했다. 세 사례의 종료 표식은 전체 조합의 재생 보증이 아니다.
b/c의 개별 브라우저 실행과 모든 조합은 검사하지 않았다. 네이티브 게임을
처음부터 진행하는 검사는 추가하지 않았다.

완결편 EXEC 로드 기준 0x06004000:

- `060496DC`: 얼굴·대사 선택 준비 함수 진입 전에 공격자 상태를 교체한다.
  이 함수는 파일럿에서 얼굴 번호를, 무기 +2 하위 6비트에서 대사 키를 읽는다.
- `06019998`: 무기 연출 번호로 D_ANIME 자원을 선택한다.
- `0601954C`: 기체 전투 그래픽 요청. 이 위치만 교체하면 이미 선택된
  무기 연출이 남으므로 주입 위치로 사용하지 않는다.
- 초기 공격자 `060C6A70`, 현재 공격자 `060C6AB0`.
  무기 +2, 연출 +4, 파일럿 +6, 얼굴 +8, 기체 +10, 전투 그림 +12.
  기체 레코드 ID와 전투 그림 ID를 구별한다.

무장 칸을 추가한 개인 편집본에서는 기체 표가 TSR 끝으로 이동할 수 있다.
미리보기 콜백의 기존 고정 주소 상한을 실제 low work RAM 범위
(`00200000`~`002FFFFF`, 런타임 `core.cpp`의 메모리 매핑)로 수정하고
포인터 셀의 범위도 검사한다. 입력 ROM의 검증 계열·전체 해시 검사는
유지한다. 이 조정은 실제 게임을 처음부터 진행하는 검사를 요구하지 않는다.
기체 표 범위를 조정한 웹 런타임에서 빔라이플 #2 / 건담 #1 /
아무로 #10의 기본 시연이 ‘재생 끝’에 도달하는 것을 확인했다. 추가된
기체 표의 형식·출처 환원은 별도로 여덟 원본·최신 패치 프로파일과 대조했다.

별도 미리보기 빌드에서만 디스패처 콜백을 활성화한다. 원본 ROM과
실행 코드를 파일로 수정하지 않는다. 입력 ROM은 무작위 토큰 채널에서 준비 신호를 받은 뒤,
같은 출처 부모 창이 토큰을 확인하고 전달한다.
에디터는 별도 워커에서 전달할 Blob 전체 해시를 검사하고, 동일 세션·편집 버전의
기체/무기 미리보기만 그 불변 Blob과 컴파일 결과를 공유한다. 부모 창에서 인증된
전달 이외의 입력은 미리보기 프레임이 직접 전체 해시를 검사한다. 계열·해시 불일치나
선택 적용 실패 시 실행하지 않는다.
일회용 저장 메모리를 쓰며 실제 세이브는 연결하지 않는다.

### 완결편 a/b 폰트 공용 런타임

승인된 a/b 이미지 전체 SHA를 확인한 뒤 EXEC `/0`을 비교했다.
b와 c의 EXEC은 동일하고, a는 `060AD505`~`060AD657`의 249바이트만
다르다. a의 해당 글자 표시 진입점 `060AD500`을 같은 재컴파일러로
추가 컴파일했다. 설치 전·후 EXEC 전체 CRC가 승인 값과 일치할 때만
기존 모듈을 선택하고, 그 모듈 안의 글자 표시 진입점만 a 구현으로
보낸다. 나머지 전투 함수는 공유한다. 사용자 ROM이나 RAM의 글꼴·코드를
c로 바꾸지 않으며, 세 폰트가 한 JS/WASM을 사용한다.

이 비교·연결은 네이티브 콜드부트 검사를 필요로 하지 않는다. 브라우저에서
같은 전투를 바로 준비하고, 이미 실행 중인 미리보기의 OFF/ON은 그 상태를
일시정지·재개한다. 게임 전체 플레이 검증과 구별한다.

당시 공용 런타임 `c4a2751a8b8bbaf8e838`에서 승인된 a/b 원본 이미지를 각각
전체 해시 검사 후 열었다. 두 폰트 모두 빔라이플 #2 / 건담 #1 / 아무로
#10으로 원래 전투 화면·한글 대사·얼굴 표시를 확인했다. b는 종료 표식에
도달했다. a는 재생 중 화면을 확인한 뒤 탭을 닫았으므로 종료를 주장하지
않는다. F 지원이나 모든 무기의 재생 검증으로 확대하지 않는다.

### 307번 이후 파일럿 선택 수정

F와 완결편 파일럿 표는 400칸이며 고유 레코드는 각각 391개다. 기존
미리보기의 307번 상한 때문에 포우 #347 등 뒤쪽 파일럿을 선택할 수
없었다. 목록·워커·WASM 콜백을 399번까지 연결했다. 308~311번은 머리부가
없는 주인공 습득표이며 312~319번은 첫 레코드의 예약 별칭이므로
계속 제외한다. 명칭이나 얼굴이 비어 있다는 이유만으로 일반 레코드를
추가로 제외하지 않는다. 실제 목록의 레코드만 선택할 수 있다.

이전 런타임 F `499724e0d9ffcecb6374`, 완결편
`69d69d926c57bebe13b0`에서의 결과다. 실제 완결편 v0.3c 검증 세션에서 빔라이플
#2 / 건담 #1에 포우 #347을 지정했고 2660프레임에 적용, 4489프레임에
종료 표식에 도달했다. 이어 샤피로 #398도 같은 적용 시점과 4309프레임의
종료 표식을 확인했다. F v0.5a의 #2 / #1 / #347은 67프레임에 적용되고
1464프레임에 종료 표식에 도달했다. 이는 세 지정 사례의 결과이며 모든 후반 파일럿의
고유 음성·대사·조합을 검증했다는 뜻은 아니다. 원본 ROM·세이브를 수정하거나
네이티브 게임을 실행하지 않았다.

목록·워커의 정상 레코드 전달과 습득표·별칭·범위 밖 값 거부, 기존 세션
검사 등 관련 자동 검사 29개가 통과했다. 두 빌드의 종료 코드 0을 확인한
후에만 패키징하고 JS/WASM 일치·소스 아카이브 전 구성원의 해시를 검증했다.
검사기·아카이브 예외 핀을 함께 갱신하고 이전 두 런타임은 기존 해시와
대조한 뒤 삭제했다. F와 완결편에 각각 한 벌만 남긴다.

## 실제 확인과 한계

동일한 지원 ROM에서 빈 저장 메모리로 실행한 두 사례:

| 선택 | 원래 로더에 전달한 값 | 관찰 |
|---|---|---|
| 빔라이플 / 건담 / 아무로 | 무기 2, 기체 1, 파일럿 10, 그림 1, 연출 57 | 건담과 아무로 얼굴·이름·대사 표시, 공격 후 적 피해 표시, 다음 전투 전 정지 |

무기 레코드는 연출 번호가 0이다. **전용 창 투척 연출을 복구했다는
의미가 아니다.** 화면에도 이 한계를 표시한다. 모든 미사용 무기·기체
조합을 정상 재생한다고 보장하지 않는다. 미사용 데이터의 존재·선택과
완성된 연출의 복구는 구별한다.

‘시연 시간 끝 · 연출 완료 미확인’을 표시하는 것을 확인했다.

## 용량·라이선스

ROM을 서버로 보내거나 브라우저 저장소에 보존하지 않는다. 같은 출처의
JS/WASM을 쓰며 필요한 격리 헤더는 동일 출처의 서비스 워커가 추가한다.
ROM을 고르기 전 첫 페이지 로드에서 실행 환경을 준비한다.
서비스 워커는 응답·ROM을 캐시하지 않는다. OFF 상태에서도 같은 편집
세션의 메모리는 유지하지만, 공유 플래그와 Atomics.wait로 실행을 멈추며
오디오도 일시정지한다. 정지·선택 변경·세션 종료는 게임 워커와 오디오를
폐기한다. 실행 프레임 상한과 일시정지를 고려한 응답 시간 제한을 둔다.

배포에 필요한 실행 파일과 해당 소스만 `weapon-preview/runtime`에 둔다.
정확한 파일 해시·크기는 저장소 검사기에 고정한다. 소스·빌드 방법·MIT,
GPL 및 외부 구성요소 고지는 같은 폴더에 포함한다. 임의 ROM·추출 자원·
세이브·추가 아카이브에 대한 예외는 만들지 않는다. 현재 작업은 로컬이며
배포 승인을 뜻하지 않는다.

## 기체 무장에서 바로 미리보기

기체 무장 영역에서도 기본 OFF인 동일한 플레이어를 연다. 각 무장의
미리보기 버튼은 해당 기체와 무기를 전달한다. 넓은 화면에서는 목록
오른쪽 상세 높이 전체에 플레이어를 둔다. 좁은 화면에서 ON이면 같은 상세
영역을 플레이어로 쓰고 상단 OFF로 편집 화면을 복원한다. iframe의 부모는
고정하므로 창 크기 변경이나 OFF/ON으로 다시 로드하지 않는다. 무장
목록은 모든 칸을 유지하고 내부 스크롤을 허용한다. 기체를 바꾸면 목록
맨 위로 돌아가고, 같은 기체의 교체·추가는 위치를 유지한다.

미리보기는 주요 기체의 기본 파일럿 표를 먼저 사용한다. 예를 들어 에바
초호기는 신지, 영호기는 레이, 마징가는 코우지, 겟타 세 형태는 각각
료마·하야토·벤케이이며 변형·후속 기체에도 적용한다. ID와 이름은 불러온
ROM의 파일럿 목록에 존재해야 한다. 이 표는 미리보기의 추천이며 ROM이나
세이브의 실제 탑승자를 변경하거나 현재 탑승자를 조회하는 기능은 아니다.

기본 표에 없는 기체는 ROM의 고정 배치와 시작·합류 스크립트에서 읽은
배정을 사용한다. F/완결편 C7과 C2.06의 명시된 구간은 위치와 SHA-256이
일치할 때만 읽고, 디버그 편성인 물리 본문 0은 제외한다. 보조 판독 결과를
view에 전달하지 않던 누락도 수정했다. 별칭은 중복 집계하지 않는다.
관련 근거가 없는 기체는 직접 선택하며 아무로로 일괄 대체하지 않는다.
직접 선택한 파일럿은 기체별로 기억하고 무기를 바꾸거나 다시 재생해도
유지한다. 화면에서도 ‘기체별 기본 파일럿’·‘ROM 등장 배정 파일럿’·
‘파일럿 직접 선택’을 구분한다.

기체 화면은 별도 무장 전용 탭을 신설하지 않는다. 기존 측정 배치 안에서
능력·특수능력의 빈 공간을 압축하고 넓은 화면에서는 앞쪽 패널을 가로로
묶는다. 격추보상·지형효과는 드롭다운 대신 검색 가능한 세로 목록으로
한 번 클릭해 선택하며, 목록과 상세 영역을 각각 화면 높이 안에 둔다.

### 전체 트랙 준비 후 재생 (2026-10-25)

무기 탭은 웹 런타임으로 공격 전체를 먼저 실행하고, 완성한 트랙을 그린 뒤
부모 화면의 두 RAF 확인을 받아 재생한다. 분석 중에는 트랙 막대를 그리지 않는다.
재생 중에는 위치선만 갱신하며 기존 막대의 시작·끝·폭을 늘리지 않는다.
기체 무장 미리보기에는 타임라인이 없어 첫 재생은 직접 보여 주면서 기록하고, 이후 같은 선택은 기록을 재사용한다.

분석한 실제 RGBA 프레임은 XOR와 반복 길이로 무손실 저장하고 오디오와 함께
브라우저 메모리에서 재생한다. 최대 128MiB·7,000프레임이며 초과 시 잘린 전투를
보여주지 않고 중단한다. 생산자에 최대 네 프레임의 역압력을 걸고 분석 완료 시
네이티브 워커를 종료한다. ROM·상태·프레임을 디스크에 저장하지 않는다.
OFF/ON은 기록의 같은 재생 위치를 일시정지·재개하고, 선택 변경·정지·종료는
이전 준비와 재생을 취소한다. 기록 프레임·곡·피해는 해당 재생에서 실제 계산된 것이며
게임 전체의 임의 시점으로 이동하는 기능은 아니다.

### 선택한 파일럿의 음악·수치에 반응하는 시연 피해 (2026-10-23)

기존 시연은 얼굴·무기 자원 요청 직전에 공격자를 바꿨다. 원래 음악 선택은
그보다 먼저 실행돼 겟타의 곡이 남을 수 있었다. 독립 데모는 실전의 자동
음악 선택도 호출하지 않고 곡을 직접 지정했다. 별도 미리보기에서만 원래
음악 로더(F `06006110`, 완결편 `0600632C`)의 곡 명령을 받으면 F의
`060185D0`, 완결편의 `06018A84`를 선택한 파일럿·무기 연출로 실행해
그 결과를 로더에 전달한다. 원본 함수의 파일럿 +2 음악 계열, F의 32칸/완결편의 64칸 음악표,
특수 연출의 음악 우선순위와 원래 음악 로더를 그대로 사용한다. 음악 선택용
임시 전투자·모드 값은 함수가 반환하면 복원하며 ROM과 세이브에는 쓰지 않는다.
이것은 기체의 출전 작품명을 보고 임의의 음원 파일을 붙이는 방식이 아니다.

피해는 **실전 공식 전체를 실행한 값이 아닌 조건 고정 비교값**이다. 실전 함수
(완결편 `06051E68`)는 맵상의 출격 명부·정신기·능력·기력 등 현재 플레이
상태를 읽는다. 독립 시연에서 없는 상태를 있는 것처럼 표시하지 않는다.
선택한 ROM 무기 공격력, 무기 +0 bit6에 따른 격투/사격의 Lv50 값(기본+49),
기체·파일럿의 해당 환경 지형 등급, 무기 지형, 원래 시연 상대의 ROM 장갑을 읽는다.
기력100·무개조·일반 명중, 정신기/특수능력/크리티컬/맵 타일 보정 없음으로 고정한다.
성장형을 변경했을 때의 별도 Lv50 재계산은 포함하지 않는다.
계산은 `max(10, floor(공격력 × (능력치+100) / 200) − floor(상대 장갑/2))`에
비교용 지형 계수를 곱한다. 공격력0이나 무기 적응0은 피해0이며, 미리보기의 표시 상한은9999다.
이것은 원본 실전 상한을 확인했다는 뜻이 아니다. 개인 편집으로 큰 값을 넣어도
독립 시연의 피해 표시를 네 자리 안으로 유지하는 제한이며, 상한을 넘는 서로 다른
공격력은 모두9999로 표시한다. 화면·상태의 조건 툴팁에도 이 제한을 표시한다.
공중 표시를 허용했지만 기체·파일럿의 공중 적응 비교 계수가0인 경우는 비행 보조를
가정한 비교용 B등급으로 취급한다. 이 조건은 실제 장착 파츠를 변경하지 않는다.

계산값을 현재 전투 결과의 표시용 total +2(F `060C068A`, 완결편 `060C6AFA`)와
HP 감소용 pending +4(F `060C068C`, 완결편 `060C6AFC`)에 함께 지정한다.
이전에는 pending만 바꾸어 HP는 달라져도 초록 숫자에는 데모의 2560이 남았다.
표시 경로는 F `06036024` / 완결편 `0603B2B8`에서 result+2를 원본 숫자 변환기에 넘기는 것으로 확인했다.
나머지 타격 분배·숫자 그림·HP 애니메이션은 원본 코드가 실행한다.
시연 상대의 HP는 그 기체의 ROM 최대HP로 준비한다. 화면 상태줄의
‘시연 피해 n’과 상태/화면의 툴팁에서 조건을 확인할 수 있다. 수치 편집은

### 같은 전투·배경으로 즉시 반복 (2026-10-26)

자동 반복은 같은 무기·기체·파일럿·ROM 버전의 무손실 화면과 오디오 기록을

현재 선택 한 개·최대128MiB이며 디스크나 브라우저 저장소에 보관하지 않는다.
정지·선택 변경·창 종료는 기록을 해제하고, 정상 종료만 같은 선택의 수동 재생을 위해 보관한다.
OFF/ON은 같은 위치를 일시정지·재개한다.

수치를 편집한 알림이 오면 다음 반복 경계에서 기존 최신 소스 검증 경로를 거쳐
새 기록을 준비한다. 이때 같은 무기는 동일한 난수와 이전 배경 제외값을 사용해

무기 값으로 다시 검사한다. 지형 자체를 바꾸면 허용 조건에 맞는 배경으로 바뀔 수 있다.
