# 제4차 Rev 1 미사용 기체 가져오기 (2026-10-27)

로컬 웹에디터의 **기타 → 제4차 Rev 1 원본 찾기**에서 사용자가 소유한 일본판 Rev 1 SFC/SMC 또는 단일 ROM ZIP을 선택한다. 전체 ROM 해시와 구조를 검증한 뒤 7개 형태를 자동 등록한다. 기존 기체와 무장 복제는 중복하지 않으며, 검증·빈 자리·인접 변형 자리 확인에 실패하면 기존 편집값을 유지한다. ROM과 추출 그림은 서버로 전송하거나 저장소에 포함하지 않는다.

등록 후 BIN을 저장하고 그 BIN을 실행한다. 기존 진행 세이브의 보유 기체 등록은 세이브 편집에서 별도로 한다. 기체 정의 추가만으로 모든 시나리오의 스토리 합류 이벤트가 바뀌지는 않는다. 현재 검증 입력은 F v0.5 a와 완결편 v0.3 c다. 아직 조립하지 않은 완결편 v0.4를 실행했다고 표현하지 않는다.

## 실제 ROM 추출 근거

검증한 Rev 1은 3,145,728B, SHA-1 `c48b09d0ed6850896db7d7b4e08caffc0376223a`, SHA-256 `efd72094b2727c4903924cf9296b3946b95a354f639b600e1d76d9ec6b9ca18b`, CRC32 `63883e1e`다. ZIP 포장을 해제한 뒤 동일한 전체 ROM 검사를 적용한다. 암호화·다중 ROM·잘린 항목·크기 초과·CRC 및 local/central 불일치를 거부한다.

맵 아이콘은 실제 ROM의 **0x2F7000 sheet16 은행**이다. 아이콘 하나의 4개 SNES 4bpp 타일은 `base + floor(id/8)*1024 + (id%8)*64`에서 `+0,+32,+512,+544`에 있다. 서로 다른 6기 형상 지문이 같은 은행을 가리키며 실제 전체 기체 참조가 범위 안에 있다. 단순 선형 128B 아이콘 배열로 읽지 않는다.

맵 팔레트는 실제 게임 실행 중 CGRAM과 ROM의 같은 32B 범위를 대조했다. 아군 0x60558, 적군 0x60576, 기타 0x6053A, 회색 0x6051C다. UI에는 제4차 원색과 F 저장색을 나란히 표시한다. F KOM의 기존 진영 팔레트 128B는 바꾸지 않는다.

G크루저 그림 #124·125의 압축 타일 포인터 표는 0x160000(LE24 HiROM), 공통 압축 자료는 0x19EBFC(1621B → 2624B/82타일)다. 긴 LZ 참조는 이 자료에서 확인한 big endian으로 읽는다. 조립표는 0x640C0의 LE16 포인터 +0x60000이며 #124는 0x676A9(12 OAM), #125는 0x676DA(17 OAM)다. OAM은 LE16 타일·플래그와 signed Y/X를 사용한다. 팔레트는 0x608B2 포인터 표 → 0x622D8의 15색이다. 각 테이블·압축 자료·배치·최종 인덱스 픽셀의 고정 해시를 검사한다.

원본 88×40 그림을 확대·재색칠하지 않고 144×112 Saturn 캔버스의 (27,43)에 배치한다. 축은 (72,96), 포구는 (29,80)이다. 이 주소 해석을 확인하지 않은 다른 전투 그림까지 확장하지 않는다.

## F/완결편 저장 및 재검증

`editor-srw4-native-map.mjs`는 검증한 빈 KOM 슬롯에 6개 아이콘만 넣고 전체를 재압축한다. 슬롯은 F 319..324, 완결편 336..341이다. 블러드템플은 원래 62번을 참조한다. 원래 파일 길이를 늘리거나 ISO 여백을 새 저장 공간으로 간주하지 않는다. 실제 출력 여유는 F 161B, 완결편 183B다.

`editor-kom-recovery.mjs`는 압축 토큰 결정만 기록하는 복원 원장으로 원래 KOM 압축 바이트까지 정확히 복구한다. 문자 그대로의 게임 그림은 원장에 넣지 않는다. 원장은 F 1452B, 완결편 1526B로 C_ROBOT의 opt-in BCP07 기록에 포함한다. 원래 C_ROBOT 및 KOM을 복구한 뒤 기존 불변 해시를 검사한다. 불변 검사 범위를 넓혀 가져오기를 통과시키지 않는다.

BCP07은 7개 형태의 전체 구성(mask 0x11F)에만 적용하며 기존 1..6 형식은 유지한다. 그림·KOM·기체 번호 연결·복원 기록을 모두 재생성해 비교한다. 임의 JSON의 `verified`나 임의 픽셀은 인증 수단이 아니다. 프리셋에는 `construction.source: "srw4-rev1"` 선택만 저장하며, 실제 자산 저장에는 다시 검증된 ROM 연결 또는 이미 검증된 BCP07 편집 BIN이 필요하다.

실제 F/완결편 BIN에 일괄 추가 → 내보내기 → 새 inspector에서 전체 이미지 재열기 → 무수정 재저장을 확인했다. 양쪽 모두 7개 형태·변형 연결·아이콘·기존 ALICE 설정이 유지됐고 재저장 변경 바이트는 0이었다.

## 실행 검증 기록

비공개 자료는 `build/srw4-native-import-20261027/`에 둔다. `core-roundtrip.mjs`, `native-roundtrip.mjs`는 실제 BIN 저장과 원본 복원을, `ui.cjs`는 실제 ZIP 선택·오류 후 편집 유지·중복 방지·미리보기와 화면 폭을 확인한다.

기존 비공개 네이티브 실행 기록의 전투·변형 사례 22건(F 12건, 완결편 10건)을 대조했다. 모두 전투 후 맵 복귀를 통과했으며, 실행 중 RAM 덮어쓰기와 무장 조건 강제 해제는 0회였다. 별도 새 프로세스 재로드 사례는 F의 비행 중 G크루저와 완결편 S건담 각 1건으로, 저장한 기체 번호·HP·EN을 유지했다. 22건 모두를 저장·재로드한 것으로 해석하지 않는다. 각 근거는 `cases/*/result.json` 및 `reload-results.json`이다.

초기 최소 편성에서 발생한 완결편 시나리오 패배와 F 네이티브 진입점 0x00258300 누락은 중간 실패 기록이다. 후속 기록은 원래 스토리 기체·플래그를 보존한 복사 세이브를 사용했고, F 네이티브는 관찰한 진입점을 등록했다. 원본 TSR 바이트는 바꾸지 않았다. 이 기록은 모든 시나리오의 장시간 진행을 보장하지 않으며 2026-10-28에 콜드부트를 새로 실행했다는 뜻도 아니다.

## 저장 전 가져오기 취소 (2026-10-28)

기타의 **가져오기 취소**는 이번 세션에 연결해 추가한 7형태를 한 묶음으로 되돌린다. 이미 가지고 있던 5종에 G크루저 2형태만 추가한 경우에는 새 2형태를 제거하고 기존 5종과 개인 수치를 보존한다. 기존 행은 가져오기 전·후·현재 값을 대조해 가져오기 변경만 원복하므로, 가져온 뒤 바꾼 기존 기체의 HP와 무기 수치도 남긴다. 다른 기체에서 쓰는 새 무기 레코드는 지우지 않는다. 다시 연결해도 최초 취소 기준은 유지된다.

제4차 구성이 활성화된 상태에서 기체 하나나 변형 한 쌍만 일반 취소하는 동작은 변경 전에 거부한다. 부분 취소는 7형태를 요구하는 저장 형식을 깨뜨릴 수 있기 때문이다. 무장 구성만 갱신하는 경우에도 제4차 출처 표시와 맵 아이콘을 유지한다. 원본 **연결 해제**는 가져오기 취소와 별개이며, 아직 저장하지 않은 가져오기는 원본을 다시 연결하거나 묶음 취소한 뒤 저장한다. 이미 저장한 BIN을 여는 것 자체를 이 취소 기록으로 되돌리지는 않는다.

실제 다운로드 ZIP과 승인 F v0.5 a·완결편 v0.3 c에서 기존 5종 → 2형태 추가 → 취소 → 출력·전체 재열기 → 무수정 재출력을 확인했다. 기존 S건담 HP 43210을 가져온 뒤 45678로 바꾸고 스마트건 공격력 7654를 유지했다. 양쪽 최종 BIN은 기존 5종·HP45678·공격력7654를 보존했고 재출력 변경 바이트는 0이었다. 대용량 BIN 사본은 저장하지 않았다. 근거는 `build/srw4-package-undo-20261028/actual-roundtrip.json`이다.

## 제4차의 ALICE 자료 범위

제공된 Rev 1의 파일 offset 0x12878F에는 강화파츠 명칭 `ＡＬＩＣＥ`가 있으며 파티마·사이코프레임·바이오센서 명칭과 같은 목록에 있다. 원저자 이름표 해석으로 읽은 파일럿 이름·약칭 각 320칸에서는 ALICE를 찾지 못했고, 연결된 독립 파일럿·초상화도 확인하지 못했다. 미참조 이미지까지 없다고 확정한 것은 아니다. 현재 로컬 에디터의 ALICE는 사용자 승인 자체 실루엣과 별도로 작성한 서브파일럿·정신기 설정이며 제4차에서 복원한 파일럿 자료가 아니다.

## 발사 위치와 MAP 영상 정정 (2026-10-28)

BCP07 출력에는 `SRWBAP05` 좌표 구성을 적용한다. G크루저 두 형태의 스마트건은 BTSR 목록 12의 `(-27,9)`, 블러드 템플 파워런처는 목록 11의 `(-51,-5)`를 사용한다. 원래 기체·FFFF 기본 좌표·손 좌표는 그대로 보존하며 BAP02..04의 복원 규칙도 유지한다. BAP05를 BCP07 그림 없이 조합한 입력은 거부한다. 과거 BCP07/BAP04 편집본은 다음 미리보기·내보내기에서 좌표를 갱신하며 게임 파일 길이는 늘리지 않는다.

기존 BIN을 사용하는 백그라운드 네이티브 시연에서 동일 프레임의 원점 보정을 대조했다. G크루저 스마트건은 충전광 중심 `(162,128)`을 총구 `(149,120)`으로 옮겼고, 블러드 템플 파워런처는 목록 12가 아닌 목록 11을 보정해 총구 `(110,112)`에 맞췄다. 이 시연은 임시 RAM 좌표를 이용한 교정 확인이며 새 디스크를 부팅한 검증으로 취급하지 않는다. 실제 저장의 검증은 F·완결편 메모리 내 BIN 출력·전체 재열기·무변경 재출력으로 별도 확인한다. 비공개 근거는 `build/srw4-emitter-fix-20261028/` 및 `build/srw4-video-review-20261028/blood-audit/`에 둔다.

이전 `f-map-buster`·`final-map-buster` 촬영은 메뉴 5번인 일반 무장 #743 기가블래스터였으며 MAP 검증 사례가 아니다. 사례의 `mapAttack:true`는 설정 메타데이터를 복사한 값이었다. 올바른 #785 버스터런처 MAP은 메뉴 4번이며 실제 맵 범위·발사·EN 50 소모와 적 HP 변화를 별도로 확인했다. 기본 블러드 템플 구성의 #743과 #785는 별도 무장으로 모두 유지한다.


## Ex-S 발사 자세와 긴 빔 보정 (2026-10-28)

**기타 → Ex-S 빔포 연출 보정**을 켜고 BIN/CUE를 저장하면 제4차 G크루저 그림과
아이콘을 보존하면서, Ex-S의 독립 4연장빔캐논 발사 때만 조준 자세로 전환한다.
네 포문 충전광·긴 빔을 같은 그림에 맞추고, 적 명중 화면의 빔도 화면 끝까지
이어지게 한다. 새 구성은 기본 ON이며 과거 편집 BIN은 명시적으로 켜야 한다.
재열기·OFF 저장·재ON 저장을 지원하고 개인 무기명·공격력·기체 능력치를 유지한다.
원본 #511을 공유하는 다른 기체의 연출은 바꾸지 않는다.

## 기존 Ex-S 연결과 저장 안정화 (2026-10-29)

이미 추가한 S 또는 Ex-S에 변형기가 없는 경우, 다른 새 변형쌍을 배정하기 전에
기존 기체 바로 뒤의 자리를 먼저 확보한다. 기존 Ex-S에 새 G크루저를 연결할 때는
편집 화면의 잠긴 변형 능력 표시도 갱신하여 저장 검사에서 이전 값으로 덮어쓰지
않는다. 유효하지 않은 입력이 남아 있으면 가져오기 전에 수정이나 복원을 요청한다.

제4차 자료를 연결하기 전에 기존 기체를 포함한 무기 부착 좌표 공간을 검사한다.
한도를 넘으면 자료와 기체를 적용하지 않고 사용량을 안내한다. 이 검사와 안내가
좌표 공간의 고정 한도를 늘리는 것은 아니다. 같은 프리셋을 여러 기체 번호에 쓰는
경우 재열기는 프리셋 종류 수가 아니라 기체 번호별 기록을 검사한다.

완결편 v0.3c와 제4차 Rev 1을 이용한 로컬 브라우저 검사에서 새 7형태 추가 후
Ex-S 미리보기 재생과 BIN/CUE 생성, 생성 BIN 재열기 및 ALICE 동승을 확인했다.
또 기존 Ex-S의 HP를 변경한 뒤 나머지 6형태를 연결한 사례에서 BIN 생성·재열기,
변경한 HP와 ALICE의 Ex-S/G크루저 연결 보존을 확인했다. 세 Ex-S를 먼저 추가해
좌표 한도를 넘는 사례에서는 기존 세 기체를 보존하고 연결을 적용하지 않았다.
별도로 Ex-S를 먼저 BIN에 저장하고 그 파일을 재열어 제4차를 연결하는 코어 검사에서도
수정한 HP와 ALICE 동승, 일곱 기체가 다시 저장·재열기된 것을 확인했다.
이 검사는 장시간 게임 진행이나 모든 기체·무장 조합의 동작을 보장하지 않는다.


## 완결편 v0.3 새 게임 초기 지급 (2026-11-10)

검증된 제4차 Rev1 연동을 적용하고 BIN/CUE를 저장한 뒤, F 세이브를 인계하지
않는 새 게임을 시작하면 슈퍼계·리얼계 모두 최초 인터미션에 기본 5대를
보유한다. 두 G크루저는 각 건담의 변형 형태이며 독립 기체로 지급하지 않는다.
ALICE 동승을 켠 경우 기존 전용 서브파일럿 #399도 한 번 등록한다. 이미
존재하는 기본형·변형형과 ALICE는 중복 생성하지 않는다.

F의 자동 지급과 기존 세이브에 새 파일럿을 추가하는 기능은 이번 단계에
포함하지 않는다. 기존 세이브를 로드한다고 자동 지급하지 않는다. 별도의
‘5대＋ALICE’ 일괄 추가 버튼도 제공하지 않는다.

완결편 v0.3c의 실제 새 게임·최초 인터미션·게임 메뉴 저장·새 프로세스 로드를
슈퍼/리얼 두 경로에서 검증했다. 후속 모든 분기·다음 인터미션·장기 플레이,
개별 a/b 글꼴의 실제 실행·실기·CD-R까지 검증했다는 뜻은 아니다.
