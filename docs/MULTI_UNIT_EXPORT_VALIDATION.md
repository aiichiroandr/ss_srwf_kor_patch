# 다중 기체 저장 추가와 편집 출력 검증

## 저장 기체

저장 행은 ROM 기체 정의와 별개다. 같은 정의 ID가 여러 저장 칸에 있는 것은
정상이며, 추가는 기존 ID→칸 대응을 재사용하지 않는다. 한 번의 추가는 필요한
모든 그룹 구성원을 새 빈 기체 칸에 만들고, 새 링크는 그 호출에서 만든 칸만
가리킨다. 따라서 기존 행의 파일럿, HP/EN, 개조, 파츠, 진행 링크는 보존된다.

변형 kind 1 S/Ex-S는 게임이 한 물리 행의 ID를 바꾸므로 base만 추가한다. 반면
kind 4와 검증된 kind 6/8은 표시된 저장 칸 수만큼 빈 칸이 필요하다. kind 9는 ordered 2/0/1 정의를 새로 모두 만들되 결합 form2만 자신의 새 base form0을 가리키고 support form1은 독립이다.
일반 파일럿 수동 추가의 ID 유일성은 바뀌지 않았다.

ALICE 지원이 인증된 S/Ex-S에서는 가족 root 수가 아니라 실제 저장 기체 행 수를
센다. 기존 유효 #399 행의 SP, 사기, EXP, 레벨, 인간 체인은 바꾸지 않고 부족한
행만 초기화한다. 공유/모호한 인간 체인, 5행을 넘는 체인, 또는 파일럿 칸 부족은
기체 추가 전체를 원자적으로 거부한다. 화면의 `ALICE 필요/새 준비/보존 포함` 수는
각각 필요한 hull, 이번에 초기화한 행, 현재 보존된 행을 뜻한다. 여러 ALICE는
같은 정의 #399를 쓰는 서로 다른 저장 행이며 인간 승무원 체인과 SP 칸도 별개다.
신규 추가 템플릿과 실제 저장 상태는 다르다. 단쿠가는 합체 상태의 구성원→본체
링크와 분리 상태의 본체→첫 구성원 링크를 구분한다. 확인하지 못한 같은 계열
상태는 원본 링크를 바꾸지 않는 경고로 남긴다.

## ROM 편집 출력

`preflightEditedImage`는 인증 세션과 요청의 형식, TSR/시나리오 데이터 writer의
용량·참조 검사를 수행한다. 실제 `exportEditedImage`는 이후 native/Fv2/캠페인
조합도 각 writer의 read-back 및 해시 단계로 완료한다. 이 작업의 단위 테스트는
파서와 writer 계약의 구조적 실패를 다루며, 게임 런타임 충돌을 전부 예방한다고
주장하지 않는다.

출력 실패는 요청이나 입력 세션을 변경하지 않아야 하며, worker는 실패한 export를
새 다운로드로 캐시하지 않는다. 경고는 확정된 구조 오류가 아닌 실제 플레이 범위의
불확실성을 구분해야 한다. 최종 물리 TSR은 inspector와 같은 보조 기록·이름·복제·
분산 저장 복원 순서를 거쳐 읽는다. 출력 화면은 이를 「구조·무결성 검사 완료」로
안내하며, 실제 게임 플레이의 성공과 구분한다.

## 2026-11-13 로컬 실행 표본

검수 원본과 로그는 저장소 밖 `SRWF-MULTI-EXPORT-검수-20261113`에 보존했다.
이 검수는 새 공개 릴리스의 승인이나 배포가 아니다.

- 실제 브라우저에서 일반 기체, 단일 행 변형, 겟타, 슈퍼건담, 단쿠가(다른 구성 형태
  선택 포함), 콤바트라와 S/Ex-S를 반복 추가했다. F는 59→100 기체 행과 ALICE
  1→5명, 완결편은 57→99 기체 행과 ALICE 0→4명으로 저장·재열기를 통과했다.
  기존 점유 행의 바이트와 다른 저장 슬롯의 payload, 체크섬을 대조했다.
- 두 게임의 해당 브라우저 출력 일반 저장을 payload 변경 없이 내부 RAM 용기에
  옮겨 Mednafen에서 스테이트 없이 로드했다. 각 기체 ID·개별 칸·탑승자·연결 칸이
  출력과 일치했다. 각 게임에서 새 S건담 두 대에 서로 다른 인간 파일럿을 태웠고
  별도 ALICE 행이 연결됨을 확인했다.
- F에서는 그 상태를 게임의 일반 저장으로 저장한 뒤 프로세스를 종료했다.
  브라우저에서 새로 출력한 HP+1 BIN으로 스테이트 없이 재로드해 기체 100행,
  두 S의 탑승자, 독립 ALICE 연결과 SP 저장 칸을 다시 확인했다.
- F v0.5 a와 완결편 v0.3 c의 개인 Rev1/ALICE 이미지에서 HP 3000→3001 편집,
  preflight, 실제 BIN/CUE 다운로드와 독립 inspector 재열기를 통과했다.
  원본 ROM이나 사용자 세이브에 덮어쓰지 않았다.

같은 S 두 대의 전투 정신기 소비·회복, 새 복수 합체 그룹의 실제 전투·변형·분리·
재합체, 모든 고정 파일럿 기체의 동시 운용, 모든 a/b/c 이미지, 장기 분기는 이 표본이
증명하지 않는다. 기존 S/Ex-S 간 정신기 소비 실행 근거는 별도의
`ALICE_SP_RUNTIME_20261113.md`에 있으며 이번 동형 두 대 표본과 혼합하지 않는다.
새 ALICE는 미탑승 기체에 준비할 때 Lv1로 초기화되며 기존 ALICE의 진행·SP는
보충하지 않는다. 인간 갈아타기 때 SP 소유권이 기체에 영구 고정된다는 뜻도 아니다.
