# 새 턴 조건의 실제 승리·게임 저장 복원

2026-10-10에 F완결편 최신 승인 v0.3 c를 바탕으로 만든 개인 편집 BIN에서 **새 조건 → 원래 승리 사건 → 전투 후 대사 → 34화 완료 → 게임 저장 → 중간 저장 없는 재부트와 게임 내 로드**를 확인했다. 이 증거는 아래 한 경로에 한정된다.

## 입력과 편집

- 승인 입력 SHA-256: `0fb10cbf4332f94c865c0e8d0a0c7234f8f6083bdbbb5a06198cebff871d195d`.
- 개인 출력 SHA-256: `d0f0e32d2325cfa28f648e3b64e18648359d19ccda7037ab7e421e95d16e2bcc`.
- SCEDATA 선택 번호 102 / 물리 본문 5 / 기존 `SRWFOB01` 연결 방식.
- 직접 지정한 시험 조건: 승리 `1턴 이상`, 패배 원래의 `아군전멸`, 승리 우선, 추가 턴 제한 0. 숫자 1은 에디터의 기본값이 아니다.
- 실제 제품의 `inspectPatchedImage`와 `exportEditedImage`로 만들고, 출력 영수증 없는 새 코어 세션에서 모든 조건 필드와 `bounded-editor-profile` 출처를 확인했다.
- 해제 본문은 13,462 → 13,618 bytes. root 8은 3,267로 유지하고 root 13은 13,511로 연결했다. 새 판정 코드 시작은 13,462이다.

원래 승리 목적지는 본문 3,301이다. 여기에는 대화와 후속 사건이 있고, 마지막의 `EC 01 EA`는 3,326에 있다. 조건이 맞았다고 이 사건을 생략하고 EC만 새로 생성하지 않았다. 원래 패배의 `EC 02 EA`도 3,329에 그대로 있다.

## 실제 실행 근거

출력 BIN을 고정된 승인 다중 트랙 구성으로 부트했다. RAM 변경, 치트, 네이티브 미디어 식별값 강제 변경은 사용하지 않았다. 이후 이어 쓴 에뮬레이터 중간 상태는 모두 **이 출력에서 생성한 것**이며, 각 실행의 source MCA 전체 해시를 기록했다. 승인 이미지에서 만든 중간 상태를 수정 BIN의 실행 근거로 재사용하지 않았다.

1. 첫 부팅은 저장 파일명 설정에서 확장자 앞 점이 빠져 복사한 기존 저장을 읽지 못했고, ‘로드 데이터가 없습니다’ 뒤에 타이틀 ‘시작’으로 진행했다. 전장 진입 전 완결편 새 게임의 실제 인터미션에는 **33화까지 완료**가 보였다. 이것을 기존 GameSave33 로드나 새 승리 성공으로 계산하지 않았다. 이후 게임 저장·재부트·로드는 이 실행이 실제 생성한 활성 backup을 사용했다.
2. 새 `D4 00`의 인수 주소 `0x20206C97`에서 네이티브 반환 `0x06027064`를 관측했다. 게임의 raw 턴 byte는 2, 조건 문맥 +20의 값은 1이었다. `F5`와 새 상대 점프가 원래 승리 사건으로 연결되는 실제 읽기도 기록했다.
3. 후속 실행 323프레임에 원래 EC의 인수 주소 `0x202044FF`에서 `EC 01`이 실행됐다. `0x06020236`의 상태 쓰기 결과는 `0x10`이었다. 이어 원래 공통 목적 소비처의 `EC FF` 인수 주소 `0x2022203D`, 반환 `0x06020238`에서 승리 결과 1을 읽었다.
4. 원래 대화를 넘긴 뒤 게임 저장 화면과 인터미션에 **34화 ‘프론티어 IV의 위기(전)’까지 완료**가 표시됐다. 이름은 사용자 입력의 TSR 제목표에서 디코딩한 `프론티어　ＩＶ의　위기（전）`과도 대조했다.
5. 실제 게임 저장을 수행했다. 확인한 저장 파일의 SHA-256은 `2fca6d73281da01ab06b12141d69ffd7d3e1d921c49d336224f3b1b527f3caa4`에서 `fe3abac1e5de71b977cdc035509ed061d0ce2c4a99720dec8c3132fe84847550`로 바뀌었다.
6. 그 실행의 저장 홈을 별도 경로로 복제하고 **MCA를 모두 제거한 뒤** 같은 출력 BIN을 재부트했다. 타이틀의 로드 → 본체 RAM → 저장 항목을 실제 패드로 선택했다. 로드 목록과 복원된 인터미션 모두 34화 완료를 표시했다.

각 실행은 정상 종료했고 timeout은 없었다. 전체 출력 이미지 해시, 원래 EC 바이트, 새 코드·루트, source MCA 연결, 실제 턴 조회와 승리 소비값, 게임 저장 변경 및 캡처 해시를 독립 사적 검사로 다시 확인했다. 바이너리·추출 데이터·BIOS·저장 데이터·캡처·trace는 저장소 밖에만 있다.

## 이 근거의 한계

이 한 경로는 F완결편 본문 5에서 새 턴 비교가 원래 승리 사건과 진행 저장까지 이어진다는 것을 증명한다. 앞서 별도로 확인한 같은 본문의 새 2턴 패배 경로와 구분한다. F의 실제 승리, 새 `SRWFOB02` 콜백, 모든 비교·결합·동시 우선순위, 다른 시나리오, 편집 전 진행 중이던 게임 저장의 호환성을 전수 검증한 근거는 아니다. 새 기체·이벤트·페이즈 이동 또는 특정 인물·영역 조건을 이 근거만으로 활성화하지 않는다.

현재 조건 편집 범위와 웹 BIN/JSON 복원 계약은 [EDITOR_OBJECTIVE_COVERAGE.md](EDITOR_OBJECTIVE_COVERAGE.md)를 따른다. 개인 출력은 ACCEPTED 릴리스가 아니며, 이 검사는 새 릴리스나 원격 배포를 승인하지 않는다.
