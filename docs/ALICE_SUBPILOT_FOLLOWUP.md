# ALICE 종속 서브파일럿 후속 검증 — 2026-11-13

이 변경은 로컬 세이브 편집기 기능이다. 공개 기준은 `693231d9e1f090c4dddf1883a062bc8ce235995b`이며, 이번 후속 변경을 push/배포하거나 새로운 게임 패치 릴리스를 승인하지 않았다. 네이티브 동승 코드와 세이브 형식은 바꾸지 않는다.

## 동작과 보존 정책

- 확인한 ROM의 동승 패치와 S/Ex-S 양쪽 변형 좌표를 인증한 경우, 기본 기체 추가와 필요한 ALICE 준비를 하나의 작업으로 처리한다. 동승 패치 또는 대상 기체를 확인하지 못하면 기체만 조용히 넣지 않고 추가를 거부한다.
- S 계열 한 기는 ALICE 한 명, S와 Ex-S를 함께 보유하면 두 명을 준비한다. 크루저로 변형된 기체도 같은 한 기다. 크루저를 별도 기체로 지급하지 않는다. 한 계열의 기본·변형 행이 동시에 있는 오래된 중복 저장은 자동 추정하지 않고 거부한다.
- 기존의 유효한 ALICE와 인간 동승자 연결, 레벨·EXP·기력·16비트 SP는 그대로 보존한다. 대상 S/Ex-S hull 밖의 인간에 붙은 terminal 행은 원래 native sync가 대기 행으로 되돌리는 경우에만 가용 수로 세며, 저장에서 unlink/reset하지 않는다. 대상 hull의 인간에 붙은 행은 재사용하지 않는다. 대기/안전 회수 행까지 충분하면 추가하지 않고 부족분만 기존 파일럿 초기화기로 만든다. 파일럿 칸이 부족하거나 연결이 모호하면 기체·파일럿 모두 변경하지 않는다.
- 새 ALICE가 필요한 기존 탑승 기체에는 해당 인간의 레벨을 사용한다. 새 빈 기체에 준비하는 ALICE는 레벨 1이다. 다른 기체의 높은 레벨을 복사하지 않는다. 대기 ALICE의 레벨이 첫 탑승 인간과 즉시 같아진다고 보장하지 않는다.
- 일반 파일럿 수동 추가의 같은 ID 중복 금지는 유지한다. 자동 ALICE 준비만 동시 운용에 필요한 여러 #399를 지원한다. 추가/내보내기에서 실제 ROM의 인증된 동승 대상 구성을 다시 확인한다.
- 일반 파일럿·기체 삭제 UI/API는 현재 없다. 삭제 기능을 새로 만들지 않았다. 구조 수리에서 일반 표시 목록에 #399가 없다는 이유로 유효한 ALICE를 지우지 않으며, 대상 기체가 수리로 제거돼도 ALICE의 SP·진행을 자동 삭제하지 않는다. 모호한 ALICE 연결은 수리를 중단한다.

화면은 `저장 선택 → 파일럿 탭 → ＋ 파일럿 추가` 및 `저장 선택 → 보유 기체 탭 → ＋ 기체 추가`를 안내한다. 대상 기체 추가 후 자동 준비 수와 실제 게임에서 인간 파일럿을 탑승시켜야 한다는 알림을 표시한다. 일반 기체 추가에는 ALICE 알림을 붙이지 않는다.

## 기존 런타임과의 관계

원본 고쇼군의 신고→레미→키리와 ALICE 모두 12바이트 파일럿 행과 다음 동승자 연결을 이용한다. ALICE는 자유롭게 갈아타는 일반 주파일럿이 아니다. 다만 현재 저장되는 연결은 인간 주파일럿의 동승자 체인이며, 기체에 ALICE 소유권을 영구 저장하는 방식은 아니다.

Final은 `aliceCrewCode()`의 현재 multi-form 코드, F는 Fv2의 설치된 코드를 조사했다. Fv2의 앞 876바이트는 F 개발 템플릿과 동일함을 검사한다. 기존 행의 재사용·중복 방지·SP 보존은 실제 생성된 SH-2 바이트를 실행하는 합성 VM에서도 검사한다. VM은 원본 게임 명령을 포함하지 않으며, allocator/SP 초기화 호출만 제한적으로 대체한다.

파일럿 행의 `+8`은 다음 동승자, `+9`는 기력, `+10..11`은 big-endian SP16이다. 초기 합성 검수에서 기력 바이트를 SP로 잘못 부른 부분을 수정했고, 255보다 큰 SP도 검사한다. 새 ALICE는 SP 초기화 함수를 호출하고 인간의 **기력**만 별도로 복사한다. 인간의 SP를 복사하지 않는다.

합성 실행에서는 두 인간을 S/Ex-S 사이에서 교환해도 기존 ALICE 체인/SP가 인간 쪽에 남는다. F에서도 웹 출력에서 실제 탑승시킨 상태의 복사본에 ALICE SP만 9/17로 구분한 뒤, 원래 게임의 갈아타기로 아무로를 S→Ex-S, 화를 Ex-S→S로 옮겼다. 아무로의 ALICE/SP9와 화의 ALICE/SP17이 각각 인간을 따라 남았다. 이 수치는 구분용으로 준비했으며 실제 정신기 사용으로 소모한 값은 아니다. Final의 같은 교환은 합성 실행까지만 확인했다.

현재 동작을 유지하면 기존 세이브의 인간 체인과 SP를 보존한다. 기체별 고정 소유권으로 바꾸려면 별도의 소유 키 또는 안정적인 귀속 규칙, 변형 계열, 기존 체인/대기 행의 이전 및 SP 귀속 정책이 필요하다. 어느 기체에 이미 소모한 SP를 남길지도 정해야 하므로 이번에는 저장 호환성을 바꾸는 그 설계 변경을 하지 않았다.

- **정적/합성:** F·Final 자동 준비, 변형 계열, 인증 위조/상실, 부족 칸의 원자적 거부, 기존 행 전체 보존, 인간 동승자 체인, 파일럿 0번 칸, 모호한 연결, 내보내기/재열기, UI 알림을 검사했다. 실제 생성된 동승 코드의 합성 실행은 별도 테스트다.
