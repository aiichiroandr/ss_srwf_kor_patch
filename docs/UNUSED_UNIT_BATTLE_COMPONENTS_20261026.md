# 미사용 기체 5종의 전투 부품·손 좌표 보정 (2026-10-26)

로컬 웹 에디터에 통합했다. 사용자가 자신의 ROM에서 미사용 기체를 구성하면 미리보기와 BIN 저장에 함께 적용한다. 이미 구성한 개인 BIN도 재열기에서 보정 필요 여부를 읽고 다음 미리보기·저장에 반영한다. v0.4 번역 조립기와 승인 배포물은 변경하지 않았다. 공개 JS/WASM 전투 실행 파일도 바꾸지 않았다.

## 서로 다른 두 원인

**총·오라소드 부품 누락:** `C_ROBOT.BIN`의 본체 이외 부품이 자리표시자로 남아 있었다. 같은 계통의 기존 부품을 연결하고 각 본체의 손 위치에 맞게 그림 기준점을 보정한다.

| 기체 / 전투 그림 | 부품 연결 | 복사 원본 대비 기준점 ΔX, ΔY |
|---|---|---|
| S건담 #305 | 자기 부품 2의 스마트건을 부품 3에도 연결 | −4, −4 |
| Ex-S건담 #306 | S건담 부품 2 → 부품 3 | −3, −10 |
| 서바인 #308 | 단바인 #41 부품 2 → 부품 2 | +23, −2 |
| 즈와우스 #309 | 단바인 #41 부품 2 → 부품 2 | +21, −5 |
| 블러드 템플 #302 | 자기 부품 3의 총 유지 | 변경 없음 |

기준점은 화면 좌표가 아니다. 양의 기준점 변화는 그림을 왼쪽/위로 옮긴다. 본체의 픽셀·팔레트·크기·기준점은 보존한다. 서바인과 즈와우스의 검을 단순 복사했을 때 몸통에 걸리던 배치도 따로 보정했다.

**S·Ex-S 빔사벨 누락:** 일반 빔사벨은 위의 C_ROBOT 검 부품을 그리지 않는다. 정상 건담과 같은 연출 #282를 쓰면서도 검이 보이지 않아 원래 부품을 유지한 BIN과도 대조했다. 완결편 `06038FFC`는 BTSR의 32개 부착 좌표 목록에서 **기체 레코드 번호(전투 상태 +10)** 를 찾는다. 새 기체 번호가 없으면 목록 끝의 `FFFF 00 50`을 사용한다. 이 경우 검 효과의 상대 위치가 `(0, 80)`이 되어 화면 아래로 내려간다. 단순히 ‘원래 베기 효과만 있는 연출’로 분류하면 틀린다.

이 표의 목록 9에 구성된 기체 번호를 넣는다. 그림 번호를 기체 번호로 대신 쓰지 않는다.

| 프리셋 | 손 좌표 X, Y (본체 기준) |
|---|---|
| S건담 | −25, −20 |
| Ex-S건담 | −26, −14 |
| 서바인 | −24, −11 |
| 즈와우스 | −22, −8 |
| 블러드 템플 | −20, −21 |

좌표는 본체 이미지의 손 중심과 본체 기준점의 차이로 계산했다. 기존 게임 함수가 이동·좌우 방향을 처리한다. 검·손잡이 확대와 정상 기체 비교 프레임으로 확인했으며, 모든 연출의 모든 회전 프레임을 정밀 측정했다는 뜻은 아니다.

## 저장과 원본 인증

- `editor-battle-components.mjs`: 사용자가 가진 원본 압축 기록을 모두 보존하고 완전히 같은 기록만 공유한다. 새 부품 기록과 짧은 원본 길이 기록 `SRWBCP01`을 기존 C_ROBOT 파일 안에 넣는다. F 633,327B / 완결편 652,842B의 파일 크기와 CD 위치를 유지한다. 다섯 기체 구성 시 남은 파일 내부 공간은 F 1,175B / 완결편 1,149B다. 개별 압축 해제 그림은 `0x3000` 예약 범위를 넘으면 거부한다.
- TSR root 1은 C_ROBOT 주소표의 사본이다. 둘을 같은 저장 계획으로 갱신한다. 첫 비공개 시험에서 사본 갱신을 빠뜨려 검은 사각형이 나온 실패가 있었으며, 종료 표식만으로 그림 정상 여부를 판정하지 않는다.
- `editor-battle-handpoints.mjs`: BTSR의 원래 부착 좌표 구간(F 75,254..77,549 / 완결편 75,409..78,256) 안에서만 재배치한다. 똑같은 빈 목록을 공유해 공간을 확보한다. 원래 모든 좌표 항목과 기본값을 유지하며, 헤더 셀 80이 참조하는 기존 내부 항목도 새 위치에 맞춘다. 다섯 기체 추가 후 남는 공간은 두 게임 모두 8B다. 더 넣어 기존 구간을 넘으면 저장 전에 거부한다. TSR 여유와 별개의 예산이다.
- 재열기에서는 추가 기록을 제거하고 두 파일을 각각 정확한 원본으로 재구성해 고정 SHA-256을 검사한다. 허용한 보정으로 다시 만든 결과와 수정 파일의 **모든 바이트**도 대조한다. 이후 기존 디스크·TSR 불변 해시를 그대로 검사한다. 부품/손 좌표의 기체 번호·프리셋은 인증된 기체 구성 기록과도 대조한다. 출처 마스크를 넓혀서 통과시키지 않는다.
- 기존 기체만 있는 이미지에 아무 편집도 하지 않으면 파일은 바뀌지 않는다. 보정 후 BIN도 아무 변경 없이 재저장하면 같은 SHA와 변경 0B를 유지한다. 요청·JSON에 임의 픽셀이나 자유 주소 패치를 받는 기능은 없다.

## 확인 범위

- 실제 F v0.5 / 완결편 v0.3c에서 다섯 기체를 한 번에 구성해 출력·재열기·무변경 재저장을 확인했다. C_ROBOT 주소표와 TSR 사본 일치, 동일 CD 파일 위치/크기도 확인했다. F의 기존 설치기 꼬리는 보존하며 지속 데이터 한도를 새로 늘리지 않는다.
- 완결편 네이티브 전투 포트의 기존 시연 진입점을 headless로 사용한다. 처음부터 플레이하거나 BIOS/타이틀 콜드부트를 하지 않는다. 제안 무장 22칸에서 중복 인컴과 MAP 버스터런처를 제외한 20개 기체/무기 조합을 확인한다. 공격 종료 표식과 실제 확대 화면은 구분해 기록한다.
- 기존 공통 빔 연출은 총을 든 화면에서 적 화면으로 전환한 뒤 빔이 들어온다. 총을 맞추기 위해 적 피격 좌표나 전체 기체 본체를 옮기지 않았다. 버스터런처 #785는 원래 MAP 병기여서 일반 연출 0을 임의의 공격으로 바꾸지 않았다. 화염 #522와 인컴 등은 여전히 기존 연출의 응용이며 전용 삭제 연출을 복구했다고 하지 않는다.
- 실제 수정 BIN을 로컬 웹 에디터에서 열어 S·Ex-S 빔사벨과 서바인 오라소드의 웹 실행 화면도 확인한다. 새 선택의 준비 중에는 이전 실행 프레임 번호를 지워, 이전 화면을 새 기체의 실행 결과로 읽지 않게 했다.
- 부품·좌표 원본 복원, 다른 기체/본체 보존, 범위·공간 초과, 데이터/원본/패딩 변조 거부 테스트를 추가했다. 전체 Node 결과는 1,477 통과 / 108 건너뜀 / 실패 0이다. 정적 파일 검사도 통과했다. 이는 전체 자연 플레이나 모든 전투 방향을 검증했다는 주장은 아니다.

비공개 재현 스크립트와 캡처·보고서는 무시된 `build/unused-battle-20261026/`에 둔다. `build-production.mjs`는 실제 에디터 출력으로 임시 CoW BIN을 만들고, `run-production-native.py`는 20개 무장을 직접 실행한다. `integration-check.mjs`는 F/완결편 출력·재열기를 확인하며 전체 BIN을 저장하지 않는다. 추출 게임 자산·BIN·CUE는 공개 파일에 포함하지 않는다.


## 인컴·어깨포 발사 기준점 조사 (2026-10-26)

완결편 네이티브 포트의 기존 전투 시연 진입점에서 원본 도벤울프 #119로 #470·#474·#475를 직접 재생하고 `06038FFC` 진입의 읽기 전용 로그를 확인했다. 타이틀/BIOS 콜드부트는 하지 않았다. 진단 코드와 네이티브 실행 파일은 조사 후 원상 복구했다. 공개 JS/WASM은 바꾸지 않았다.

목록 0의 조회가 곧 탄환 발사라는 뜻은 아니다. 같은 게임 함수가 연출 오브젝트를 배치할 때 쓰는 상대 기준점이며, 호출 시점과 대상 오브젝트를 구분해야 한다. #470·#475는 몸체/총 배치 이후 다른 목록을 조회하지만 인컴은 같은 두 번째 조회를 하지 않는다. 손 좌표 목록 9만 고치는 것으로 셋을 모두 맞출 수 없다는 근거다.

기체 번호별 항목을 해당 목록에 추가하면 위치를 고려한 보정이 가능한 구조다. 그러나 현행 다섯 기체의 손 보정 뒤에는 BTSR의 인증된 구간에 8B만 남는다. 단순 추가로는 두 항목까지만 가능하므로 전용 기준점을 모두 넣기 전에 원래 좌표/기본값을 보존하는 별도 배치 계획이 필요하다. 현재 구현에는 새 어깨포·인컴 좌표를 적용하지 않았다. 인컴 사출 기준점과 단말의 이동/리플렉터 빔 반사 궤적도 서로 다른 작업이다. 후자는 기존 모션의 별도 수정이 필요하며 복원 완료로 표시하지 않는다.
