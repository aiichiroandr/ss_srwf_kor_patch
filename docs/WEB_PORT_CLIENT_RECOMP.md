# 브라우저 내 변환 방식 웹 포트 설계

상태: **설계와 시제품 단계 (2026-11-03).** 공개 사이트에는 플레이어가 없습니다.
다시 공개하려면 아래 조건을 모두 갖춘 뒤 사용자의 별도 승인이 필요합니다
(`AGENTS.md` "WEB PORT trial ended").

## 1. 왜 바꾸는가

종료한 시험판(2026-10-21)은 개발 PC에서 F 완결편 실행 파일을 C++로 정적
재컴파일하고, 그것을 Emscripten으로 컴파일한 `saturn.wasm`을 공개 서버에
올렸습니다. 그래서 게임 데이터는 없어도 **게임 프로그램의 번역본**을 배포하는
구조였습니다. 함수 3,168개로, 실행 파일 758,232바이트 중 명령어 약 27만 개에
해당합니다.

새 구조의 원칙은 패치(`.srwfp`)와 같습니다. **서버는 도구만 주고, 게임에서
나온 결과물은 사용자 기기 안에서만 만듭니다.**

## 2. 경계: 무엇을 어디에 두는가

| 구분 | 공개 서버 (이 저장소) | 사용자 브라우저 |
|---|---|---|
| 범용 런타임 (VDP1/VDP2/SCSP/CD 블록/SMPC/BIOS HLE) | 허용. 게임 모듈 0개로 빌드한 wasm과 그 전체 소스 | — |
| SH-2 → wasm 변환기 | 허용. 게임과 무관한 JS | 실행 |
| 게임 실행 파일·오버레이 | **금지** | 사용자 디스크에서 읽음 |
| 번역된 게임 코드 (wasm) | **금지** | 생성·실행. 캐시는 사용자 기기에만 두고 사용자가 지울 수 있음 |
| 게임별 메타데이터 (함수 시작 주소, 모듈 기준 주소·크기·CRC32) | 숫자 사실만, 에디터 프로필과 같은 수준으로 검토 후 허용 여부 결정 | 사용 |
| 게임별 어댑터 (설치기 확인, 인터미션 연결 등) | 주소·상수 수준만. 명령어 바이트, 디스어셈블리, 텍스트 금지 | 사용 |

함수 시작 주소 목록조차 두지 않는 편이 가장 깨끗합니다. 변환기가 진입점부터
호출을 따라가며 함수를 찾고, 실행 중 처음 만나는 주소는 그 자리에서
번역합니다(지연 번역). 메타데이터는 이 방식으로 성능이나 정확도가 부족할 때만
보조로 검토합니다.

## 3. 브라우저 쪽 흐름

1. **디스크 선택:** 기존 패처의 검증을 그대로 씁니다. 스톡 원본이나 승인된
   F 완결편 v0.3 c 이미지만 받고, 해시가 다르면 거부합니다.
2. **실행 파일 읽기:** 디스크 ISO9660에서 실행 파일(루트 파일 `0`, 적재 주소
   0x06004000)과 상주·저수준 모듈 이미지를 읽고 CRC32를 확인합니다.
3. **번역:** 진입점부터 함수를 찾아 SH-2를 wasm으로 번역합니다. 함수들을
   하나의 모듈에 모아 서로 직접 호출하게 하고, 모르는 주소는 런타임 디스패처로
   보냅니다.
4. **컴파일:** `WebAssembly.compile`로 컴파일합니다. 사파리를 포함한 브라우저
   엔진이 직접 컴파일하므로, 앱에서는 막힌 아이폰에서도 동작합니다.
5. **캐시:** 번역된 바이트를 디스크 해시와 변환기 버전을 키로 사용자 기기의
   OPFS/IndexedDB에 둡니다. 서버로는 보내지 않습니다.
6. **실행:** 범용 런타임에 메모리와 함수 테이블을 공유해 연결합니다.

## 4. 런타임 쪽 변경 (소유자 빌드 저장소에서)

- 게임 모듈 0개 빌드: 상류 테스트에 모듈 없는 빌드(`no_modules`)가 이미
  있습니다. 공개 런타임은 이 형태로만 빌드합니다.
- 동적 등록 API: 브라우저가 만든 함수들을 런타임의 주소 → 함수 조회에
  등록합니다. wasm 함수 테이블을 공유하는 방식입니다.
- 호출 규약: 레지스터 파일 위치, 느린 메모리 경로(MMIO), 폴링, 태스크 전환,
  BIOS 호출, 프로그램 재시작을 import/export로 노출합니다.
- GPL: VDP1 GPL 옵션을 켜면 런타임 전체가 GPL이 되고 전체 소스를 함께 내야
  합니다. 게임 코드가 없으므로 문제없습니다.

## 5. 시제품 결과 (`lab/sh2-wasm/`)

### 2026-11-03 (2차): 런타임 호출 규약 호환, 지연 번역

- **호출 규약:** 번역된 함수가 런타임의 기존 재컴파일 함수와 같은 규약을 따릅니다.
  - CPU 상태 구조체 배치(r0–r15, T/S/Q/M/IMASK, GBR, VBR, MACH/MACL, PR, PC,
    안전 지점 예산)가 런타임 헤더와 같습니다.
  - 작업 RAM 두 개(0x00200000, 0x06000000, 캐시 우회 미러 포함)는 직접 읽고 씁니다.
    그 밖의 주소는 런타임의 입출력 함수로 보냅니다.
  - 레지스터 호출, 안전 지점, `trapa`는 런타임 함수를 부릅니다. 호출 뒤에는
    복귀 주소를 확인하고, 맞지 않으면 즉시 빠져나갑니다(비정상 복귀).
- **지연 번역:** 처음 호출되는 주소를 그 자리에서 찾아 번역합니다. 그 함수가
  `bsr`로 부르는 함수들은 한 모듈로 묶어 서로 직접 호출하게 합니다. 기존 변환기의
  함수 목록이나 탐색 규칙이 필요 없고, 서버에 게임별 함수 주소를 둘 필요도
  없습니다. `jmp @Rn`(점프 테이블)은 런타임을 거친 꼬리 호출로 처리합니다.
- **명령 범위:** 종료한 시험판 빌드가 번역했던 명령 형태 126종을 모두 해석하고
  번역합니다. 지원하지 않는 명령(`rte`, `sleep`, `braf`, `cmp/str` 등)이나 지연
  슬롯 안의 PC 상대 명령은 번역하지 않고 예외를 냅니다. 이 형태 목록은 예전
  생성 코드의 명령 이름을 센 통계로만 얻었고, 그 코드를 저장소에 옮기지 않았습니다.
- **검증:** JS로 만든 런타임 대역(`harness.mjs`)에서 번역본을 실행하고,
  전체 프로그램 참조 인터프리터와 비교했습니다. 레지스터, SR 필드, GBR,
  MACH/MACL, PR, 두 작업 RAM, 입출력·trap 기록이 모두 일치했습니다.
  - 손으로 짠 프로그램 8종: 재귀, 리터럴 풀 호출, 64비트 캐리 연산, 나눗셈,
    곱셈·누산과 포화, GBR·입출력, SR, 점프 테이블, 비정상 복귀
  - 무작위 다중 함수 프로그램 300개
  - 안전 지점은 인터럽트처럼 동작하게 해서(문맥 저장, 뒤섞기, 복원) 레지스터를
    메모리에 내려 두지 않은 버그가 드러나게 했습니다.
  - 일부러 버그를 넣은 변환기 6종(호출 뒤 재적재, 안전 지점 전 저장, `div1`,
    `mac.l` 포화, 복귀 확인, 바이트 입출력 마스크)은 모두 테스트에서 걸러졌습니다.
  - 무작위 테스트가 실제 버그 하나를 찾았고 고쳤습니다. 지연 슬롯의 `div1`이 분기
    대상을 담은 임시 변수를 덮어쓰던 문제입니다.
- **측정 (Node 22, 클라우드 서버 CPU, 합성 코드, JS 런타임 대역 경유):**

  | 항목 | 결과 |
  |---|---|
  | 재귀 fib(22), 호출 약 5.7만 회 | 약 2 ms (호출 1회당 약 40 ns) |
  | 정수 연산 루프 100만 회 | 약 4 ms |
  | 명령 2만 개짜리 함수 | 번역 45–52 ms, wasm 158 KB, 컴파일 1 ms 미만 |

  실제 게임 속도를 뜻하지 않습니다. 실제 런타임(그래픽·소리·CD), 인터럽트, 두
  CPU 동기화가 빠져 있고, 종료한 시험판의 Emscripten 최적화 빌드와도 비교하지
  못했습니다.
- **한계:** 참조 인터프리터는 SH-2 설명서와 런타임 헤더(`div1`, `mac.l`, `mac.w`)를
  따라 이 시제품과 함께 작성한 것입니다. 그래서 일치는 "번역 = 인터프리터"를
  보여 줄 뿐, 하드웨어나 기존 변환기(`sh2emu`)와 같다는 증명은 아닙니다. 그
  확인은 M2에서 실제 런타임과 디스크로 합니다.

## 7. 단계

1. **M0 (완료):** 이 설계, 첫 변환기 시제품, 차등 테스트, 합성 벤치마크.
2. **M1 (완료, 범위 변경):** 처음 계획은 기존 변환기의 함수 탐색 규칙을 옮기는
   것이었습니다. 대신 지연 번역을 도입해 그 일이 필요 없어졌습니다. 런타임 호출
   규약 호환, 명령 126종, 다중 함수 차등 테스트를 마쳤습니다.
3. **M2:** 런타임을 게임 모듈 0개로 빌드하고, 다음을 추가합니다.
   - 주소 → 함수 테이블 조회에 동적 등록 항목 더하기
   - `sh2_call_unknown`과 `sh2_program_start`에서 즉시 종료하는 대신 JS 번역기를
     부르고 다시 조회
   - 작업 RAM 위치와 서비스 함수 내보내기, 함수 테이블 확장 허용
   - 합성 디스크(직접 만든 IP.BIN과 시험 프로그램)로 부팅 확인 후, 소유자
     기기에서 실제 디스크로 타이틀 화면까지 부팅
4. **M3:** 성능을 맞춥니다. 레지스터 지역 변수 범위 축소, 메모리 빠른 경로 인라인,
   예산 감소를 지역 변수로, 큰 묶음 번역과 기기 캐시를 적용합니다. 종료한 시험판과
   같은 장면에서 프레임 시간을 비교하고, 갤럭시와 아이폰 실기에서도 측정합니다.
5. **M4:** 공개 게이트(아래)를 통과하고, 사용자 승인을 받은 뒤 배포합니다.

## 8. 공개 게이트 (다시 열 때 `scripts/verify_repo.py`에 추가할 것)

- **런타임 wasm:** 크기와 SHA-256을 고정합니다. 게임 모듈 표가 비어 있어야 하고,
  게임 모듈 이름 문자열(예: `SRWFIN`)이 없어야 합니다. 공개 소스에서 재현
  빌드한 결과와 같아야 합니다.
- **소스:** 공개 소스에 정적 재컴파일 결과(`generated/`)가 없어야 합니다. 지금의
  정적 재컴파일 표지 검사를 그대로 유지합니다.
- **변환기·어댑터:** 게임 바이트, 디스어셈블리, 게임 텍스트가 없어야 합니다.
  게임별 숫자 메타데이터는 항목별로 검토합니다.
- **사용자 기기 캐시:** 서버 전송 경로가 없어야 합니다. 정적 사이트 규칙상
  네트워크 쓰기는 이미 금지되어 있습니다.
