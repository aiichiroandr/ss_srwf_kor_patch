# ALICE 서브파일럿 — 로컬 완결편 v0.3c

기존 인간 주파일럿을 유지하고 Ex-S건담↔G크루저의 서브파일럿으로 ALICE를
동승시킨다. 이름·40×40 초상 등록에 이어 실제 승무원 연결, 여섯 정신기와
독립 SP, 양방향 변형, 게임 세이브 및 새 프로세스의 이어하기를 검증했다.
지원 기반은 승인 완결편 v0.3c
`0fb10cbf4332f94c865c0e8d0a0c7234f8f6083bdbbb5a06198cebff871d195d`다.
v0.4 검수 자료나 F에 같은 호환성을 주장하지 않는다.

## 에디터 사용

1. 로컬 에디터에서 지원 BIN을 연다. 기체 추가에서 Ex-S·G크루저 변형 한 쌍을 준비한다.
2. 새 Ex-S 쌍은 ALICE 등록·동승이 자동으로 켜진다. 파일럿 목록의 ALICE에서 변경한다.
   이미 등록한 ALICE 설정이나 사용자가 명시적으로 바꾼 동승 선택은 덮어쓰지 않는다.
3. 지원 정신기 여섯 개, 각 습득 레벨, SP 기본값을 편집하고 BIN을 저장한다.
4. ALICE 대응 로컬 웹 실행기 또는 해당 코드로 빌드한 Mac 네이티브 호스트를 사용한다.

원본 BIN의 ALICE 연결은 OFF다. 2026-10-27 로컬 후보부터 새 Ex-S 쌍을 만들면
기본 동승을 적용하며, S건담 쌍에는 연결하지 않는다. 새 쌍을 취소하면 자동 적용만
원복한다. 이후 사용자가 정신기·SP를 바꿨다면 그 값은 남기고 동승만 해제한다.
기체를 조종하는 인간은 기존 게임의 배정을 따른다.
처음 동승할 때 ALICE의 레벨을 주파일럿에 맞추고 원래 게임의 성장·SP 계산으로
초기화한다. 같은 출격 중 재조회·변형·재연결은 소비한 SP를 회복시키지 않는다.
이름·초상 또는 동승 해제를 저장하고 재열 수 있고, 다시 등록한 BIN도 검증한다.

기본 정신기는 정찰·집중·필중·번뜩임·교란·각성, SP 기본값은 25다.
이것은 사용자가 바꿀 수 있는 지원용 제안이며 원작에서 추출한 ALICE 고유 능력표가
아니다. 정신기 비용과 효과는 원래 게임이 계산한다. 이번 네이티브 시험에서는
Lv50 최대 SP101, 번뜩임15 사용 후86, 저장·새 프로세스 로드 후86,
집중15 사용 후71을 확인했다. 주파일럿 아무로의 SP105는 계속 같았고,
아무로/G크루저 상태창에 번뜩임과 집중이 함께 표시됐다.

예전 번들 WEB PORT/무장 미리보기 호스트에는 새 실행 코드 모듈이 없다.
2026-10-27 로컬 호스트는 자체 ALCCREW2 코드만 추가하고 원래 EXEC 함수 표는
재사용한다. 실제 선택한 manifest의 `aliceCrew: true`를 확인하며, 구 모듈을
일반 미리보기로 먼저 컴파일했어도 ALICE용 모듈과 혼동하지 않는다. 구 모바일
호스트는 ALICE 지원 데스크톱 호스트로 전환하며, 미지원 호스트로 실행하지 않는다.
이는 완결편 v0.3c 지원이며 v0.4 지원을 뜻하지 않는다.
세이브 호환 검사는 실행 없이 실제 편집 결과를 생성·재검사하므로 ALICE가
켜져 있어도 가능하다. 이 데이터 검사를 웹 게임 실행 지원으로 간주하지 않는다.

웹 어댑터는 IP의 1,024B 예약 영역·서명·패딩과 67개 호출 리터럴을 확인한다.
동적으로 바뀌는 두 기체 번호만 허용하고, 나머지 EXEC는 실제 RAM을 바꾸지
않은 채 원래/설치 후 CRC로 확인한다. 등록한 자체 코드 네 진입점만 연결하며
임의 SH-2 코드를 해석하거나 파일럿 동승을 건너뛰지 않는다. 일반 모듈을
ALICE 코드로 오인하지 않도록 OFF 경로도 검사한다.

자체 C++와 SH-2 참조 실행기를 같은 RAM·레지스터에서 비교했다. 두 기체
번호쌍의 동승·재조회·변형·SP 보존·인간 승무원 보존·풀 고갈 등 19개 실행,
식별 포함 24개 정상 사례와 82개 변조 거부를 확인했다. 검증은 콜드부트나
모든 시나리오의 장시간 진행을 뜻하지 않는다. 소스와 재현 명령은 각 새 호스트의
대응 소스 압축 안 `tools/ALICE_CREW_BUILD.txt`에 포함한다.

## 저장 형식과 실행 코드

새 파일럿은 빈 #399, 새 초상은 FACE #342다. 인간 파일럿을 덮어쓰지 않는다.
이름·초상의 기존 `SRWALC01` 출력도 읽고, 동승 설정은 가역적인 `SRWALC02`에
전체 37바이트 파일럿 레코드와 여섯 (정신기, 레벨) 쌍, SP 기본값, 변형 기체 번호를
저장한다. 초상과 TSR root2 주소표 미러는 함께 검사한다.

새로 작성한 SH-2 코드 656바이트를 IP의 예약 영역 0x1300..0x16ff에 두고,
EXEC의 확인된 호출 리터럴 67셀만 바꾼다. 부분 설치, 코드·패딩·서명 변조,
다른 원본 및 TSR 설정과 실행 코드의 불일치는 거부한다. 정확히 원복한 뒤
기존 전체 디스크 출처 검사를 실행하며 불변 해시 마스크를 넓히지 않는다.

원래 게임의 파일럿 할당기와 SP 초기화 함수를 사용한다. 기존 인간 승무원
연결을 보존하며, 단 하나의 활성 Ex-S·G크루저 구성에만 붙인다. 파일럿 공간이
가득 차면 인간을 덮어쓰지 않는다. 기존 다른 주파일럿으로 연결을 옮기는 경우,
기체 이탈과 재연결, 마지막 슬롯127도 원래 SH-2 명령 실행기로 확인했다.

AQ03 용량 확인 코드와 ALICE 코드는 별도 예약 영역을 쓰며 함께 정규화한다.
승인 a의 EXEC 해시는 `17c8bbf0…`, 승인 b/c는 `2b17a510…`여서 정확한
기반별 해시를 구분한다. 관련 없는 실행 파일 바이트는 계속 거부한다.

## 네이티브 호스트 재현

읽을 수 있는 새 코드 소스는 `scripts/build_alice_crew_code.py`다.
다음 명령은 게임 바이트 없이 자체 코드와 라벨만 생성한다.

```sh
python3 scripts/build_alice_crew_code.py --out build/alice-code --exs 430 --cruiser 431
```

Mac 정적 재컴파일 호스트는 디스크의 실행 명령을 C++로 옮기므로 BIN의
호출 대상만 바꾸는 것으로 새 함수가 생기지 않는다. 사용자의 출력에서 얻은
EXEC 원시본·한글 설치 후 실행본을 호스트 모듈로 다시 생성하고, 위 코드의
별도 모듈을 base0x06003300, seeds0x06003300/0x06003306으로 추가한다.
두 EXEC 모듈에는 원래 꼬리 호출 대상0x06053560/0x0602CBD0도 seed로 유지한다.
기존 설치기·resident·low 모듈과 어댑터는 각 로컬 프로젝트의 것을 재사용한다.

로컬 `native.toml`의 경로를 준비한 뒤 그 프로젝트의 Python 환경으로
`python -m saturnrecomp.build /absolute/path/native.toml --recompile`을 실행한다.
새 호스트는 `--cue /absolute/path/output.cue --save /absolute/path/copy.bin`으로
사용한다. 호스트·디스크·실행 파일·세이브 및 게임 픽셀은 공개 저장소에 넣지 않는다.

## 실제 검증과 한계

비공개 재현 근거는 `build/alice-subpilot-20261026/`에 보관한다.

- `crew-report.json`: 실제 지원 BIN에서 저장·영수증 없는 재열기·무수정 출력,
  기존 Ex-S/G크루저 능력과 무장 보존.
- `lifecycle-report.json`: 동승 해제, 이름·초상 등록 해제, 재등록의 저장·재열기.
  다시 켠 출력은 기존 동승 BIN과 전체 해시까지 같다.
- `capacity-composition-report.json`: AQ03과 동승 코드 동시 설치·재열기·무수정 출력,
  용량 코드만 해제한 정확한 원복, 관련 없는 EXEC 변조 거부.
- `browser-report.json`: 실제 저장 BIN의 1440/390/320px 화면, 정확한40×40초상,
  여섯 정신기·SP 입력 유지, 등록 해제·재등록 및 오류·넘침 검사.
- `crew-emu-report.json`: 원래 SH-2 할당기/SP 계산을 포함한9가지 경계·연결 사례.
- `native-normal-trace/`: 타이틀의 이어하기 → 실제 게임 정신기/변형 → 메뉴 저장.
  이 호스트는 저장 함수 호출을 기록하는 비공개 진단 빌드다. 복사 세이브 삭제용
  시험 명령도 있으나 이 검증에서는 호출하지 않았다. 용량이나 게임 RAM을 바꾸지 않았다.
- `native-final-proof/native-proof.json`: 진단 명령이 없는 일반 네이티브 호스트를
  새로 실행하고 위 게임 세이브만 로드했다. RAM 쓰기와 스냅샷 없이 승무원·SP86,
  양방향 변형, 이후 집중 사용 SP71과 인간 기체의 정신기 상태를 확인했다.

시작 세이브는 원본의 복사본으로 만든 시험 배치다. ALICE는 그 세이브에서
인간을 치환한 것이 아니라 출력 BIN의 동승 코드가 추가했다. 정상 시나리오에서의
장시간 진행, 모든 인간 파일럿 조합, 다른 기체·다른 게임 버전까지 검증한 것은 아니다.
일반 게임 세이브와 프로세스 재시작 검증은 에뮬레이터 스냅샷 로드와 구분한다.

앞서 메뉴 초기화를 건너뛴 임시 GOTO 시험은 저장 용량 정보가 초기화되지 않아
저장 판정 근거에서 제외했다. 또한 두 줄 정신기 메뉴에서 DOWN으로 사용한 첫
명령은 집중이 아니라 번뜩임이었다. 정상 로드 후 RIGHT로 집중을 별도로 골라
설명문·독립 SP 감소·인간 기체의 적용 상태를 확인한 근거를 사용한다.


## 2026-10-30 실제 에뮬레이터 결함 수정

사용자의 F·제4차 연동 v0.4 개인 BIN과 mc4/5/6에서 ALCCREW3의
RAM0x06003300..0x06003317이0으로 된 상태를 확인했다. 기존 호출은
0x06003300/306으로 진입해 SH-2 예외 루프0x06000956에 빠졌다.
이 prefix를 지우는 정확한 쓰기 주체는 아직 특정하지 않았다.
기존 네이티브 통과는 이 RAM 상태를 재현하지 않았으므로 이 결함을 검출하지 못했다.

ALCCREW4는 같은 IP0x1300..0x16ff 안에서 앞32B를0으로 예약하고
실행 진입점·내부 replay 주소를32B 뒤로 옮긴다. TSR 공간이나 세이브 형식은
늘리지 않는다. 옛 ALCCREW2/3 BIN도 정확히 읽고 다음 저장 때 새 배치로 바꾼다.
서명·67개 호출·코드·패딩의 정규화 검사는 그대로 유지한다.

동일 상태 비교에서 F 리얼1화 아군9기, 슈퍼1화 마징가1기 생성과 다음 대사를
확인했다. 완결편은 실제 ‘연인이 있습니까?’에서 있음/없음 둘 다 다음 브라이트
대사로 진행했다. 옛 배치를 다시 적용하면 있음 선택 뒤 PC0x06000956,
PR0x0602b810의 예외가 재현됐다. 게임 진행 데이터는 바꾸지 않았다.
맥 네이티브는 실제 수정 BIN으로 하로→완결편→주인공→연인 선택→다음 대사를
입력으로 진행했다. 크리티컬의 기존 표 리터럴과 도감 해금의 기존 반환 명령도
네이티브에서 별도로 인증·반영해야 한다. 장기 플레이 전체 보증은 아니다.
