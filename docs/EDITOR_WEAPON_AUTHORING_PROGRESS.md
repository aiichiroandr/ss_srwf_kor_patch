이는 구조·파일 쓰기 검증이며 실게임에서 무기를 선택·사용한 검증이 아니다.

독립 연출 시험은 양쪽 게임의 기존 선택자 282를 미사용 후보
`057C..057F`의 6,312바이트 pool에 복제했다. 선택자 057C가 새 무기를
담당하고 나머지는 바이트가 같은 원 template을 참조한다. 원래 767개
선택자의 프로그램 내용은 모두 같았다. 복제한 CC 수평 이동값 한 항목을
-16에서 -15로 바꾸고 TSR root6/D_ANIME 디렉터리를 함께 반영한 시험
BIN도 생성했다. D_ANIME의 섹터 6개 변경과 readback을 확인했다.

F 독립 연출 시험 BIN은 MCA가 없는 사적 emulator home에서 cold boot하여
실제 F 타이틀에 도달했다(3605 frames, 49.12초, terminal 0, timeout 없음).
RAM poke·치트 데이터·외부 MCA 없이 사용자 기존 backup의 사본만 사용했다.
이는 신규 무장의 선택·공격이나 수정한 이동값의 게임 내 실행 증거가 아니다.

네이티브 무장 loader의 추가 정적 근거: F `0602DB98..0602DC4C`,
완결편 `0603197C..06031A52`는 320바이트(16×20) work 영역을 비우고,
항목의 상위 slot nibble을 0..15로 mask하여 20바이트 work 위치를 고른다.
무기 번호는 07FF mask 뒤 root29로 전달한다. loop 종료는 F
`0602DBAC..0602DBC2`, 완결편 `06031994..060319AA`의 항목 첫 word=0이다.
실제 game save에서 새 slot의 개조·탄약 저장이 지속되는지는 아직 미검증이다.

## Bounded project 저장과 재열기

`editor-weapon-project.mjs`는 D_ANIME의 마지막 bank에 있는 미사용 후보
`0560..057F`의 동일 template 영역에서만 프로그램을 할당한다. 50,496바이트
중 마지막 4,096바이트는 `SRWFWPN1` 이력이며 프로그램 예산은 46,400바이트다.
최대 24개의 독립 연출을 기록하되 실제 크기가 예산을 넘으면 거부한다.
기존 고유 연출을 지우거나 파일 길이·extent를 늘리지 않는다.

이력은 ACCEPTED 판정이나 쓰기 허가가 아니다. 새 inspector는 각 프로그램을
잠긴 원본 프로그램과 대조하여 검증된 motion 피연산자 외의 변경을 거부한다.
TSR/D_ANIME 디렉터리가 같은지도 먼저 확인한다. 새 무기의 독립 개조·탄약
슬롯과 기존 소유 무기 연결, 이름 참조, 공간 회수 기체를 확인한 다음,
원본 배치와 프로그램으로 정규화해 **기존 pinned immutable TSR 및 전체
디스크 hash**를 통과시킨다. 다른 파일·참조·명령 변경은 숨기지 않는다.
이전에 받은 출력 receipt만으로 범위를 확대하지 않는다.

F v0.5 a 및 완결편 v0.3 c의 실제 입력에서 코어 export로 신규 무기와
수평 이동값을 저장하고 receipt 없이 fresh `imageKind: local`로 다시 열었다.
그 세션에서 두 번째 무기를 추가하고 또 저장·fresh reopen하여 이력 2개와
첫 무기의 공격력 1999가 유지되는 것을 확인했다. 완결편의 두 번째 저장은
ordinary 재압축으로 603바이트를 넘었으므로, authoring 경로에서만 기존
`completeNearMatches` 압축을 추가 시도하여 고정 공간에 맞췄다. 일반 TSR
편집의 기존 압축 선택·증가 거부 규칙은 그대로다.

생성한 ISO/TSR/D_ANIME fixture의 실제 inspector·writer 통합 시험은 반복
편집, 독립 개조/탄약 칸, 원 무기의 연출 복제, 미확인 명령 위조와 TSR
디렉터리/공간 회수 카운터 위조를 확인한다. 사적 실게임 표본은 아직 앞서
기록한 cold/기존 저장 Load 범위이며 신규 무기 선택·공격 증거는 남았다.

## 로컬 UI와 편집값 파일

무기 탭의 `연출 편집`은 확인된 원본 이동 명령을 고른 뒤 이동·좌표·시간
피연산자를 바꾸는 패널이다. 적용은 선택한 움직임만 바꾸며 초기화도 그
움직임만 되돌린다. `무기 추가`는 선택한 무기의 현재 수치와 편집한 연출을
선택 기체의 독립 무장으로 복제한다. 신규 무기만 삭제할 수 있다.

BIN 저장과 편집값 JSON 저장은 입력 중인 연출값도 검증하여 적용한다.
JSON에는 숫자 피연산자와 원본 무기·소유 기체 식별자만 넣는다. 스프라이트나
게임 프로그램은 넣지 않는다. 불러오기는 적용 전에 별도 계획으로 검토하며
취소하면 현재 편집값을 바꾸지 않는다. 다른 편집 이력이 있으면 충돌로 표시한다.

실제 F v0.5 a와 완결편 v0.3 c를 390×844 Edge 화면에서 열고 이동 수정,
무기 추가, 공격력 1999, JSON 저장 및 BIN 생성을 버튼으로 수행했다.
출력 BIN을 다시 폴더로 선택해 이력 2개와 공격력 1999를 확인했다.
320×568과 1440×1000에서도 연출 패널의 가로 잘림을 확인했다.

현재 기능은 원본 연출 복제와 확인된 이동·시간 수치 수정이다. 새로운 무기
이름 문자열, 이미지 제작, 임의 명령·분기 삽입, 전체 연출 타임라인 편집은
지원하지 않는다. 원본 그림 미리보기는 게임의 전투 실행을 재현하지 않는다.

JSON 불러오기 검수에서 동일값 필드가 잘못 저장되는 결함을 수정했다. F와
완결편 모두 원본에 JSON을 읽어 취소하면 이력이 0개로 유지되고, 재불러오기·
모두 적용 후 만든 BIN의 SHA-256이 직접 화면에서 편집한 출력과 일치했다.

## 로컬 게임 실행 표본

현재 export 코드로 F v0.5 a에서 새 빔사벨 #1248, 공격력 1999, 복제 연출
#0560을 담은 BIN을 만들었다. 외부 상태와 RAM 쓰기 없이 냉부팅한 뒤
기존 카트리지 저장을 불러오고 게임의 갈아타기 메뉴로 이노를 건담에 배치했다.
유닛 능력 조회 시 원본 5개와 추가 1개를 게임 로더가 읽었고, 무장 목록에
빔사벨 1999가 표시됐다. 이 표본의 SHA-256은
`e3642ae1d1a5ebfc58dff271de6a73aaa5943d0dc3ea95a1c71d0862e3dca2e7`이다.
이것은 F의 냉부팅·저장 불러오기·무장 목록 표본이며 전투 실행이나 완결편의
런타임 검증으로 확대하지 않는다.

생성 fixture에서 저장한 신규 무기를 삭제하고 다시 저장·재열기하면 원래
압축 해제 TSR 배치와 D_ANIME 프로그램이 바이트까지 복원된다. 압축 스트림
