# 로컬 무기 연출 편집·신규 무기 조사

2026-10-12 진행 기록. 제품 기능 완료·배포·실제 게임 동작의 근거가 아니다.
현재 사용자 화면은 원본 스프라이트 미리보기이며 writer의 웹 입력 UI는 아직 연결하지 않았다.
현재 `prepareEditorWeaponProject → exportEditedImage` 코어 경로와 fresh
inspector 재열기는 연결했다. 웹의 버튼·입력 UI 연결은 아직 남았다.

## 확인한 구조와 구현

- 무기 root29의 +3/+4 BE16 값이 D_ANIME 선택자다. 기존 근거는
  `EDITOR_BATTLE_IMAGE_MAPPING.md`를 따른다.
- D_ANIME은 여섯 bank × 128개의 파일 절대 start/end 쌍을 갖는다.
  레코드 +0은 LE32 46, +4는 LE32 actor 시퀀스 표 위치다.
  시퀀스 표의 BE16 값은 레코드 시작 기준이다. 마지막 셀의 end 또는
  table-self 센티넬은 명령 영역으로 취급하지 않는다.
- `editor-weapon-authoring.mjs`는 기존 네이티브 명령 폭 해석을 공유한다.
  BF/C0의 프레임 참조, CC의 수평 이동값, C9/CA의 signed BE16 좌표·변위와
  duration byte만 같은 길이로 편집한다. F/완결편의 소비자 주소는 각각
  BF `06037E30/0603D0FC`, C0 `06037E50/0603D11C`,
  CC `06038000/0603D2CC`, C9 `06036C40/0603BF0C`,
  CA `06036D74/0603C040`다. 명령 폭이 확인됐다는 이유만으로 다른 피연산자를
  편집 허용하지 않는다.
- 분기 그래프를 따라 명령 경계를 구분한다. 피연산자 안으로 들어가는
  분기·겹침은 거부한다. 미확인 명령·동시 트랙·복합 분기는 해당 경로를
  중단하며 그 뒤의 바이트를 편집 대상으로 추측하지 않는다.
- 별도로 허가된 미사용 연출 슬롯에 원본 레코드를 복제한 뒤 편집하는
  primitive가 있다. 다른 선택자의 물리 영역과 겹치거나 기존 슬롯에
  들어가지 않으면 거부한다. TSR root6 디렉터리 동기화와 개인 출력
  provenance는 아래 bounded project 형식으로 연결했다.
  큰 레코드는 연속된 동일 template 슬롯을 모으는 pool primitive로
  복제한다. 대상 이외의 선택자는 원래와 바이트가 같은 template을
  참조하며, 고유 레코드·물리 중첩·예산 초과는 거부한다.
- `editor-weapon-layout.mjs`의 사적 실험은 미사용 무기 레코드에 기존
  무기를 복제하고, 미사용 기체의 센티넬 무장 4바이트를 회수해 선택
  기체에 추가한다. root27의 총 길이와 다른 root 주소는 유지하고 각
  포인터 셀 자신의 주소를 기준으로 다시 기록한다. 기존 무장은 보존한다.
  슬롯·탄약 배치는 구조 실험이며 게임의 개조·세이브 호환 검증은 남았다.
- F #126의 개수/종료 불일치는 고치지 않는다. 신규 무기 번호가 개수
  기준과 종료 기준 양쪽 경로에 없는지 확인하고 원래 레코드를 보존한다.
- 이름은 기존 이름의 절대 문자열 목표를 새 셀의 상대 포인터로 연결한다.
  임의의 새 이름 입력·문자열 arena 재배치는 구현되지 않았다.

## 실제 승인 이미지에 대한 사적 검증

F v0.5 a와 F완결편 v0.3 c를 사용자 로컬 파일에서 읽었다. 추출 데이터,
시험 BIN·캡처는 저장소에 포함하지 않는다.

| 확인 | F | F완결편 |
|---|---:|---:|
| 소유 무기가 참조하는 서로 다른 연출 레코드 읽기 | 303 | 318 |
| signed 이동값 한 항목 시험 수정·재파싱 | 261 | 268 |
| 원본 D_ANIME 물리 레코드 수 | 768 | 768 |
| 바이트가 서로 다른 레코드 수 | 412 | 422 |
| 완전 동일 레코드의 중복 바이트 | 557,187 | 541,407 |

중복량은 독립 연출 공간을 확보할 수 있는 후보이며 아직 모든 중복을
제거하거나 그 공간을 편집 허용하지 않았다. 미확인 명령이 있는 레코드를
읽었다는 사실은 전체 연출 재생·편집을 지원한다는 뜻이 아니다.

사적 신규 무기 시험은 두 게임의 기체 #1에 빔사벨 레코드를 추가했다.
F 새 무기 #1248/기체 공간 후보 #367, 완결편 새 무기 #1331/기체 공간
후보 #447을 사용했다. 이름과 사용 기체가 새 레코드에 연결됐고,
시험 BIN의 ISO/섹터 검사 및 압축 TSR 재열기가 동일한 편집 데이터를 냈다.
이는 구조·파일 쓰기 검증이며 실게임에서 무기를 선택·사용한 검증이 아니다.

독립 연출 시험은 양쪽 게임의 기존 선택자 282를 미사용 후보
`057C..057F`의 6,312바이트 pool에 복제했다. 선택자 057C가 새 무기를
담당하고 나머지는 바이트가 같은 원 template을 참조한다. 원래 767개
선택자의 프로그램 내용은 모두 같았다. 복제한 CC 수평 이동값 한 항목을
-16에서 -15로 바꾸고 TSR root6/D_ANIME 디렉터리를 함께 반영한 시험
BIN도 생성했다. D_ANIME의 섹터 6개 변경과 readback을 확인했다.

F 독립 연출 시험 BIN은 MCA가 없는 사적 emulator home에서 cold boot하여
실제 F 타이틀에 도달했다(3605 frames, 49.12초, terminal 0, timeout 없음).
RAM poke·치트 데이터·외부 MCA 없이 사용자 기존 backup의 사본만 사용했다.
이는 신규 무장의 선택·공격이나 수정한 이동값의 게임 내 실행 증거가 아니다.

네이티브 무장 loader의 추가 정적 근거: F `0602DB98..0602DC4C`,
완결편 `0603197C..06031A52`는 320바이트(16×20) work 영역을 비우고,
항목의 상위 slot nibble을 0..15로 mask하여 20바이트 work 위치를 고른다.
무기 번호는 07FF mask 뒤 root29로 전달한다. loop 종료는 F
`0602DBAC..0602DBC2`, 완결편 `06031994..060319AA`의 항목 첫 word=0이다.
실제 game save에서 새 slot의 개조·탄약 저장이 지속되는지는 아직 미검증이다.

## 완료 전에 남은 일

1. 미사용 무기·기체·연출 슬롯의 네이티브 참조와 런타임 예산 확인.
2. 추가 연출·프레임 참조 편집 범위 조사. 현재 공개 입력에 허용하는
   연출 필드는 검증된 좌표·이동값·시간이며 프레임 bank/index는 읽기만 한다.
3. 반복 편집·삭제 및 기존 기능과의 최종 회귀 검증.
4. 웹의 추가·삭제·diff·reset·편집값 저장/불러오기·BIN 출력 연결.
5. 모바일/데스크톱 조작 검수, 실제 디스크 출력으로 게임 내 무장 선택과
   공격·명중·회피·방어·격추 동작 검증.

공개 배포와 ACCEPTED 패치·manifest·release index 수정은 범위 밖이다.

## Bounded project 저장과 재열기

`editor-weapon-project.mjs`는 D_ANIME의 마지막 bank에 있는 미사용 후보
`0560..057F`의 동일 template 영역에서만 프로그램을 할당한다. 50,496바이트
중 마지막 4,096바이트는 `SRWFWPN1` 이력이며 프로그램 예산은 46,400바이트다.
최대 24개의 독립 연출을 기록하되 실제 크기가 예산을 넘으면 거부한다.
기존 고유 연출을 지우거나 파일 길이·extent를 늘리지 않는다.

이력은 ACCEPTED 판정이나 쓰기 허가가 아니다. 새 inspector는 각 프로그램을
잠긴 원본 프로그램과 대조하여 검증된 motion 피연산자 외의 변경을 거부한다.
TSR/D_ANIME 디렉터리가 같은지도 먼저 확인한다. 새 무기의 독립 개조·탄약
슬롯과 기존 소유 무기 연결, 이름 참조, 공간 회수 기체를 확인한 다음,
원본 배치와 프로그램으로 정규화해 **기존 pinned immutable TSR 및 전체
디스크 hash**를 통과시킨다. 다른 파일·참조·명령 변경은 숨기지 않는다.
이전에 받은 출력 receipt만으로 범위를 확대하지 않는다.

F v0.5 a 및 완결편 v0.3 c의 실제 입력에서 코어 export로 신규 무기와
수평 이동값을 저장하고 receipt 없이 fresh `imageKind: local`로 다시 열었다.
그 세션에서 두 번째 무기를 추가하고 또 저장·fresh reopen하여 이력 2개와
첫 무기의 공격력 1999가 유지되는 것을 확인했다. 완결편의 두 번째 저장은
ordinary 재압축으로 603바이트를 넘었으므로, authoring 경로에서만 기존
`completeNearMatches` 압축을 추가 시도하여 고정 공간에 맞췄다. 일반 TSR
편집의 기존 압축 선택·증가 거부 규칙은 그대로다.

생성한 ISO/TSR/D_ANIME fixture의 실제 inspector·writer 통합 시험은 반복
편집, 독립 개조/탄약 칸, 원 무기의 연출 복제, 미확인 명령 위조와 TSR
디렉터리/공간 회수 카운터 위조를 확인한다. 사적 실게임 표본은 아직 앞서
기록한 cold/기존 저장 Load 범위이며 신규 무기 선택·공격 증거는 남았다.
