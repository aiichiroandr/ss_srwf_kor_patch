# C7 합류 이동의 최소 경계 재검토

2026-10-23. 기존 C7 초기레벨 제품 기능과 별개인 후속 정적 조사다. 제품 파일·profile·writer를 변경하지 않았으며 콜드부트·에뮬레이터 실행·BIN 출력도 하지 않았다. 승인 F v0.5a 및 Final v0.3a의 실제 SCEDATA와 F 실행 파일 `0`을 메모리에서 읽었다.

## 같은 시나리오에서 닫을 수 있는 부분

**동일 basic block 안에서 생성·삭제·조회·분기 없는 명령 하나만 건너뛰는 이동**은 다른 시나리오로 합류를 복제하는 문제보다 작다. 모든 진입·재개가 그 block의 앞에서 들어오고 사이에 로스터 변경이 없다면 원래 C7의 실행 횟수와 최대 점유를 늘리지 않는 변환으로 만들 여지가 있다. 따라서 모든 이동에 새 allocator와 별도 중복 플래그가 반드시 필요하다고 단정할 수는 없다.

실제 좁은 후보는 F 물리 본문48 / 선택 번호70의 마징가Z(#30)·카부토 코우지(#85) C7이다. **root8=2796, source C7=2845, 초기레벨12**이며 직전 +2842의 `05 00 1E`는 타이머 30회 대기다. 바로 뒤에는 다른 두 C7이 이어진다. 이 C7 뒤에 C1.06/0B 보조 파일럿 묶음은 없다.

05의 승인 F native handler `06017AB0..06017AE4`는 VM 문맥 +72의 timer를 읽고 감소시킨다. 0일 때 인수 두 byte를 진행하는 `D002`를 반환하고, 남은 시간이 있으면 0을 반환한다. 이 함수 자체는 pilot/unit/actor 표를 조회·생성하지 않는다. 따라서 C7을 **직전 타이머 30회 대기 앞으로만** 옮기는 경우를 검토할 수 있다. 반대로 대기 중 native dispatcher/다른 callback이 실행하는 일과 저장 재개점, 정확한 프레임 수까지 이 함수 하나로 증명한 것은 아니다.

더 앞에는 `+2834 D0.02 00E0`, `+2838 F0 00 0057`이 있으며 후자의 목적지는 **+2927**이다. 이 조건은 대기와 C7 묶음을 함께 우회한다. 이동 지점을 이 가드 앞까지 넓히면 원래 진입 조건을 바꾸므로 같은 변환으로 허용할 수 없다. 같은 본문 root4에도 **+2696의 동일 pilot85/unit30/Lv12 C7**이 있다. 따라서 ‘시나리오 안의 같은 pilot/unit은 C7 한 개뿐이고 한 번만 실행된다’는 가정도 틀린다.

현재 native 문법으로 확인한 root8의 local CFG에서는 +2842 대기에서 +2845 C7으로 단일 fallthrough가 이어진다. 다만 다른 root/간접 진입에서 이 창 내부로 들어오는 참조의 전부, 대기의 save/continue·frame scheduling 계약은 아직 닫지 않았다. 이 후보를 제품 기능으로 열지 않았다. 또한 이 짧은 대기보다 이른 생성은 사용자가 원하는 ‘늦게 합류하는 기체를 초반부터 사용’하는 기능의 실질적인 대체가 아니다.

다른 후보인 F 본문35 root4의 C7(pilot77/unit16) 직전 C2.04/C2.0A는 순수 표시 명령이 아니다. 승인 native C2.04 `0602B5B4`는 `0602D1B8`을, C2.0A `0602B93C`는 `0602E914`를 호출하며 기체 생성/처리 경로에 들어간다. 이 구간을 ‘대사만 있는 여백’으로 취급하지 않는다.

## 다른 시나리오로 이데온을 옮길 때의 구체적 차이

두 원래 이데온 합류를 한 bundle로 취급할 수 없다.

| 경로 | 실제 callback과 source | 확인된 최소 생성·연결 묶음 |
| --- | --- | --- |
| 우주 | 본문34 / 선택131, **root2=1975**, C7 **+2606** | C7 pilot218/unit236/Lv50 → C1.06 pilot219/Lv48 → C1.0B 218/219, 합계 **15byte** |
| 지상 | 본문76 / 선택173, **root0=6550**, C7 **+7150** | 같은 C7 → C1.06 pilot219/Lv48 → C1.06 pilot222/Lv50 → C1.0B 218/219 → C1.0B 218/222, 최소 **25byte** |

양쪽 C7 바로 앞에는 **pilot220/unit237/Lv50 C7**이 별도로 있다(본문34 +2601, 본문76 +7145). 이 로스터를 함께 옮겨야 하는지, 원래 시점까지 남겨도 후속 대화·출격·기체 검색이 성립하는지는 아직 별도 계약이다. 지상 경로의 pilot222를 우주 경로에도 무조건 선생성하는 방식은 원래 인물 구성을 바꾼다.

우주 쪽 15byte 뒤 +2621은 `E9 01 FFFE`의 대기 loop다. 여기의 local exit는 source C7으로 돌아가지 않는다. 그러나 전체 root2의 분기·다른 root 진입까지 조사한 ‘전체 게임에서 한 번’의 증명으로 확대하지 않는다. 단순 source 비활성은 +2606에서 +2621로 `01 000E` 점프를 쓰는 길이 보존 형태로 표현할 수 있지만, C1.06/0B 내부를 가리키는 진입 참조가 없다는 확인 전에는 적용하지 않는다.

초반 도착점 후보인 Final 본문5 / 선택102는 **root2=1975, root4=2731, 본문 길이13462**다. root2 시작은 A8.03과 81.16 그래픽 준비다. F의 실제 native A8.03 `06075AB4` / 81.16 `06073CE8`에서 각각 총 길이6/3을 확인했지만, 이것을 Final의 같은 주소나 최초 1회 합류 보증으로 일반화하지 않았다. F 인계 로스터의 복원보다 앞/뒤 중 어느 지점인지가 확정돼야 한다.

현재 특정 cross-scenario template에서 남은 확인은 다음처럼 줄어든다.

1. **도착 위치 하나 고정:** 본문5의 실제 인계 복원 완료 뒤이며 C7에 필요한 game-state 진영 비트가 설정된 command boundary를 찾는다. 단순 root2 시작은 아직 허가하지 않는다.
2. **원래 source 둘을 각각 고정:** 우주 15byte/지상 25byte의 원래 guard·모든 진입·C1 연결 소비를 분리한다. root2와 root0를 같은 callback으로 취급하지 않는다.
3. **기존 인물 처리:** full pilot218와 그 기체/보조 구성의 존재를 native roster에서 판별해야 한다. 현재 C0.11 맵 actor 검색은 미출격 인물과 같은 기종의 다른 pilot을 구별하는 이 조건이 아니다. 기존 full-ID 검색 함수 F `0602A3E0` / Final `0602D98C`는 후보지만 VM에서 안전하게 부를 제품 경로는 아직 없다.
4. **추가 동시 점유:** 서로 다른 시나리오로 옮길 때는 두 시점 사이에 원래 합류/이탈/변형이 있으므로 같은 block 이동에서의 점유 동등성을 사용할 수 없다. pilot/unit 전체 128칸과 변형 파생 레코드까지 도착 시점에 검사해야 한다. C7은 pilot 생성 뒤 unit 빈칸을 검사하므로 사후 실패 처리로 대체하지 않는다.
5. **대화·출격의 후속 대상:** 늦은 source에서 C7을 생략해도 해당 callback의 CA01/CA00·C1.0B·개별 pilot lookup이 이미 만들어진 정확한 레코드를 사용하고, Save/Continue에서 새 생성이 반복되지 않는지 확인한다.

이 다섯 조건 중 특히 1·3·4를 닫으려면 현재 제품의 숫자/문구 editor보다 큰 VM/native 경로가 필요하다. 이번에는 해당 경로를 추측해 활성화하지 않았다. 기존 초기레벨 1..99 기능은 이 이동 권한과 분리돼 그대로 유지된다.
