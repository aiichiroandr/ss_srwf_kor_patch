# 제4차 연결 기체와 ALICE의 게임 도감

로컬 웹에디터에서 검증된 제4차 Rev 1 자료를 연결하고 BIN으로 저장하면,
완결편의 기존 로봇대도감에 S건담·Ex-S건담·서바인·즈와우스·블러드템플과
S건담 G크루저·Ex-S G크루저가 추가된다. 실제로 생성한 레코드만 찾으므로
기체 번호를 430–436으로 고정하지 않는다. ALICE 이름·초상이 등록된 출력은
기존 인물사전에 ALICE(#399)를 추가한다. 새 메뉴나 사용자 설정은 없다.

기존 편집 BIN도 다시 저장하면 적용된다. 파일을 열기만 해서는 원본 파일을
수정하지 않는다. 원래 달성률 0%로 도감 메뉴가 잠겨 있으면 본편의 열람
조건 또는 기존 기타 탭의 「도감·영상 전체 열람」 설정을 따른다. 전체 도감을
자동 해금하거나 세이브 진행률을 덮어쓰지 않는다. F 자체의 도감에는 적용하지 않는다. 공개 v0.3 기반과 비공개
v0.4 검수본은 각각 별도 사전 레시피를 사용하며 승인 패치를 변경하지 않는다. 동일 코드 revision 3의
잘못된 작품명 출력도 정확한 이전 슬롯 해시로 읽고, 새 저장에서 수정한다.

## 문안과 표시

문안 원본은 [SRW4_DICTIONARY_TEXT.json](SRW4_DICTIONARY_TEXT.json)이다.
설명은 이 편집기의 추가 기체 구성에 맞춰 작성한 한국어 문안이다. 원본 F의
미공개 설명문을 복구했다고 주장하지 않는다. 문장 안 단어를 보존하면서 실제
288px 본문 폭에 맞춰 줄을 채운다. 모든 문자는 기존 문자표로 인코딩한다.

- S건담: 빔스마트건·인컴, ALICE의 기체 제어와 학습.
- S건담 G크루저: 순항 형태의 이동·사격과 MS 형태 전환.
- Ex-S건담: 추가 장갑·추진 장치, 4문 빔캐논·I필드·리플렉터인컴.
- Ex-S G크루저: 대형 추진 장치와 사격을 활용하는 순항 형태.
- 서바인: 바란바란의 비보, 시온 자바, 검 중심의 근접전.
- 즈와우스: 라반 자라만드, 검은 장갑·날개·꼬리, 서바인과의 격전.
- 블러드템플: 현재 편집기 무장 구성인 버스터런처·기가블래스터.
  등장작품은 「중전기 엘가임」으로 표시한다. 본편 미등장 설정 기체라는 점과
  첫 SRW 출연작 「제4차 슈퍼로봇대전」을 구분한다.
- ALICE: S건담의 학습형 인공지능, 상황 판단과 기체 제어.
  등장작품은 「건담 센티넬」, 성우는 「없음」으로 표시한다.

기체 설명에 원본 공여체인 건담의 전장 18m·중량 43.4t를 복사하지 않는다.
확인되지 않은 제원은 게임의 기존 미상 표시를 사용한다. 게임의 실제 능력치는
변경하지 않으며 도감 표시용 20B 사본만 사용한다.

설정 확인에 참고한 공식 자료:
[건담 센티넬 소개](https://gget.ggame.jp/jp/titles/detail.php?t=glyw2f6d),
[Ex-S건담 설명서](https://manual.bandai-hobby.net/pdf/636.pdf),
[단바인 OVA 작품 소개](https://www.sunrise-world.net/titles/titles.php?id=179),
[Ex-S 제품 설명](https://www.bandaispirits.co.jp/products/search/detail.php?grp_id=5325&prd_id=4549660062462000).

## 쓰기 범위와 복원

기존 주인공 도감 수정의 revision 3이다. 과거 original/1/2 출력도 계속 읽고
저장 시 3으로 올린다. 정확한 LBA·파일 길이·전체 슬롯 SHA-256과 EXEC 포인터
조합을 함께 검사한다. 알려지지 않은 바이트나 부분 설치는 정규화하지 않는다.
기존 불변 해시의 편집 허용 범위는 넓히지 않는다.

DIC S1/S2는 각각 기존 64KiB 버퍼 안의 65,500B까지 사용한다. TSR은 늘리지
않는다. DIC 압축 길이는 v0.3 80,892B, v0.4 검수본 101,029B다. DIC 뒤의
다음 ISO 파일까지 비어 있는 구간에서 1 CD 섹터(2,048B)를 추가로 사용한다.
LBA·다른 파일·전체 디스크 길이는 유지한다. 원래 슬롯과 그 추가 섹터 전체를
핀으로 고정하며, 되돌릴 때 추가 섹터의 **원래 바이트**도 복원한다.
v0.3의 해당 섹터는 0으로 차 있지 않으므로 0 초기화로 대체할 수 없다.

기체 레코드는 2바이트 단위로 붙어 있어 홀수 번째 레코드는 4로 나눈 나머지가
2인 주소에서 시작한다(예: 431·433·435). SH-2는 이런 주소의 32-bit 읽기에서
주소 오류를 내므로, 도감 표시용 20B 사본은 1바이트씩 복사하고 그래픽 번호도
2바이트를 따로 읽는다. 이전 revision 3 출력(`before-unit-alignment-fix`)은
S건담 G크루저·Ex-S G크루저·즈와우스 상세 화면에서 검은 화면으로 멈췄으며,
다시 저장하면 새 도우미로 바뀐다.

공유 도우미는 0x2029F600–0x2029F9FF, 읽기 전용 문안/연결표는 FA00 이후,
로봇 표시용 임시 레코드는 FEF0이다. 기존 주인공 초상화/이름 복원 도우미는
F500으로 이동하며 이름 임시 포인터 F580/F588과 분리한다. v0.4의 기존 페이지
도우미 F000–F0A2는 보존한다. 실제 저장 등록 비트맵은 수정하지 않는다.

EXEC 파일 `0`의 32-bit BE 포인터만 변경한다:

| 파일 오프셋 | 원래 대상 | 추가 대상 | 조건 |
|---|---|---|---|
| 0x8278C | 0x2029F200 (주인공 도감 수정) | 0x2029F600 | ALICE |
| 0x82B10 | 0x06004CC8 | 0x2029F640 | 제4차 기체 |
| 0xB7FE0 | 0x06085B54 | 0x2029F8C0 | ALICE 목록 |
| 0xB7FE4 | 0x06085C28 | 0x2029F800 | 기체 목록 |
| 0x81F20 | v03 0x06004CC8 / v04 0x2028C0C8 | 0x2029F780 | 하나 이상 |

연결 여부는 사용자 입력 플래그만 믿지 않는다. 같은 export에서 검증된 실제
기체/초상화 쓰기 계획으로 결정하고, 재열기에서도 도감 연결과 등록 데이터가
맞는지 검사한다. 기준 revision 3 없이는 추가 도우미를 설치하지 않는다.
해제·정규화 순서는 추가 도감 → 기존 주인공 도감이다. 증원 수용량·크리티컬·
전체 도감 해금·F 저장 호환 코드는 각자의 정확한 상태를 보존한다.
전투 미리보기는 컴파일된 호스트가 도감을 실행하지 않으므로 복제 입력의
이 포인터만 원복한다. 저장된 BIN의 도감은 유지된다.

작성한 공유 SH2 코드 재생성 (ROM 불필요):

```sh
python3 scripts/build_dictionary_additions.py --out build/dictionary-helper
```

## 검증 범위

비공개 증거 폴더: `build/srw4-dictionary-20261101/`.

- `export-proof.json`: 실제 제품 writer로 예전 F+제4차 편집 BIN 저장·재열기.
- `v04-export-proof.json`: 제4차 Rev 1 ZIP을 검증·연결한 v0.4 새 출력 저장·재열기.
- `v03/04-product-0.bin`은 네이티브 실행용 EXEC와 바이트 일치로 대조한다.
- `v03/04-*-registered.json`: 기존 목록 생성 함수를 통한 신규 항목 자동 등록.
  캡처의 상세 항목 선택에는 진단용 목록 커서를 사용한다.
- 원래 마틸다 및 주인공 제스·헥토르 화면은 앞선 수정본과 픽셀 비교한다.
- 추가 목록 없이 저장한 결과의 전체 원본 해시 왕복, 추가 섹터 복원,
  accepted a/b 사전 슬롯 동일성, 네이티브 실제 표시를 별도로 확인한다.
- 사전 텍스트·그림·제원은 출력 BIN에서 읽는다. 화면에 텍스트를 합성하지 않는다.
  네이티브 도우미/CRC는 비공개 포트에서 재생성하며 배포 JS/WASM은 바꾸지 않는다.

출시 승인·하드웨어·CD-R·장시간 진행 보증은 아니다. 이 작업으로 공개 배포를
실행하거나 승인 패치 아티팩트를 바꾸지 않는다.
