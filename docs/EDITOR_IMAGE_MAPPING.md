# 로컬 에디터 이미지 연결 검증 (2026-10-06)

## 2026-10-09: 얼굴 미지정 전수 조사와 참고 초상화

F v0.5-a 및 완결편 v0.3-c의 승인 이미지 전체 해시를 검사한 뒤 파일럿 391행씩을 모두 미리보기로 읽었다. 직접 참조 345/382개는 전부 비투명 픽셀을 표시한다. 별도로 FACE의 모든 셀(F 338개, 완결편 342개)을 디코딩했으며 모두 비투명 그림을 포함한다. 셀 0은 그림이 있어도 예약 번호이므로 직접 초상화로 취급하지 않는다.

F의 얼굴 0인 이름 있는 템플릿 362–371은 완결편의 동일 레코드와 대조했다. 다음 연결은 F 파일 자체의 FACE 셀을 **참고 초상화**로 보여 준다. 이름 검색으로 그림 번호를 추측하지 않으며, 원본의 얼굴 번호 0을 변경하지 않는다. `previewEditorRecord`/worker의 `imageSource: "reference"`를 화면에서도 표시한다.

F 364 단테는 완결편에서 FACE 339를 참조한다. F의 셀 수는 338이며 완결편 339와 동일한 디코딩 픽셀은 F의 전체 FACE 셀에서 발견되지 않았다. F의 다른 파일이나 실행 중 시나리오 그림까지 없다고 단정하지 않는다. 확인하지 않은 대체 얼굴을 연결하지 않는다.

양 게임 304–307은 주인공 공용 머리 레코드로 고정 얼굴 0, 308–311은 얼굴 필드 자체가 없는 공용 습득표다. 화면도 각각 ‘주인공 공용 데이터 (고정 얼굴 미지정)’, ‘공용 습득표 (고정 얼굴 미지정)’로 구분한다. 나머지 얼굴 미지정 행은 F 372–399 및 완결편 399의 이름 없는 미사용 레코드다. F의 참고 표시 9개를 제외한 미지정 행은 37개(주인공/습득표 8 + 단테 1 + 미사용 28), 완결편은 9개(주인공/습득표 8 + 미사용 1)다.

이는 파일 구조와 그림 리소스의 검증이며 해당 시나리오를 에뮬레이터에서 실행한 증거는 아니다. 추출 그림과 승인 BIN은 저장소에 추가하지 않는다.

양 게임의 읽기 전용 별칭 312–319도 확인했다. 이 8개 이름 칸은 레코드 1을 공유하며 소유자의 직접 FACE 번호는 1이다. 391개 고유 레코드와 별도로 존재하지만 얼굴 미지정 항목은 아니며, 별도의 레코드나 초상화로 오인하지 않는다.

이전의 이름 대조 기반 수동 매핑과 그 매핑에 대한 검증 주장은 폐기한다. 원본 명칭 표의 인덱스와 실제 레코드의 기체 정체성을 혼동하여 여러 기체와 파일럿 얼굴을 잘못 연결했다. 실제 무장과 원판 실행 코드, 원본 TSRViewer의 그림 선택 목록으로 다시 확인했다. 이름 표의 키는 레코드 번호이며 그림 번호와 무관하다.

## 최종 참조 규칙

원판 완결편 실행 코드 0x06047FAC는 TSR root27의 기체 레코드 +2/+3 BE16을 전투 캐시 0x060C6ABC에 저장한다. 0x06019550 이후 C_ROBOT 로더는 캐시 값을 그대로 읽어 0x0600B47C에 전달하며, 로더는 번호×8의 자체 상대 포인터 셀을 읽는다. root1 그림 포인터 표는 C_ROBOT 헤더와 동일하다. 별도의 이름 기반 재번호 매핑은 없다.

파일럿은 레코드 +0/+1의 packed 9-bit 얼굴 번호를 FACE에 사용한다(0은 고정 얼굴 없음). 원본 TSRViewer robotgraphic 369개 / pilotgraphic 342개 선택 목록이 실제 디코딩 그림의 정체성과 일치한다. 이 번호는 **이름 키가 아니다**: 기체 +0/+1의 9-bit 값은 맵 아이콘 번호이고 파일럿의 값은 얼굴 번호다. 기체·파일럿·무기의 이름은 모든 이름표에서 레코드(포인터 셀) 번호로 찾는다. 그림 정체성은 이름을 대신하지 않는다. 그림의 이름 목록은 저장소에 싣지 않으며(이전에는 그림 이름과 레코드 이름을 비교하는 보조 표시용 목록이 있었으나 화면이 쓰지 않아 지웠다), 행의 `imageIndex`와 `imageStatus`는 레코드의 직접 참조만 나타낸다. 2026-10-09부터 확인된 F 참고 초상화는 별도의 `referenceImageIndex`로 표시하며 직접 참조와 섞지 않는다. 수치, 이름 ID, 그림 ID 등 원본 디스크 바이트는 표시를 위해 변경하지 않는다.

기체 레코드 67은 그림 61, 69는 그림 63, 71은 그림 65를 가리키며 각각 무기 번호 293~298, 302~305, 311~315를 가진다(두 승인 이미지 모두 같은 값이다). 이전 방식(그림 정체성으로 이름을 덮어쓰는 방식)은 폐기했다.

모든 nonzero 참조는 각각 C_ROBOT 356/369, FACE 338/342개 범위 안에 있고 실제 비투명 RGBA가 디코딩됐다. 그림 참조 0인 기체는 F 45개(미사용 템플릿 20 + 이름이 있는 템플릿 수치 25), 완결편 21개(미사용 18 + 이름이 있는 템플릿 3)다. 기체 315–317은 이름은 있으나 그림 참조 0이며 다른 기체의 도감 그림으로 대신하지 않는다(이전 매핑은 기체 +0/+1 값을 이름 번호로 오해한 것이었다). 얼굴 참조가 없는 파일럿은 고정 얼굴이 없는 영웅 머리 레코드 304–307(실제 수치가 있다), 머리부가 없는 영웅 목록 템플릿 308–311, 이름이 있는 템플릿 수치 레코드(F 362–371), 미사용 레코드(F 372–399, 완결편 399)다. 참조 0만으로 게임 실행 중 그림이 절대로 없다고 주장하지 않는다. C_ROBOT에는 동일 RGBA 공유 그룹 0/1/295/296/340, 47/48, 71/72가 있고 완결편은 255/256도 같다. FACE 0/1과 완결편176/341도 동일하다. 공유 픽셀을 다른 기체로 임의 재연결하지 않는다.

이미지는 사용자가 선택한 디스크의 C_ROBOT.BIN/FACE.BIN에서 로컬로 읽는다. 공개 저장소에는 추출 게임 이미지가 없으며 개인 디스크·세이브를 업로드하지 않는다. 기체·파일럿별 요청 ID로 초기 동시 요청 및 빠른 선택에서 최신 응답을 보존한다. 그림 미지정과 읽기 오류는 로딩 중으로 남기지 않는다.

위 표의 숫자는 승인 이미지를 에디터 해석기로 열어 센 값이며, 전체 레코드 SHA/pixel 검사 기록은 게임 이미지에서 파생된 자료이므로 저장소에 포함하지 않는다. 이 검증은 에디터 표시·저장 검증이며 전체 자연 플레이 검증이 아니다.
