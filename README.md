# 세가 새턴 슈퍼로봇대전 F 한글 패치

세가 새턴판 **슈퍼로봇대전 F**와 **슈퍼로봇대전 F 완결편**의 한글 패치를
브라우저에서 적용하기 위한 정적 웹 패처입니다. 번역과 도구는
**Codex × Claude 협업**으로 제작하고 있습니다.

패처는 사용자가 직접 준비한 정품 디스크 이미지를 브라우저 안에서만 읽습니다.
원본을 서버에 올리지 않고, 원본과 다른 새 파일로 패치 결과를 만듭니다.

[GitHub Pages에서 패처 열기](https://aiichiroandr.github.io/ss_srwf_kor_patch/)

## 현재 공개 상태

| 게임 | 상태 | 현재 공개 버전 |
|---|---|---|
| 슈퍼로봇대전 F | 패치 가능 | **2026.08.14 · v0.1** |
| 슈퍼로봇대전 F 완결편 | 작업 중 | 공개 승인된 패치 없음 |

`v0.1`은 현재 유일한 기본 공개판입니다. 일본어판 Rev. B 정품 원본 전체와 현재
승인된 v0.1 결과 전체를 직접 비교해, 서로 다른 모든 바이트를 희소 패치로 만들었습니다.
이전 공개판에 마지막 수정분만 덧붙인 증분 패치가 아닙니다. 따라서 현재 결과의
`KORPROL.BIN`, `TSR.BIN` 변경을 포함한 누적 반영 범위가 모두 패치 대상입니다.

정확한 v0.1 결과는 상태 파일을 불러오지 않은 짧은 콜드부트와 선별한 기능·화면 경로에서
확인했습니다. 이는 전체 게임 완주나 장시간 실플레이 검증, 모든 화면의 완전한 번역을
뜻하지 않습니다. 대사 품질, 고유명사, 일부 UI 문구와 줄 배치는 계속 검수하고 솎아낼
예정입니다.

F 완결편은 구성요소 번역과 내부 검수가 진행 중이지만, 아직 공개용 전체 디스크 결과,
목표 SHA-256, 희소 패치와 공개 승인 영수증이 한 세트로 확정되지 않았습니다. 따라서
페이지에서는 게임을 고를 수 있지만 패치 실행은 `준비 중`으로 안전하게 잠깁니다.

## 버전별 패치 범위

웹 패처에서 버전을 고른 뒤 `패치노트 열기`를 누르면 대표 변경의 AS-IS/TO-BE를
바로 비교할 수 있습니다. `공개 릴리스 반영` 표시는 실제 공개 빌드에 들어간 변경이고,
`공개 릴리스 반영 · 기능 화면 참고` 표시는 같은 데이터·동작을 사용한 내부 기능
검증 화면으로 실제 반영 범위를 설명하는 비교입니다.

현재 승인된 결과의 누적 범위를 정품 원본 기준으로 다시 묶은 첫 공개 버전입니다.

- 시나리오 대사와 작전 목표, 전투 메시지의 한글 데이터

- 옵션, 개조, 파일럿, 음향 설정, 정신기 이름·커서·열 배치와 지형 보정 화살표 등 주요 시스템 UI
- 저장·상세 화면 이름, 출격 유닛 수 위치, 질문·선택·파츠 창의 문구와 레이아웃

- 겟타 3 관련 무기·시나리오·전투 대사의 `대설산 떨구기` 용어 통일

대표 화면 아홉 건은 웹 패처의 패치노트에서 비교할 수 있습니다. 이후 발견한 표기·배치
개선점은 [GitHub Issues](https://github.com/aiichiroandr/ss_srwf_kor_patch/issues)에서
추적합니다.

재현 위치와 완료 판정을 함께 적어 이슈로 관리합니다. 패치노트에는 해당 UI를 설명하는
저해상도 비교 화면만 둘 수 있으며, 세이브, 상태 파일, 원본 또는 완성 디스크 이미지는
이슈나 저장소에 첨부하지 않습니다.

## 슈퍼로봇대전 F 지원 원본

현재 패치 가능한 원본 프로필은 세가 새턴 일본어판 F Rev. B의 전체 디스크
바이트 스트림입니다. 다음 두 입력 형태를 지원합니다.

- 전체 디스크가 이어진 단일 raw `.img` 또는 `.bin` 파일
- 한 폴더에 있는 원본 `.cue`와 `.bin` Track 1·2·3 파일 네 개

- 크기: `578,512,032` bytes
- SHA-256: `c198a93007d46161abe769b6f579f01cae89e23737c0a2ff38ec314d43b3adf8`
- 정규화 형식: 2352-byte raw sector, `245,966` sectors

사용자는 파일을 하나씩 고르지 않고 원본 파일이 바로 들어 있는 **폴더를 한 번만 선택**합니다.
패처가 그 폴더에서 지원하는 단일 raw 파일 또는 CUE와 BIN 세 개를 자동으로 찾고, CUE의
트랙 순서대로 BIN을 가상 결합하므로 중간 합본 파일을 만들 필요가 없습니다. 단일 raw
파일명은 달라도 되지만,
멀티트랙 원본은 압축에서 풀린 원래 파일명을 유지하고 CUE 안의 `FILE` 항목과 실제
BIN 이름이 일치해야 합니다. 정규화한 전체 크기와 SHA-256이 위 값과 정확히 일치하지
않으면 패처가 중단됩니다.

일반적인 2048-byte ISO와 CHD는 현재 웹 패처의 입력으로 지원하지 않습니다. 확장자만
바꾼 파일이나 손실 오디오가 포함된 이미지를 억지로 변환하지 않으며, 승인된 원본과
동일한 raw 바이트를 검증할 수 있는 경우에만 패치합니다.

## 패치 방식

이 프로젝트는 xdelta가 아니라 자체 공개 포맷인 `.srwfp` 희소 바이트 패치를 씁니다.
패치 파일에는 바뀌는 바이트와 원본 구간 검증값만 들어 있으며 게임 전체 데이터는
들어 있지 않습니다.

브라우저는 다음 순서로 동작합니다.

1. 게임과 공개 버전을 선택합니다.
2. 정품 원본 IMG/BIN 또는 CUE와 BIN 세 개가 바로 들어 있는 폴더를 선택합니다. 모바일은
   읽기 권한만, 같은 폴더에 직접 결과를 만드는 데스크톱은 읽기·쓰기 권한을 사용합니다.
3. `패치 실행`을 누릅니다. 원본 폴더는 다시 선택하지 않습니다.
4. 패처가 원본을 한 번 읽으면서 전체 SHA-256과 각 변경 구간을 검증합니다. 데스크톱은
   처음 선택한 폴더에 겹치지 않는 새 이름의 BIN을 만들고, 모바일은 다운로드용 BIN을
   구성합니다.
5. 새 BIN의 전체 SHA-256까지 일치해야 완료합니다. 데스크톱은 이를 여는 CUE를 같은
   폴더에 자동으로 만들고, 모바일은 검증된 BIN/CUE 다운로드 링크 두 개를 표시합니다.

일부 Android 브라우저·파일 앱은 폴더를 읽을 수 있어도 그 안에 새 파일을 만드는
기능을 제공하지 않습니다. 이 경우 원본 선택과 검증 준비는 그대로 유지한 채 브라우저
다운로드 방식으로 자동 전환합니다. 별도 폴더 선택 창을 다시 열지 않고 전체 SHA-256과
변경 구간 검증을 통과한 뒤 `패치 BIN 다운로드`와 `CUE 다운로드` 링크를 표시합니다.
두 링크를 각각 눌러 파일 이름을 바꾸지 말고 같은 폴더에 두면 됩니다. BIN은 원본의
변경되지 않은 Blob 구간을 재사용해 구성하므로 전체 579 MB를 JavaScript 바이트 배열로
한꺼번에 복사하지 않습니다.

패처는 정품 원본 파일을 쓰기 대상으로 열지 않습니다. 출력에는 예측하기 어려운 고유
식별자가 붙은 새 이름을 사용해 기존 이름을 재사용하지 않습니다. 패치가 끝나면 재배치된
파일까지 하나의 연속 데이터 트랙으로 읽는 F용 CUE도 같은 폴더에 자동으로 만듭니다. 원본
Redump의 3트랙 경계를 그대로 쓰는 CUE가 아니며, CUE 저장만 실패한 경우에는 완성된 BIN을
유지하고 CUE 재시도 버튼을 표시합니다.

Android에서는 Chrome 132 이상, 데스크톱에서는 최신 Chrome 또는 Edge의 네이티브
폴더 API를 사용합니다. 데스크톱 Chrome·Edge는 같은 폴더 자동 생성을 우선 사용합니다.
Android Chrome과 삼성 인터넷은 0바이트 자리표시자나 원본 폴더 쓰기 실패를 남기지 않도록
처음부터 폴더를 읽기 전용으로 열고 검증된 BIN/CUE 다운로드 경로를 사용합니다.
iPhone·iPad Safari는 약 579 MB 결과를 사용자가 고른 Files 경로에 스트리밍 저장하는
동등한 API가 없어 현재 패치를 실행할 수 없습니다. 지원되지 않는 기기에서도 원본 선택
버튼을 누르면 필요한 환경을 화면에 안내합니다. 모바일에서 작업할 때는 패치가 끝날 때까지
화면을 켜 두고 다른 앱으로 전환하지 마세요.

## 로컬에서 확인하기

```bash
npm test
python3 -m http.server 8000
```

그다음 `http://localhost:8000/`을 엽니다. `슈퍼로봇대전 F`를 선택하면 v0.1 한 개가
보이고, `F 완결편`을 선택하면 준비 중 안내와 잠긴 파일 선택 버튼이 보이면
정상입니다.

커밋 전 검증 훅은 다음처럼 이 저장소에만 연결할 수 있습니다.

```bash
git config core.hooksPath .githooks
```

## 공개 및 권리 고지

저장소에는 승인된 희소 패치와 정적 웹 파일, 패치 내역을 설명하는 저해상도 UI 비교
화면만 둡니다. 원본·완성 이미지, CUE, 추출 게임 파일, 세이브, 세이브 상태와
에뮬레이터 캐시는 배포하지 않습니다.

이 프로젝트는 비공식 팬 프로젝트이며 원 저작권자·플랫폼 사업자와 제휴하거나
승인을 받은 프로젝트가 아닙니다. 자세한 내용은 [NOTICE.md](NOTICE.md)를 확인하세요.
