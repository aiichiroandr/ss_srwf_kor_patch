# 세가 새턴 슈퍼로봇대전 F 한글 패치

세가 새턴판 **슈퍼로봇대전 F**와 **슈퍼로봇대전 F 완결편**의 한글 패치를
브라우저에서 적용하기 위한 정적 웹 패처입니다. 사용자가 준비한 정품 원본을
브라우저에서 직접 검증하고, 승인된 희소 패치를 적용해 새 BIN/CUE를 만듭니다.

패처는 사용자가 직접 준비한 정품 디스크 이미지를 브라우저 안에서만 읽습니다.
원본을 서버에 올리지 않고, 원본과 다른 새 파일로 패치 결과를 만듭니다.

[GitHub Pages에서 패처 열기](https://aiichiroandr.github.io/ss_srwf_kor_patch/)

## 현재 공개 상태

| 게임 | 상태 | 현재 공개 버전 |
|---|---|---|
| 슈퍼로봇대전 F | 패치 가능 | **2026.08.23 · v0.3** |
| 슈퍼로봇대전 F 완결편 | **패처에서 숨김** (검수 부족) | 2026.08.14 · v0.1 시험판 |

F의 `v0.3`은 현재 기본 공개판입니다. 일본어판 Rev. B 정품 원본 전체와 승인된
v0.3 결과 전체를 직접 비교해, 서로 다른 모든 바이트를 희소 패치로 만들었습니다.
이전 공개판에 마지막 수정분만 덧붙인 증분 패치가 아니라, 현재 공개 결과까지의
누적 변경을 원본 전체와 비교한 패치입니다. 따라서 내부 파일 이름이나 작업 단계가
달라도 원본과 결과의 전체 해시가 맞으면 같은 방식으로 적용됩니다.

`v0.2`(2026.08.21)는 패치 형식의 정규형을 어겨 공개 목록에서 내렸습니다. 그 판을
받으셨다면 `v0.3`으로 다시 패치해 주세요.

**F 완결편은 현재 패처에서 고를 수 없습니다.** F에 비해 검수가 한참 덜 된 상태라
지금 설치를 권할 수 없어, 게임 선택 목록에서 잠시 내렸습니다. 릴리스 자체를 철회한
것은 아니며 매니페스트와 패치 파일은 그대로 남아 있습니다 — 검수가 진척되면 다시
엽니다. 아래 「F 완결편」 항목에 어디까지 확인했는지 적었습니다.

`v0.1.1`은 `v0.1`에서 한국어 프롤로그가 출력되지 않던 문제를 수정한 핫픽스입니다.
그 과정에서 프롤로그 제목 화면의 그래픽 경계 두 곳까지 잘못 바뀌어 화면이 깨지는
문제가 생겼고, `v0.1.2`는 그 두 경계만 원래 위치로 복구한 후속 핫픽스입니다.
철회된 `v0.1` manifest·receipt·payload는 공개 목록에서 제외하고 바이트 불변의 실패
이력으로만 보존합니다.

정확한 v0.1.2 결과는 상태 파일을 불러오지 않은 프롤로그 경로와 선별한 기능·화면
경로에서 확인했습니다. 이는 전체 게임 완주나 모든 화면의 완전한 번역을 뜻하지 않습니다.
대사 품질, 고유명사, 일부 UI 문구와 줄 배치는 계속 검수하고 솎아낼 예정입니다.

F 완결편 `v0.1 시험판`은 일본어판 Rev. A 정품 원본 전체를 기준으로 시나리오 대사,
전투 대사, 화자명과 가라오케 자막 일부를 한글화한 고정 공개판입니다. 콜드부트에서
타이틀·가라오케·시나리오 전투 데모까지의 제한된 경로와 한글 표시를 확인했지만,
장시간 실플레이와 전 경로 완주는 검증하지 않았습니다. 완전 검수판이 아니라 공개
시험판입니다.

F 완결편은 F에 비해 검수가 한참 덜 된 상태이므로 **패처의 게임 선택 목록에서 잠시
내렸습니다.** 지금은 F만 패치할 수 있습니다. 완결편 릴리스와 패치 파일은 철회하지
않고 그대로 두었으므로, 검수가 진척되면 다시 열 수 있습니다.

웹 패처에서 버전을 고른 뒤 `패치노트 열기`를 누르면 F 핫픽스 요약을 확인할 수
있습니다. F의 기존 AS-IS/TO-BE 비교 자료는 삭제하지 않고 데이터와 저해상도 자산으로
보존하되, 공개 버전별 변경과 다시 맞춰 정리할 때까지 화면에서는 숨깁니다. F 완결편
v0.1 시험판은 해당 공개판에서 확인한 세 비교 항목을 좌우로 넘겨 볼 수 있습니다.

영상은 공개 패치 형식의 record 상한을 넘겨 담을 수 없었고, 다음 판에서 형식을 넓혀 다시

시나리오 대사, 전투 대사, 화자명과 가라오케 자막 일부를 정품 Rev. A 전체 디스크에

## 아직 남은 작업

- 일부 기체명, 인명, 고유명사와 목록 표기의 일본어·미정리 문자열
- 파일럿 풀네임과 공유 문자열의 잔여 표기 전수 검수
- 질문·선택·파츠 창의 폭과 줄바꿈
- 여러 경로의 대사 자연스러움과 용어 통일 재검수
- 정확한 공개 결과를 이용한 더 넓은 실플레이·장시간 회귀 확인
- F 완결편의 더 넓은 실플레이·시나리오·줄바꿈 검수

게임 화면에서 발견한 문제는 가능하면 `현재 화면(AS-IS)`, `원하는 화면(TO-BE)`,
재현 위치와 완료 판정을 함께 적어 이슈로 관리합니다. 패치노트에는 해당 UI를 설명하는
저해상도 비교 화면만 둘 수 있으며, 세이브, 상태 파일, 원본 또는 완성 디스크 이미지는
이슈나 저장소에 첨부하지 않습니다.

## 지원 원본

각 게임은 아래에 고정한 세가 새턴 일본어판 전체 디스크 바이트 스트림만 지원합니다.
두 프로필 모두 다음 입력 형태를 지원합니다.

- 전체 디스크가 이어진 단일 raw `.img` 또는 `.bin` 파일
- 한 폴더에 있는 원본 `.cue`와 `.bin` Track 1·2·3 파일 네 개

| 게임·원본 | 크기 | SHA-256 | 정규화 형식 |
|---|---:|---|---|
| F 일본판 Rev. B | `578,512,032` | `c198a93007d46161abe769b6f579f01cae89e23737c0a2ff38ec314d43b3adf8` | `245,966 × 2352` raw sector |
| F 완결편 일본판 Rev. A (`11M` 기준) | `520,408,224` | `ff7192abc112d5c969a0e236f5061fc6853234eedc350525c46c0548c57dfbdb` | `221,262 × 2352` raw sector |

사용자는 파일을 하나씩 고르지 않고 원본 파일이 바로 들어 있는 **폴더를 한 번만 선택**합니다.
패처가 그 폴더에서 지원하는 단일 raw 파일 또는 CUE와 BIN 세 개를 자동으로 찾고, CUE의
트랙 순서대로 BIN을 가상 결합하므로 중간 합본 파일을 만들 필요가 없습니다. 단일 raw
파일명은 달라도 되지만, 멀티트랙 원본은 지원하는 한 세트의 CUE 이름과 CUE 안의
`FILE` 항목, 실제 BIN 이름이 모두 일치해야 합니다. 선택한 게임에 맞춰 정규화한 전체
크기와 SHA-256이 위 값과 정확히 일치하지 않으면 패처가 중단됩니다.

F 완결편은 Redump Rev. A `11M`을 위 canonical 원본으로 고정합니다. Rev. A `10M`
CUE+Track 1·2·3 BIN도 지원하며, 화면에 보인 하이픈 없는
`Super Robot Taisen F Kanketsuhen … (10M)` 454-byte CUE 이름까지 포함합니다.
`10M` 합본의 정규화 전 SHA-256은
`b94fec3e4ddcbac5849a94b3bae17c4d38efe74c583714417deefffa7b57c976`,
Track 3 SHA-256은
`66f03f518c58106976cab1f83c19190103f10f66ccc40ce049c7e08cce58691b`입니다.
`10M`의 Track 1·2는 같고 Track 3만 정확히 20개의 `00` 바이트만큼 밀린 가역 표현이므로,
브라우저가 `20 × 00 + Track3[0:-20]`으로 길이를 바꾸지 않고 정규화합니다. 잘려 나가는
마지막 20바이트가 모두 `00`인지 먼저 확인하고, 정규화한 전체 이미지가 반드시 위
`ff7192…` SHA-256과 일치해야만 패치를 진행합니다. 이 처리는 별도 공개 버전이나 오디오
교체가 아니며, 현재는 `10M` 단일 합본 파일이 아니라 CUE+BIN 3개 입력에만 적용됩니다.

일반적인 2048-byte ISO와 CHD는 현재 웹 패처의 입력으로 지원하지 않습니다. 확장자만
바꾼 파일이나 손실 오디오가 포함된 이미지를 억지로 변환하지 않으며, 승인된 원본과
동일한 raw 바이트를 검증할 수 있는 경우에만 패치합니다.

## 패치 방식

이 프로젝트는 xdelta가 아니라 자체 공개 포맷인 `.srwfp` 희소 바이트 패치를 씁니다.
패치 파일에는 바뀌는 바이트와 원본 구간 검증값만 들어 있으며 게임 전체 데이터는
들어 있지 않습니다.

브라우저는 다음 순서로 동작합니다.

1. 게임과 공개 버전을 선택합니다.
2. 정품 원본 IMG/BIN 또는 CUE와 BIN 세 개가 바로 들어 있는 폴더를 선택합니다. 모바일은
   읽기 권한만, 같은 폴더에 직접 결과를 만드는 데스크톱은 읽기·쓰기 권한을 사용합니다.
3. `패치 실행`을 누릅니다. 원본 폴더는 다시 선택하지 않습니다.
4. 패처가 원본을 한 번 읽으면서 전체 SHA-256과 각 변경 구간을 검증합니다. 데스크톱은
   처음 선택한 폴더에 릴리스에 표시된 고정 이름의 BIN을 만들고, 모바일은 같은 고정
   이름의 다운로드용 BIN을 구성합니다.
5. 새 BIN의 전체 SHA-256까지 일치해야 완료합니다. 데스크톱은 이를 여는 CUE를 같은
   폴더에 자동으로 만들고, 모바일은 검증된 BIN/CUE 다운로드 링크를 표시합니다.

일부 Android 브라우저·파일 앱은 폴더를 읽을 수 있어도 그 안에 새 파일을 만드는
기능을 제공하지 않습니다. 이 경우 원본 선택과 검증 준비는 그대로 유지한 채 브라우저
다운로드 방식으로 자동 전환합니다. 별도 폴더 선택 창을 다시 열지 않고 전체 SHA-256과
변경 구간 검증을 통과한 뒤 `패치 BIN 다운로드`와 `CUE 다운로드` 링크를 표시합니다.
두 파일을 같은 폴더에 두고, 같은 이름의 이전 다운로드가 있으면 먼저 삭제해 브라우저가
이름 뒤에 `(1)`을 붙이지 않도록 해야 합니다. BIN은 원본의
변경되지 않은 Blob 구간을 재사용해 구성하므로 전체 500~580 MB를 JavaScript 바이트 배열로
한꺼번에 복사하지 않습니다.

패처는 정품 원본 파일을 쓰기 대상으로 열지 않습니다. 출력은 릴리스의 버전명으로 끝나는
고정 BIN/CUE 이름을 사용합니다. 데스크톱에서 같은 이름의 파일이 이미 있으면 덮어쓰지
않고 중단하므로 기존 결과를 먼저 옮기거나 삭제해야 합니다. 패치가 끝나면 BIN과 함께
그 결과에 맞는 CUE도 같은 폴더에 자동으로 만듭니다. CUE는 결과 BIN의 실제 트랙
구성(데이터·동영상·오디오 구간)을 단일 BIN 안의 절대 INDEX로 적은 한 가지뿐이며,
에뮬레이터용과 CD-R 굽기용을 따로 나누지 않습니다. F v0.3은 옮겨 넣은 한글 데이터까지
MODE1·MODE2·MODE1·AUDIO 4트랙으로 적고, 이 CUE로 CD-R을 구워 실기에서 구동했다는
사용자 보고가 있습니다. F 완결편 결과는 승인 빌드가 보존한 MODE1·MODE2·AUDIO 3트랙
경계를 적습니다. 이전 버전인 v0.1.2와 v0.1.1은 승인 당시의 단일 데이터 트랙 CUE를
그대로 만듭니다. 트랙 경계는 빌드가 데이터를 어디까지 옮겨 넣었느냐에 따라 달라지므로,
새 릴리스는 결과 이미지에서 확인한 트랙 구성을 패처에 등록해야 CUE를 만들 수 있습니다.
CUE 저장만 실패한 경우에는 완성된 BIN을 유지하고 CUE 재시도 버튼을 표시합니다.

Android에서는 Chrome 132 이상, 데스크톱에서는 최신 Chrome 또는 Edge의 네이티브
폴더 API를 사용합니다. 데스크톱 Chrome·Edge는 같은 폴더 자동 생성을 우선 사용합니다.
Android Chrome과 삼성 인터넷은 0바이트 자리표시자나 원본 폴더 쓰기 실패를 남기지 않도록
처음부터 폴더를 읽기 전용으로 열고 검증된 BIN/CUE 다운로드 경로를 사용합니다.
iPhone·iPad Safari는 약 500~580 MB 결과를 사용자가 고른 Files 경로에 스트리밍 저장하는
동등한 API가 없어 현재 패치를 실행할 수 없습니다. 지원되지 않는 기기에서도 원본 선택
버튼을 누르면 필요한 환경을 화면에 안내합니다. 모바일에서 작업할 때는 패치가 끝날 때까지
화면을 켜 두고 다른 앱으로 전환하지 마세요.

## 폰트 리비전 선택

F v0.4 / F 완결편 v0.1의 폰트 선택 매핑은 다음과 같습니다.

| 패치 리비전 | 게임 폰트 |
| --- | --- |
| a | DOS thin 커스텀 (기존 폰트) |
| b | 갈무리11 |
| c | Mona12 |

게임 → 패치 버전 → 게임 폰트 순서로 선택합니다. 폰트를 바꾸면 해당 리비전의
해시가 고정된 매니페스트를 다시 검증하고, 이전 원본 선택과 출력 준비 상태를
초기화합니다. 패치 실행 중에는 폰트를 바꿀 수 없습니다. 버전을 바꿨을 때 고른
폰트가 그 버전에 없으면 게임 기본 릴리스의 폰트, 그다음 a·b·c 순으로 대신 불러오고
화면 읽기 프로그램에 알립니다.

현재 선택기의 연결 규칙은 `srwf-f-YYYYMMDD-v0-4-a` 또는
`srwf-final-YYYYMMDD-v0-1-a`처럼 버전 뒤에 `-a`, `-b`, `-c`를 붙인 릴리스 ID입니다.
같은 게임·날짜·버전만 하나의 버전 선택지로 묶습니다. 이는 신규 배포본을 위한
연결 규칙이며 기존 승인 파일의 ID를 바꾸는 지침이 아닙니다. 실제 승인 파일의
명명 규칙이 다르면 파일을 변경하지 않고 선택기의 연결 규칙을 조정해야 합니다.

각 리비전은 독립적인 ACCEPTED 승인 영수증·릴리스 매니페스트·희소 패치와
일치하는 원본/결과/패치 해시가 필요합니다. 폰트별 릴리스가 하나도 없는 게임에서는
폰트 선택 칸을 표시하지 않습니다. 폰트별 릴리스가 있는 게임에서 접미사 없는 기존
버전을 고르면 폰트 선택 미지원으로 표시하며, 등록되지 않은 리비전은 선택할 수
없습니다. 원본 디스크의 Rev. A/B와 패치 폰트의 a/b/c는 서로 다른 구분입니다.

같은 버전의 a/b/c 행은 인덱스 `label`이 같아야 합니다. 버전 목록에는 이 label이
그대로 보이고 폰트는 별도 칸에 표시되므로, 주의 문구는 세 행에 똑같이 적습니다.
같은 날짜·버전의 접미사 없는 ID와 `-a`/`-b`/`-c`를 함께 올리거나, 같은 폰트를 두 번
올리거나, 묶음 안 label이 다른 인덱스는 저장소 검증과 패처 부팅에서 모두 차단됩니다.

선택 UI와 연결 로직은 준비되어 있으나, F v0.4 및 완결편 v0.1의 a/b/c 배포 세트는
아직 이 저장소에 연결되지 않았습니다. 승인 자료를 확인하기 전에는 릴리스 인덱스에
추가하지 않습니다.

```bash
npm test
python3 -m http.server 8000
```

그다음 `http://localhost:8000/`을 엽니다. `슈퍼로봇대전 F`를 선택하면 v0.3이
기본으로 보이고 v0.1.2와 v0.1.1도 이전 버전으로 선택할 수 있어야 합니다. F 완결편
공개 시험판은 명세에 보존되어 있지만 현재 선택 화면에서는 숨겨져 있습니다.

커밋 전 검증 훅은 다음처럼 이 저장소에만 연결할 수 있습니다.

```bash
git config core.hooksPath .githooks
```

## 공개 및 권리 고지

저장소에는 승인된 희소 패치와 정적 웹 파일, 패치 내역을 설명하는 저해상도 UI 비교
화면만 둡니다. 원본·완성 이미지, CUE, 추출 게임 파일, 세이브, 세이브 상태와
에뮬레이터 캐시는 배포하지 않습니다.

각 공개 릴리스의 원본·결과·패치 SHA-256과 지원 형식은 매니페스트에 고정되어
있습니다. 사용자가 확인해야 할 기준은 내부 작업명이나 개발 단계가 아니라, 이 공개
해시와 패처의 원본 검증 결과입니다.

이 프로젝트는 비공식 팬 프로젝트이며 원 저작권자·플랫폼 사업자와 제휴하거나
승인을 받은 프로젝트가 아닙니다. 자세한 내용은 [NOTICE.md](NOTICE.md)를 확인하세요.
